EBS CURI — Windows 설치 없이 실행하기

1. 대상과 포함 파일
- Windows 10/11 64비트 x64 (Intel/AMD) PC용입니다. ARM PC용 실행 환경은 아닙니다.
- Node.js 24.18.0 실행 파일, Windows용 패키지, 검색 모델, 실행 DB, Chrome 확장을 포함합니다.
- Node.js 설치, npm ci, Hugging Face 모델 다운로드, API 키 입력이 필요하지 않습니다.
- 실행 환경과 모델은 용량 때문에 분할 압축되어 있지만 자동 복원되므로 직접 풀지 않습니다.
- Chrome은 별도 설치되어 있어야 합니다: https://www.google.com/chrome/
- 검색 모델은 로컬에서 실행합니다. EBS 영상 시청·로그인과 외부 썸네일에는 인터넷이 필요합니다.

2. 다운로드와 압축 해제
① GitHub에서 Code → Download ZIP을 누르거나 제공받은 제출 ZIP을 저장합니다.
② ZIP을 마우스 오른쪽 클릭 → 모두 압축 풀기를 선택해 완전히 풉니다.
③ CURI_START.cmd, package.json, server, public이 보이는 폴더를 엽니다.
   확장자가 숨겨져 있으면 start-windows라는 Windows 명령 스크립트로 표시될 수 있습니다.
④ ZIP 미리보기 안에서 실행하거나 public 안의 HTML을 직접 열지 마세요.
⑤ 충분한 공간(압축 파일 외에 여유 3GB 이상)을 확보하세요. 경로가 너무 길면 C:\Curi 같은 짧은 폴더로 옮기세요.

3. 실행 — 다음부터도 같은 방법
① CURI_START.cmd를 두 번 클릭합니다. 터미널에서 경로를 입력할 필요가 없습니다.
② EBS CURI - Windows x64 launcher 안내와 [1/5]~[5/5] 단계가 표시됩니다.
   첫 실행은 포함된 실행 환경·데이터·모델을 복원하므로 몇 분 걸릴 수 있습니다.
   오류가 나거나 서버가 종료되어도 창이 남으므로 오류 문구를 확인하세요.
③ 실행 창에 안내가 나오면 Chrome에서 아래 주소를 엽니다.

http://localhost:3000

④ 서버 실행 창은 열어 둡니다. 첫 검색은 색인 준비로 수십 초 걸릴 수 있습니다.
⑤ 종료할 때 실행 창에서 Ctrl+C를 누르거나 창을 닫습니다.
⑥ 다시 쓸 때도 CURI_START.cmd만 두 번 클릭합니다. 기존 DB는 초기 데이터로 덮어쓰지 않습니다.

4. 실행 라이브러리가 없다고 나올 때
- 일부 새 Windows PC에는 Microsoft Visual C++ 실행 라이브러리가 없을 수 있습니다.
- 최초 복원이 끝난 뒤 runtime → windows-x64 → vc_redist.x64.exe를 실행해 설치합니다.
- 이 공식 Microsoft 보조 설치 파일도 동봉되어 별도 다운로드는 필요 없습니다.
- 관리자 승인이 필요할 수 있으며, 설치 후 CURI_START.cmd를 다시 실행합니다.
- 설치된 적 없는 Windows에서 모든 시스템 라이브러리까지 무조건 설치 없이 된다는 뜻은 아닙니다.
- 기관 보안 정책이 스크립트 실행을 막으면 담당자에게 실행 허용을 요청하세요.

5. Chrome 확장 설치 — 영상 구간 기능 이용 시
① Chrome 주소창에 chrome://extensions 를 입력합니다.
② 개발자 모드를 켭니다.
③ 압축해제된 확장 프로그램을 로드합니다를 누릅니다.
④ extensions → curi-segments 폴더를 선택합니다. manifest.json이 바로 있는 폴더입니다.
⑤ 확장 아이콘을 도구 모음에 고정합니다.
⑥ http://localhost:3000/lesson.html 탭을 열어 둡니다.
⑦ 확장의 EBS CURI 연결 주소를 http://localhost:3000 으로 맞춥니다.
⑧ EBS 원본 영상을 열고 필요한 경우 로그인하여 본편을 직접 재생합니다.
영상 이용 권한과 플레이어에 따라 구간 제어가 제한될 수 있습니다.
확장을 바꾼 뒤에는 확장 카드와 Curi/EBS 탭을 새로고침하세요.

6. 저장과 실행 범위
- 개인 폴더·메모·구간은 브라우저 프로필과 접속 주소별로 저장됩니다.
- 같은 Chrome 프로필과 http://localhost:3000 주소를 사용하세요.
- 폴더·메모는 다른 PC에 자동 동기화되지 않습니다.
- 유료 LLM 검색은 비활성입니다. 모델을 동봉한 로컬 의미 검색이며 유료 모델을 쓰는 개발 환경과 결과가 다를 수 있습니다.
- 검색 모델 파일은 server/data/submission-model, Windows 실행 환경은 runtime-seed/windows-x64에 들어 있습니다.
- 실행하면 실제 파일이 server/data/.model-cache, runtime/windows-x64, node_modules에 복원됩니다.

7. 문제가 생기면
- al 등이 명령이 아니라고 나오면 예전 실행 파일을 닫고 CURI_START.cmd를 실행하세요.
  수정 ZIP의 내용을 기존 프로젝트 폴더(package.json이 있는 곳)에 덮어써야 합니다.
- 파일 손상/조각 누락: ZIP을 다시 다운로드하여 새 폴더에 완전히 풉니다.
- 3000번 포트 사용 중: 이전 Curi 실행 창을 종료한 다음 다시 실행합니다.
- 접속 불가: 서버 실행 창의 오류와 http://localhost:3000 주소를 확인합니다.
- 복원 실패: 폴더 쓰기 권한·남은 저장 공간을 확인하고, 필요하면 짧은 로컬 경로로 옮깁니다.
- Windows가 앱이나 스크립트를 차단하면 보안 정책 담당자의 허용이 필요할 수 있습니다.
- 실제 Windows 더블클릭·권한·Chrome 확장·EBS 재생은 Windows에서 최종 확인해야 합니다.

8. macOS 또는 Windows ARM에서 소스로 실행하는 경우
동봉된 휴대용 실행 환경은 Windows x64 전용입니다. 다른 환경에서는 Node.js와 해당 OS 패키지를 설치해야 합니다.
Node.js 공식 다운로드: https://nodejs.org/en/download
Node.js 24.18.0 이상을 설치하세요. Windows 설치 시 npm과 Add to PATH를 기본 선택하고 터미널을 새로 여세요.
Windows에서는 이 폴더에서 탐색기 Alt+D → cmd → Enter로 명령 프롬프트를 엽니다.
아래 명령을 한 줄씩 실행합니다. 최초 npm ci에는 npm 배포 서버 연결이 필요합니다.

node --version
npm.cmd ci
npm.cmd start

macOS에서는 이 폴더에서 터미널을 열고 npm ci, npm start를 실행합니다.
동봉된 모델은 npm start 시 자동 복원되므로 Hugging Face 다운로드는 필요 없습니다.
Windows x64 자동 실행으로 복원된 node_modules는 다른 OS/CPU에서 재사용하지 마세요.

검증 범위
모델 및 패키지 파일 검증과 macOS에서의 네트워크 차단 추론 검사는 별도 기록합니다.
Windows 실제 실행·기관 보안 정책·실제 EBS 로그인/시점 이동/끝 정지 확인은 별도입니다.
GitHub 업로드만으로 외부에서 접속 가능한 배포 URL이 생기지는 않습니다.
