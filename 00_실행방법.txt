EBS CURI — Windows 설치·실행 방법

이 문서는 Windows 사용자를 위한 안내입니다.
아래 순서대로 진행하면 폴더 경로를 직접 입력하거나 붙여넣지 않고 실행할 수 있습니다.
기본 로컬 검색에는 API 키가 필요하지 않습니다.

────────────────────────────────
시작 전: 인터넷과 의미 검색 모델 확인
────────────────────────────────

현재 ZIP에는 방송/교육과정 DB는 들어 있지만, Hugging Face 검색 모델 파일은 포함하지 않습니다.
의미 검색을 처음 사용할 때 Xenova/multilingual-e5-small 모델을 내려받아야 합니다.
이미 준비된 DB가 있다는 사실과 모델 파일까지 준비됐다는 사실은 다릅니다.

모델 출처:
https://huggingface.co/Xenova/multilingual-e5-small

필요한 연결:
- GitHub: 프로젝트 ZIP 다운로드
- npm 패키지 저장소: npm.cmd ci 설치
- huggingface.co와 모델 파일을 제공하는 연결 대상/CDN: 최초 의미 검색 모델 다운로드
- EBS 원문/영상 서비스: 방송 페이지와 영상 이용

사내망에서 Hugging Face나 모델 파일 서버가 막혀 있고 로컬 모델도 없다면 의미 검색은 실행되지 않습니다.
일반 교사 검색은 이때 단어/원문 근거 검색을 계속할 수 있지만 결과·순위는 의미 검색과 달라질 수 있습니다.
관리자의 임베딩 검색 준비와 검증 자산 벡터 검색도 모델 실행이 필요한 경로입니다.
서버 화면이 열렸다는 사실만으로 의미 검색까지 준비된 것은 아닙니다.

모델 파일 4개가 완전히 준비된 후에는 해당 임베딩 추론을 로컬에서 수행합니다.
학교/회사에서 다운로드가 제한되면 담당자와 승인된 접속 또는 모델 파일 사전 제공 방법을 확인하세요.
보안 설정이나 인증서 검사를 임의로 해제하지 않습니다.
Hugging Face 첫 화면만 열려도 실제 대용량 모델 파일의 연결 대상이 차단될 수 있습니다.
프록시/방화벽의 연결 대상은 다음 공식 안내를 참고합니다:
https://huggingface.co/docs/hub/en/models-downloading#downloading-behind-a-proxy-or-firewall

앞선 설치 검사는 화면/저장 동선의 확인이며 모델 다운로드 완료·의미 검색 성공을 보증하는 결과가 아닙니다.
네트워크 차단 검사에서는 지구의 자전/기후 변화의 단어 기반 결과가 표시되고 의미 검색 상태는 LOCAL_FAILED였습니다.
실제 다운로드 실패 문구와 사용 중인 사내망 여부를 함께 전달하면 원인을 구분할 수 있습니다.

────────────────────────────────
1. Node.js 설치 — 처음 한 번
────────────────────────────────

공식 다운로드 페이지:
https://nodejs.org/en/download

Windows용 Node.js 24.x LTS를 선택하세요. 최소 버전은 24.18.0입니다.
npm은 Node.js 설치 파일에 함께 포함됩니다.

테스트한 버전(24.18.0)의 Windows x64 설치 파일:
https://nodejs.org/dist/v24.18.0/node-v24.18.0-x64.msi

ARM 기반 Windows PC라면 다음 ARM64 설치 파일을 사용합니다:
https://nodejs.org/dist/v24.18.0/node-v24.18.0-arm64.msi

PC 종류는 Windows 설정 → 시스템 → 정보 → 시스템 종류에서 확인할 수 있습니다.
Intel/AMD의 일반 64비트 Windows PC는 x64를 선택합니다.

설치 순서:
① 위 링크를 Chrome으로 열어 .msi 설치 파일을 받습니다.
② 다운로드한 설치 파일을 실행합니다.
③ Next → 사용권 동의 → Next로 진행합니다.
④ npm package manager와 Add to PATH 항목의 기본 선택을 유지합니다.
⑤ Install을 누르고 설치가 끝나면 Finish를 누릅니다.
⑥ 열려 있던 명령 프롬프트·PowerShell·터미널 창을 모두 닫습니다.
   새로 연 창에서 설치된 Node.js를 인식합니다.

※ 이미 Node.js 24.18.0 이상이 설치되어 있으면 2번부터 진행해도 됩니다.

────────────────────────────────
2. Curi ZIP 다운로드와 압축 해제
────────────────────────────────

저장소:
https://github.com/katiesong2023/EBSCuriFinalTest

직접 ZIP 다운로드:
https://github.com/katiesong2023/EBSCuriFinalTest/archive/refs/heads/main.zip

① GitHub 저장소에서 초록색 Code → Download ZIP을 누릅니다.
② 키보드의 Windows 키 + E를 눌러 파일 탐색기를 엽니다.
③ 왼쪽의 다운로드 폴더를 엽니다.
④ EBSCuriFinalTest-main.zip을 오른쪽 클릭 → 모두 압축 풀기 → 압축 풀기를 누릅니다.
⑤ 압축을 푼 폴더를 엽니다. 안에 같은 이름의 폴더가 있으면 한 번 더 엽니다.

이 안내 파일, package.json, public·server·extensions 폴더가 함께 보이면 올바른 위치입니다.
파일 확장명이 숨겨져 있으면 package.json은 package로 보일 수 있습니다.
ZIP 미리보기 안에서는 실행하지 말고 반드시 압축을 먼저 풀어 주세요.
DB가 들어 있는 .gz 파일은 프로그램이 자동으로 해제합니다.

────────────────────────────────
3. 해당 폴더에서 명령 프롬프트 열기
────────────────────────────────

탐색기에서 위 프로젝트 폴더를 열어둔 상태로 진행합니다.

① Alt + D를 누릅니다.
   탐색기 위쪽에서 현재 폴더 위치가 표시되는 긴 주소 표시줄이 선택됩니다.
② cmd를 입력합니다.
③ Enter를 누릅니다.

검은색 명령 프롬프트 창이 열립니다.
지금 열린 창은 이미 Curi 폴더에 있으므로 cd나 폴더 경로를 입력할 필요가 없습니다.
아래 명령은 이 검은 창에 한 줄씩 입력하고 Enter를 누릅니다.

────────────────────────────────
4. 올바른 폴더와 Node.js 설치 확인
────────────────────────────────

먼저 입력:

dir package.json

package.json 파일이 표시되면 올바른 폴더입니다.
'파일을 찾을 수 없습니다'가 나오면 창을 닫고 2번의 폴더 위치부터 확인합니다.

이어서 한 줄씩 입력:

node --version
npm.cmd --version

v24.18.0처럼 Node.js 버전과 npm 버전 숫자가 나오면 다음 단계로 갑니다.
Node.js는 24.18.0 이상이어야 합니다.

'내부 또는 외부 명령, 실행할 수 있는 프로그램, 또는 배치 파일이 아닙니다'라고 나오면:
- Node.js 설치를 완료했는지 확인합니다.
- 모든 터미널 창을 닫고 3번 방법으로 새 명령 프롬프트를 엽니다.
- 여전히 같은 오류가 나면 Windows를 다시 시작한 뒤 재확인합니다.
- 계속 안 되면 입력한 명령과 오류 문장 전체를 전달해 주세요.

────────────────────────────────
5. 필요한 패키지 설치 — 처음 한 번
────────────────────────────────

아래 한 줄을 입력합니다:

npm.cmd ci

설치가 끝나고 다시 명령을 입력할 수 있을 때까지 기다립니다.
인터넷 연결이 필요합니다.
오류가 나면 다음 단계로 넘기지 말고 오류 문장을 확인합니다.

────────────────────────────────
6. Curi 실행과 화면 열기
────────────────────────────────

설치가 끝나면 입력합니다:

npm.cmd start

처음 실행할 때 포함된 DB 4개를 검사하고 자동 복원한 뒤 서버가 시작됩니다.
DB 압축 파일을 따로 풀거나 옮기지 않아도 됩니다.
이미 복원된 DB는 다시 실행할 때 덮어쓰지 않습니다.

서버 실행 메시지가 나오면 Chrome 주소창에서 아래 주소를 엽니다:

http://localhost:3000

검은 명령 프롬프트 창은 열어 둡니다.
첫 검색은 자료 색인 준비에 수십 초 걸릴 수 있습니다. 최초 대기는 최대 2분입니다.
개인 폴더·메모·구간을 유지하려면 같은 Chrome 프로필과 같은 접속 주소를 사용하세요.

────────────────────────────────
7. Chrome 확장 설치 — 영상 구간 기능을 사용할 때
────────────────────────────────

① Chrome 주소창에서 chrome://extensions 를 엽니다.
② 개발자 모드를 켭니다.
③ 압축해제된 확장 프로그램을 로드합니다를 누릅니다.
④ Curi 프로젝트 폴더 안의 extensions → curi-segments 폴더를 선택합니다.
   manifest.json이 바로 들어 있는 폴더를 선택해야 합니다.
⑤ Chrome의 확장 메뉴에서 EBS CURI 아이콘을 도구 모음에 고정합니다.
⑥ http://localhost:3000/lesson.html 탭을 열어둡니다.
⑦ 확장 아이콘을 누르고 EBS CURI 연결 주소를 http://localhost:3000 으로 맞춥니다.
⑧ EBS 원본 영상을 열고, 필요한 경우 로그인한 뒤 본편을 직접 재생합니다.

영상의 이용 권한·플레이어에 따라 시간 읽기나 구간 재생이 제한될 수 있습니다.
확장을 갱신하면 확장 카드와 Curi/EBS 탭을 새로고침하세요.

────────────────────────────────
8. 종료와 다음 실행
────────────────────────────────

종료: 서버를 실행한 명령 프롬프트에서 Ctrl + C를 누릅니다.
배치 작업 종료 여부를 물으면 Y를 입력하고 Enter를 누릅니다.

다음 실행:
① 탐색기에서 같은 Curi 프로젝트 폴더를 엽니다.
② Alt + D → cmd → Enter로 명령 프롬프트를 엽니다.
③ npm.cmd start를 실행합니다.
④ Chrome에서 http://localhost:3000 을 엽니다.

npm.cmd ci는 최초 설치 또는 의존성 변경 후에 실행하면 됩니다.

────────────────────────────────
9. 다른 오류가 나면
────────────────────────────────

- EADDRINUSE / 3000번 포트 사용 중:
  이미 실행 중인 Curi 서버의 명령 프롬프트에서 Ctrl + C로 종료한 뒤 다시 실행합니다.
- Chrome에서 연결할 수 없음:
  npm.cmd start가 실행 중인지와 http://localhost:3000 주소를 확인합니다.
- npm.ps1 실행 정책 오류:
  3번의 cmd 방법으로 열고 이 문서의 npm.cmd 명령을 사용합니다.
- 데이터 파일 손상 안내:
  GitHub ZIP을 다시 받아 새 폴더에 풉니다. 기존 개인 DB를 임의로 삭제하지 않습니다.
- 확장 연결 실패:
  서버와 내 수업 탭이 열려 있는지 확인하고 확장/Curi/EBS를 새로고침합니다.

오류를 전달할 때는 입력한 명령과 화면에 표시된 오류 문장 전체를 보내 주세요.
GitHub 공개만으로 웹 서비스가 실행되는 구조는 아니며, 위 절차로 내 PC에서 실행합니다.

macOS 사용자는 docs/INSTALL_AND_TEST_GUIDE.md의 터미널 실행 절차를 참고하세요.
