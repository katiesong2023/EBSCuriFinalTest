# Task R08-03 - 관리자 예외 작업공간과 가져오기 무효화

## 설명

관리자를 전량 승인 처리자가 아니라 자동 연계의 오류·변경·근거 부족을 관리하는 역할로 바꾼다. 기존 목록·상세·세션 인증을 바탕으로 예외 우선 작업 목록과 자동 검사 상세를 제공하고, 화면 왕복 없이 자료의 처리 상태와 다음 조치를 알 수 있게 한다. 2026-10-05 구현·에이전트 실행 검증을 마쳤으며 사용자 완료 처리·R08-04 후속 진행 요청을 반영해 **완료**다. 기존 R08의 완료 기록과 인증 경계는 유지한다.

## 구현 항목

### 작업 목록과 지표

- [x] 출처/인용 오류·관계 상충·원문/기준/규칙 변경·저장/검색 준비 실패를 우선 확인할 수 있게 정렬·필터한다. 원문 보강 필요·지원 규칙 밖·미처리 신규 자료는 별도로 구분한다.
- [x] 기본 목록에서 처리 이유·영향받은 관계·최근 검사와 변경 시점·다음 가능한 조치를 제시한다. 정상 자료의 등록 어휘 미발견을 실제 오류와 같은 우선순위로 취급하지 않는다.
- [x] 현재 `태그 근거 부족`의 뜻이 등록 어휘 미발견임을 바로잡고, 원문 부족·인용 실패·의미 미확인을 별도 지표로 보여준다. 태그 0건 자체는 잘못된 자료 판정이 아니다.
- [x] 현재 `검수 대기` 수치를 전체 작업량으로 사용하지 않는다. 초안 없는 신규 자료, 후보 생성 완료, 자동 검사 통과/실패/보류, 변경 후 재검사, 선택적 사람 검토를 실제 저장 상태로 집계한다.
- [x] 집계의 자료 수·관계 수·실행 수, 분모·중복 여부를 명시한다. 한 자료에 여러 실패 이유가 있어도 전체 자료 수를 중복 합산하지 않는다.
- [x] 검색어·필터·정렬·페이지·선택 자료를 상세 확인과 후속 처리 후에도 유지한다. 처리 후 목록에서 빠지는 자료와 마지막 자료의 다음 이동도 일관되게 처리한다.

### 상세와 자동 처리

- [x] 한 자료의 현재 원문·출처·판본과 성취기준별 후보를 같은 작업공간에서 비교한다. 각 관계에 인용 위치·기준 요구·연결 부분·미확인 부분·자동 검사 결과·실패 이유·버전 변경을 먼저 보여준다.
- [x] 후보 생성·검사·재검사·자산 저장·검색 준비의 진행과 실패를 구분하고 해당 단계만 재시도할 수 있게 한다. 자료를 가져오기·CuriMap·검수 화면으로 순서대로 이동해야만 자동 처리할 수 있는 제약을 없앤다.
- [x] 후보가 없거나 원문이 부족한 자료는 보류 이유와 보강 필요를 남긴다. 사람의 승인 입력을 자동 처리의 필수 완료 단계로 요구하지 않는다.
- [x] 여러 자료의 출처 점검·자동 검사·재검사를 명시적으로 실행할 수 있게 한다. 실행 대상과 건별 성공·보류·실패, 중단 후 재개 범위를 알 수 있어야 하며 일괄 실행이 사람 검토 기록을 만들지 않아야 한다.
- [x] 기존 원문·처리 이력을 확인하고 필요한 보강을 할 수 있게 한다. 공개 원문 인용과 관리자의 메모·수정 내용을 구분하며 근거 변경은 R08-02의 무효화 경계를 따른다.
- [x] 선택적 사람 판단을 시작할 때 현재 관계·근거·목록 조건이 이어지도록 한다. 실제 관계별 결정·저장 통합은 R08-04에서 구현한다.

### 가져오기와 운영 회귀

- [x] 단일 입력·CSV 파일/텍스트·스냅샷의 미리보기 뒤 입력이 달라지면 이전 미리보기와 저장 가능 상태를 무효화한다. 미리보기 요청 중 입력 변경, 이전 응답의 늦은 도착, 연속 저장도 이전 입력 사본을 저장하는 결과를 만들지 않아야 한다.
- [x] 현재 입력과 유효한 미리보기의 일치를 확인한 결과만 저장하고, 실패·변경 시 현재 입력을 보존해 다시 확인할 수 있게 한다. 코드 검토로 발견된 문제는 구현 시 실행 재현 결과와 구분해 기록한다.
- [x] 로딩·빈 목록·상세 조회 실패·재시도·세션 만료·직접 접근·작은 화면을 처리하며 관리 API 인증과 Origin/Host 검증을 유지한다. 교사 화면과 기존 수업 폴더의 저장 내용은 보존한다.

## 구현 결과

### 작업공간과 처리 경로

- `/admin.html`에서 오류·변경·실패를 우선 정렬한다. 출처·인용·상충·변경·실행/저장 실패·검색 준비·원문 보강·규칙 미지원·미처리·후보·자동 통과·보류·선택적 사람 검토를 각각 조회한다. 등록 어휘 0개 자체는 오류로 올리지 않는다.
- 자료 수는 검색어 범위의 고유 원본 ID 수이며 필터는 중복될 수 있다. 최신 후보는 교과/학년별 최신 실행의 관계 수, 실행 이력은 보존된 전체 실행 수다. 최근 100개 이력 API의 제한을 집계에 적용하지 않는다. 초안 없는 미처리·후보 0개 보류·원본 없는 실패도 포함한다.
- 자료 상세는 현재 원문과 성취기준별 인용·UTF-16 위치·기준 요구·연결/미확인 부분·실패 조건·원문/기준 지문을 나란히 보여준다. 변경된 근거의 당시 검사 결과와 현재 제공 중단을 구분한다. 원문 이력·태그·기존 사람 검토·자동 실행 이력은 펼쳐 확인한다.
- `후보·근거만 미리보기`는 저장하지 않는다. `자동 검사·저장`/`자동 재검사·저장`은 기존 R08-01·02 API를 호출한다. 원본 방송 ID는 가져오기·CuriMap·사람 승인을 거치지 않고 처리한다. 생성/검사 실패와 자산 저장 실패를 구분하고 같은 입력의 저장 실패는 보존한 검사 보고서로 저장을 재시도한다. `이 실행의 검색 준비만 재시도`는 검색 단계만 수행한다.
- `저장 출처 점검`과 `POST /api/admin/source-check`는 저장된 ID·버전·URL·활성/알려진 불일치를 검사한다. 외부 도착 페이지를 새로 수집·대조하거나 사람 확인 기록을 만들지는 않는다.
- 목록에서 최대 30자료와 교과/작업을 선택해 `선택 자료 작업 준비` → `표시한 대상 실행`을 누른다. 건별 성공·보류·차단·실패, `현재 건 이후 중단`, `미완료·실패 건 재개`를 제공한다. 브라우저 재개 목록은 `curi.admin.jobs.v1`에 보존한다. 응답 미확인은 서버의 동일 입력 중복 방지로 재확인한다. 완료된 자료는 재개 대상에서 제외한다.
- 검색어·필터·정렬·페이지·선택 자료·이전 위치를 URL로 유지한다. 처리 후 필터에서 빠져도 상세 근거와 다음 자료를 유지하며 마지막 자료는 끝으로 표시한다. 기존 가져오기/CuriMap/검수 동선의 `returnTo`와 `automaticRunId`·`automaticRelationId`가 관계 문맥을 전달한다. 실제 관계별 사람 결정은 R08-04에서 구현한다.
- 가져오기는 모든 단일 필드·CSV 파일/텍스트·전체 스냅샷·입력 방법 변경 시 미리보기를 무효화한다. 읽기/요청 중 변경과 늦은 응답을 버리고 저장 직전 현재 입력을 비교한다. 저장 중 입력을 잠그고 중복 클릭을 막으며 실패 시 입력값을 보존한다.

### 파일·저장 경계

- 화면: `public/admin.js`(목록), `admin-detail.js`(근거 상세), `admin-jobs.js`(작업 실행/재개), `admin-ui.js`(표시/복귀 문맥), `admin-session.js`, `admin.html`, `admin.css`, `ingestion.js/html`.
- 서버: `admin-workspace.js`(통합 조회), `admin-automatic-state.js`(전체 실행/현재 변경), `admin-work-items.js`(우선순위/집계), `admin-source-check.js`(출처 조건), `automatic-assets.js`(실패 단계/저장 재시도), `server.js`(보호된 라우트).
- 자동 SQLite 스키마는 v1 그대로이며 기존 승인 JSON·방송 DB·시맨틱 DB의 이전/덮어쓰기는 없다. 자동 실행이 사람 검토·승인 기록을 생성하지 않는다. 가져오기 소개문은 공개 출처의 원문이며 관리자 의견/검토 메모를 인용으로 사용하지 않는다.

### 실행 확인

- [상태·집계·저장 재시도 검사](../docs/r08-03-admin-check.json) **13개**: 우선순위와 중복 분모, 초안 없는 자료, 최신 100개 초과 이력, 보류 자료 변경, 원본 없는 실패, 검색 실패, 필터 이탈/마지막 이동, 저장 실패의 재생성 없는 복구.
- [HTTP·브라우저 검사](../docs/r08-03-http-browser-check.json) **15개**: 임시 복제 서버와 합성 방송 DB에서 인증/Origin/Host, 원본 ID 직접 처리, 미리보기 무저장, 일괄 중단/새로고침 재개, 검색만 재시도, 사람 검토 문맥, 변경 원문 비교, 실패/빈 목록/세션, 가져오기 경쟁 상태를 확인했다.
- 가져오기 문제는 `git show HEAD:public/ingestion.js`의 수정 전 스크립트를 임시 브라우저에만 주입해 **미리보기 → 제목 수정 → 저장 시 과거 제목 전송**을 재현했다. 수정 후 모든 필드·CSV/파일/스냅샷 변경, 요청 중 수정·응답 역전, 느린 파일 읽기, 이벤트 없는 값 수정, 연속 저장·저장 실패를 검사했다. 가져오기 요청은 검사에서 가로채므로 실제 자료에 테스트 입력을 저장하지 않았다.
- [기존 관리자 회귀](../docs/r08-03-legacy-admin-check.json) 권한/상태 12개·CuriMap/검수/복귀 브라우저 6개, 기존 CuriMap 실패/중복/응답 역전, 사람 검수 결정/수정/제외/저장 실패 회귀를 통과했다. 자동 자산 저장 계약 26개도 통과했다. 기존 승인 4개·검토 이력·실제 JSON/방송/시맨틱/자동 SQLite 해시와 교사 폴더 저장값을 보존했다. 유료 API 호출은 0회다.
- [목록](../docs/r08-03-admin-desktop.png)·[근거 상세](../docs/r08-03-admin-detail.png)·[390px 화면](../docs/r08-03-admin-mobile.png)을 확인했다. 통과 관계는 합성 개발 사례이며 실제 방송의 교육과정 의미 정확도 평가가 아니다. 실제 원본 2건은 기존 보류 결과를 유지하고 공개 자동 자산은 0개다.
- 재실행: `node server/admin-exceptions-check.js`. 브라우저 검사는 설치된 Playwright 모듈 경로를 `CURI_PLAYWRIGHT_MODULE`, 필요 시 Chromium 경로를 `CURI_BROWSER_EXECUTABLE`로 지정하고 `node server/admin-exceptions-browser-check.js`를 실행한다. 외부 서비스 키는 사용하지 않는다.
