# Task R12-39 - 요청 역할과 내용 검색의 공통 구조

## 설명

개별 테스트 문장 추가 대신 일반 검색과 구조화 해석에서 대상·목적이 내용 필수 조건으로 재유입되는 구조를 수정한다. 기존 요청 계약·원문 근거 검사·200/170 입력을 재사용한다. 상태: 진행중.

## 구현 항목

- [x] 주제와 대상·목적의 역할 및 원문 위치를 공통으로 보존한다.
- [x] 로컬/구조화 검색에서 문맥을 내용 필수어로 다시 검사하지 않는다.
- [x] 명사 훼손을 막고 미지 내용어와 명시 제외 조건을 보존한다.
- [x] 기존 200/170 및 전체 어휘 기반 불변 조건으로 확인하고 검색 유무와 정확도를 구분한다.

## 범위 밖

- 유료 API 실행, 원천/승인/개인 저장자료 변경, 개별 질의별 결과 하드코딩

## 사전 전제

기존 요청 v1 계약·검증기·검색 실행기 및 고정 370문장.

## 수동 작업

없음.

- [x] 전체 기존 입력 실행과 남는 실패 보고

## 구현 내용

- `server/request-context-roles.js`: 일반 검색/검증된 계약의 공통 투영 경계, 원문 위치 보존, 문맥과 실행 조건 구분.
- `server/request-nouns.js`: 기존 등록 어휘/내용 어휘/단원 어휘와 원천 어절을 사용한 명사 정규화.
- `discovery-intent.js`, `discovery-search.js`: 공통 투영 적용·내용 절의 역할 재해석 방지·캐시 모드 구분.
- `request-search-plan.js`: 계약에 따라 문맥·문법·선호·날짜 등을 분리하고 기존 조건 실행식에 연결. 각 내용 절의 원문 검사 후 계약 논리식으로 결정하며 원문 전체의 어휘 AND를 다시 적용하지 않음.
- `request-contract-validation.js`: 주제의 문맥 은폐·근거 없는 선호 강등 거절.
- `teacher-discovery.js`: 내용 없는 대상/목적 요청에 `TOPIC_REQUIRED` 안내.
- `request-structure-check.js`, `request-structure-evaluate.js`: 기존 입력 기반 불변 조건/실자료 실행. 새 성공 사례 세트는 추가하지 않음.
- `search-term-matching.js`: 공유 경계 검사·제한 캐시로 대량 질의의 정규식 중복 생성 축소.
- `request-connection-check.js`: 과거 카탈로그 SHA 대조를 현재 실행 전후 원천 보존 대조로 정정.

## 에이전트 확인 기록

기존 370문장 문맥 변형 740회·등록 명사 1,211개·기존 해석 계약 10개·로컬/구조화 경로 검사 통과. 기존 검색 연결 39개·모델 계약 23개·공통 품질 25개·관련 품질 10개 통과. 이 수치는 기능 계약이며 정확도 평가가 아니다. 최종 실자료370 실행은 새200 결과19/빈181, 기존170 결과15/빈155, 오류0이다. 빈 결과336개를 품질 통과로 보지 않는다. 실제 HTTP 재현 검색0→29, 내용 없는 요청 TOPIC_REQUIRED, 최종 서버 반영을 확인했다. [구조 설명](../docs/R12_REQUEST_STRUCTURE.md).

반복 실행에서 메모리 종료가 발생한 중간 실행은 성공으로 집계하지 않는다. 원천 어절 복제 제거/512 판정 캐시·공유 경계 검사/2,048 패턴 상한을 적용하고 30,275회 경계 동등성 확인 후 전체370 재실행을 완료했다. 실행 중 코드/보호한5저장소 변경0이며 최종 소스 지문도 일치한다. 기본 Node 설정으로 완주했고 heap 관측 최대1,158MiB다. 배포 RSS 측정이나 영상 적합성 검증은 아니다.
