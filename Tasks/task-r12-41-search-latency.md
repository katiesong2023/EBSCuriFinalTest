# Task R12-41 — 검색 지연·반복 연산 개선

## 설명

사용자의 검색 지연·무거움 제보에 따라 현재 검색 품질 판정과 승인 예산을 유지하며 초기 계산과 반복 요청의 불필요한 처리를 줄인다. 상태: 진행중.

## 구현 항목

- [x] API 호출 없이 저장 응답으로 현재 경로의 초기·반복 지연을 측정한다.
- [x] 검색에 필요하지 않은 전체 표시 키워드와 근거 감사의 선계산을 줄인다.
- [x] 동일 판본·질문의 완료 검색과 진행 중 요청을 재사용하고 원천·정책 변경 시 무효화한다.
- [x] 실패 재시도·결과 보존·캐시 경계를 국소 검사한다.

## 범위 밖

- 모델 비활성화·후보 검사 생략·검색 품질 기준 변경
- 추가 유료 실험·370개 전체 평가·개인/승인 DB 변경

## 사전 전제

- R12-40의 현재 교사 모델 검색·원문 후보·응답 캐시

## 실제 확인

- 생물 관계 기존 질문1개를 실제 저장 응답으로 재생: 최초63,314ms/반복324ms·결과8건 동일·응답5개 모두 캐시 적중. 신규 API·예산 원장 변경 없음. 시간은 해당 프로세스의 소표본이며 일반 성능 보증이 아니다.
- 현재 모델 경로는 해석·복구·강한 해석·조건검사·최대3후보 재검사를 순차 수행할 수 있다. 클라이언트 후속 제한12초와 개별 모델 제한30초의 불일치가 있다.
- `semantic-layer.js`는 근거 감사·표시 키워드를 실제 접근 시 계산한다. 키워드 지연 계산만 적용한 중간 소표본은 초기40,369ms/반복393ms·생물관계8건이었다. 최종 근거 감사 지연 계산 후의 전체 지연은 아직 미측정이다.
- `teacher-search-result-cache.js`와 `teacher-model-search.js`는 동일 카탈로그/질문/로컬후보/정책/임베딩색인 판본의 결과·진행 요청을 최대16건·5분 재사용한다. 실패는 보존하지 않고 전달 응답 실험은 캐시를 우회한다. 후속 요청의 paidCalls는0으로 기록한다.
- 국소8확인(동시 재사용/변형 격리/기간·원천·정책 변경/실패 재시도/감사·키워드 동일)과 기존 교사 연결5검사, 변경JS3개 구문 통과. 신규 유료 API0·370미실행. 사용자의1분내처리 요청으로 추가 전체 성능 측정은 보류했다. 모델 신규 호출의 대기와 화면 제한 불일치는 남는다.
