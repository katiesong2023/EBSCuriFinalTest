> 현재 정본: [PLANS](../docs/PLANS.md) · 대응: **R00~R03 기반 / 완료 이력·기반 보존**. 기존 승인·증분·화면·출처 자산을 재사용하며 새 탐색의 완료로 확대 해석하지 않는다. 과거 구현·사람 확인 기록은 보존한다.

## 설명

대회 Track 1 기준의 현업 사용자·반복업무와 개인 개발 범위를 정하고, 설치·배포 선택을 구현 전에 확정한다.

## 작업 크기와 추천 모델

- 배치: 준비
- 예상 집중 작업: 약 1시간. 개인 입문자 계획용 추정이며 설치·보류·재작업 시간은 별도이다.
- 개발 보조 모델: **GPT-5.6 Terra** (`gpt-5.6-terra`)
- 추천 추론 수준: **medium**
- 선택 이유: 환경 선택과 요구사항 판단을 함께 해야 하지만 대규모 설계까지는 필요하지 않다.

### 비용 최소 운영 원칙

비개발자 관점에서 CuriMap은 콘텐츠를 읽고 공식 교육과정 목록에서 맞는 항목을 골라 주는 보조자다. 이 판단을 새로 만들 때만 외부 AI에게 요청하므로 비용이 생긴다. 반면 이미 사람이 검수해 저장한 결과를 교사가 검색하는 일은 도서관에서 색인표를 찾는 것에 가깝게 만들어, AI에 다시 묻지 않는다.

| 단계 | 비용을 쓰는 이유 | 최소 비용 방식 |
| --- | --- | --- |
| 화면·공식 후보·저장·무료 배포 준비 | AI 판단이 필요하지 않다. | OpenAI API를 호출하지 않는다. Vercel Hobby와 Supabase Free의 한도 안에서 준비한다. |
| 새 콘텐츠 1건의 CuriMap 초안 | 공개 소개문과 좁혀진 공식 후보를 읽고 연계 근거를 작성해야 한다. | 제목·소개문·선별된 공식 후보만 보내고, 1건으로 먼저 확인한다. 결과가 부적합하면 무제한 재시도하지 않고 사람 검토로 보류한다. |
| 승인 결과의 검색 반영 | 새로 승인·수정된 자료를 의미 검색에서 찾을 수 있게 해야 한다. | 바뀐 자료만 임베딩한다. 이미 색인한 자료는 다시 처리하지 않는다. |
| 교사 검색·기존 결과 조회 | 검증된 CuriBase에서 결과를 찾으면 된다. | OpenAI API를 호출하지 않는다. 검색마다 CuriMap을 다시 실행하지 않는다. |
| 모델·비용 비교 | 실제 서비스에 쓸 가장 저렴한 적격 선택을 확인해야 한다. | `03-01`에서 DEV 5~10건만 비교한다. Gold·최종 평가 결과로 비용 절감을 위한 튜닝을 하지 않는다. |

유료 API 호출 또는 유료 플랜 전환이 필요한 task가 오면, 작업 전에 다음 네 가지를 쉬운 말로 설명하고 사용자 확인을 받는다: 무엇을 만들기 위한 호출인지, 왜 무료 기능만으로는 부족한지, 몇 건만 호출하는지, 호출을 줄이거나 멈추는 방법은 무엇인지. API 키·결제 수단·실제 금액은 코드·문서·로그에 기록하지 않는다.

## 수동 작업

1. GitHub에서 개인 비공개 저장소를 만들고, 이 저장소의 원격으로 연결한다. 원격 URL이나 로그인 정보는 이 문서·대화에 기록하지 않는다.
2. Vercel 계정을 사용할 수 있는지와 Hobby 약관의 개인·비상업 사용 조건이 대회 제출에 맞는지 확인한다. 맞지 않거나 유료 플랜이 필요하면 진행 전 월 예산을 정한다.
3. Supabase 계정을 사용할 수 있는지 확인한다. 유료 플랜·도메인·유료 API 사용이 필요한 경우, 각 항목의 월 상한과 총 상한을 먼저 결정한다.
4. 실제 사용 가능 시간이 주 20~25시간과 다르면 수정된 주당 시간을 기록하고, API·호스팅·DB의 유료 예산을 허용하는 경우에만 금액을 알려준다.
