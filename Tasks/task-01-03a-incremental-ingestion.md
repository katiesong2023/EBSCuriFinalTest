# Task 01-03A - 신규·변경 콘텐츠 증분 가져오기

> 현재 정본: [PLANS](../docs/PLANS.md) · 대응: **R00~R03 기반 / 완료 이력·기반 보존**. 기존 승인·증분·화면·출처 자산을 재사용하며 새 탐색의 완료로 확대 해석하지 않는다. 과거 구현·사람 확인 기록은 보존한다.

## 설명

매일 추가되거나 수정되는 EBS 콘텐츠와 새 프로그램을 전체 재적재 없이 등록한다. P0에서는 담당자가 CSV 또는 단건 입력으로 쉽게 갱신할 수 있게 하고, 이후 공식 API·Feed·내보내기 파일이 제공되면 같은 증분 처리 경로를 일일 스케줄러가 호출할 수 있게 한다.

## 작업 크기와 추천 모델

- 구분: P0 필수
- 배치: Week 1
- 예상 집중 작업: 약 2.5시간. 개인 입문자 계획용 추정이며 외부 데이터 소스 연결·보류·재작업 시간은 별도이다.
- 개발 보조 모델: **GPT-5.6 Sol** (`gpt-5.6-sol`)
- 추천 추론 수준: **medium**
- 선택 이유: 원본 ID·중복·변경 이력·재검수 상태를 잘못 처리하면 검증 자산과 검색 결과가 낡거나 중복될 수 있어 저장 경계를 함께 검토해야 한다.
- 상향 조건: 처음부터 xhigh·max로 시작하지 않는다. 원인을 좁혀도 해결되지 않는 동시 저장·부분 실패·외부 소스 정합성 문제만 high로 검토한다.
- 사람 판단/수행 포함: 자동화는 콘텐츠 발견·변경 판별·초안 대기열 생성을 보조한다. 사람 승인 없이 검증 자산으로 저장하지 않는다.
- 모델 배치는 과업 성격에 따른 추천이며 이 서비스에서 측정한 모델 성능 결과가 아니다. [공식 모델 역할·추론 수준 안내](https://learn.chatgpt.com/docs/models)
- 개발 모델과 서비스 API 모델·비용의 차이는 [task 사용 안내](./00_README.md)를 참고한다.

## 구현 항목

- [x] 담당자가 CSV 파일 또는 콘텐츠 1건을 입력했을 때 필수 필드·원본 ID·출처를 확인하고, 저장 전에 신규·변경·동일·오류 건수와 변경 내용을 미리 볼 수 있게 했다.
- [x] `source_system + source_content_id`를 안정 키로 사용해 콘텐츠를 중복 없이 추가·갱신하고, 최초·최근 확인 시각·원본 수정 시각·콘텐츠 지문·가져오기 실행 이력을 남긴다.
- [x] 교육 의미에 영향을 주는 제목·소개문·콘텐츠 단위 변경은 기존 사람 승인 이력을 `review.history`에 보존한 채 재검수 필요 상태로 보낸다. 변경 없음은 AI 호출·임베딩·재검수를 반복하지 않고, 전체 출처 내보내기에서 사라진 항목은 삭제 대신 비활성 후보로 구분한다.
- [x] 수동 실행과 예약 실행용 명령이 같은 증분 처리 경로를 사용한다. 공식 API·Feed·내보내기 파일은 아직 확인·설정되지 않아 일일 스케줄러를 실제 연결하지 않았으며, 수동 CSV·단건 갱신은 독립적으로 동작한다.
- [x] 새 콘텐츠는 `DRAFT_INPUT`·`PENDING` CuriMap 검수 대기열로 보낸다. 공식근거·기능검증 이력에 자동 편입하거나 사람 승인 없이 CuriBase 검색 자산으로 공개하지 않는다.
- [x] 부분 실패·재실행·잘못된 행이 기존 정상 데이터를 덮어쓰지 않게 하고, 처리·오류·재검수 대기·비활성 후보 수와 실패 사유를 실행 단위로 확인할 수 있게 했다.

## 산출물 (2026-09-17)

- `server/incremental-ingestion.js`: CSV·단건 입력의 필수 필드와 URL·원본 수정 시각을 검증하고, 미리보기와 적용에서 같은 안정 키·지문 비교를 수행한다. 신규·변경·동일·재활성·비활성 후보·오류를 구분하며, 적용은 원자적으로 저장한다.
- `server/ingest-content.js`, `npm run data:ingest`: 터미널에서 CSV 또는 단건 JSON을 미리보기하고 `--apply`일 때만 반영한다. `npm run data:ingest:scheduled`는 공식 원본 CSV가 확인된 후 `INGESTION_SOURCE_FILE`을 설정해 외부 스케줄러가 호출할 준비만 되어 있으며, 현재 자동 실행을 연결하지 않는다.
- `server/data-store.js`, `server/data/curi-store.json`: 스키마 1.1에 `ingestionRuns`·`lastIngestion`을 추가한다. 실행마다 입력 종류·수량·상태·오류·변경 내용을 보관한다.
- `server/server.js`: `POST /api/ingestion/preview`, `POST /api/ingestion/apply`, `GET /api/ingestion/runs`를 제공한다. 적용 API는 유효한 행만 반영하고 잘못된 행을 실행 이력에 남긴다.
- `public/ingestion.html`, `public/ingestion.css`, `public/ingestion.js`: CSV 파일/붙여넣기 또는 단건 입력, 전체 출처 내보내기 여부, 미리보기, 정상 항목 저장, 수량·변경·오류 표시 화면을 제공한다.

전체 출처 내보내기에서 오류 행이 하나라도 있으면 비활성 처리를 하지 않는다. 따라서 불완전한 파일이 기존 정상 데이터를 비활성으로 바꾸지 않는다.

## 범위 밖

- 허가되지 않은 EBS 사이트 전수 크롤링
- 공식 API·Feed가 확인되지 않은 상태에서 특정 공개 페이지 구조에 의존하는 일일 수집
- 사람 검수 없는 자동 승인·자동 검색 공개
- EBS 내부 운영 시스템·SSO·관리자 권한 연동
- 과거 전체 아카이브의 일괄 재수집

## 수동 작업

실제로 저장할 신규·변경 콘텐츠가 있을 때만, 출처 시스템·원본 콘텐츠 ID·원본 URL·제목을 포함한 CSV를 준비하거나 해당 값을 확인한다. 공식 API·Feed·내보내기 파일과 일일 스케줄러는 아직 연결하지 않는다.
