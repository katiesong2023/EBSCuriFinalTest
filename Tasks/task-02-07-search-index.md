# Task 02-07 - 검증 자산의 검색 인덱스 준비

> 현재 정본: [PLANS](../docs/PLANS.md) · 대응: **R00~R03 기반 / 완료 이력·기반 보존**. 기존 승인·증분·화면·출처 자산을 재사용하며 새 탐색의 완료로 확대 해석하지 않는다. 과거 구현·사람 확인 기록은 보존한다.

## 설명

검수된 콘텐츠와 교육과정 문맥을 의미 검색에 재사용할 수 있게 만든다.

- 상태: 완료 — 검색 준비·재시작 뒤 상태 유지 사용자 확인 완료. 실제 재검수 사례는 미실행이며 격리 검증 결과와 구분한다.

## 작업 크기와 추천 모델

- 구분: P0 필수
- 배치: Week 2
- 예상 집중 작업: 약 1.5시간. 개인 입문자 계획용 추정이며 설치·보류·재작업 시간은 별도이다.
- 개발 보조 모델: **GPT-5.6 Terra** (`gpt-5.6-terra`)
- 추천 추론 수준: **medium**
- 선택 이유: 인덱스 갱신과 사용량 기록은 범위가 명확한 데이터 연결 작업이다.
- 상향 조건: 원인을 좁혀도 해결되지 않는 제약·상태·데이터 무결성 문제는 해당 부분만 Sol / medium으로 검토한다.
- 모델 배치는 과업 성격에 따른 추천이며 이 서비스에서 측정한 모델 성능 결과가 아니다. [공식 모델 역할·추론 수준 안내](https://learn.chatgpt.com/docs/models)
- 개발 모델과 서비스 API 모델·비용의 차이는 [task 사용 안내](./00_README.md)를 참고한다.

## 실제 산출물

- `server/search-index-contract.js`: 검증 관계별 제목·공식 성취기준·교과·학년군·핵심개념·사람 검수 근거·수업 활용·공개 원문으로 검색 문서를 만든다. 콘텐츠 ID·검증 자산 ID·관계 ID·콘텐츠 버전·저장 버전·검증 지문과 연결한다. 모델·문서 구성·입력 내용이 같은 경우에만 임베딩을 재사용한다.
- `server/local-embedding.js`, `server/local-embedding-worker.js`: `@huggingface/transformers` 4.3.0과 `Xenova/multilingual-e5-small`의 고정 revision `761b726dd34fb83930e26aab4e9ac3899aa1fa78`을 사용한다. CPU·q8·384차원·평균 풀링·정규화 설정이며, 최대 512토큰까지 색인한다. 넘는 입력은 절단 여부를 기록하고 원문 전체는 검증 자산에 보존한다. 문서에는 `passage:` 접두어를 사용한다.
- 모델은 처음 사용할 때 고정 버전의 공개 파일을 `server/data/.model-cache/`에 내려받고 이후 로컬 파일만 읽는다. 다운로드는 임시 파일을 완성한 뒤 교체하며, 작업 스레드의 다운로드·추론에는 관계당 3분 제한을 둔다. 준비 실패는 재시도할 수 있다. API 키나 유료 API 호출은 필요하지 않다.
- `server/search-index.js`: 검증 자산의 관계 전체가 준비된 후 한 번에 `searchProjection`에 게시한다. 중간 실패 시 완성된 임베딩은 `embeddingCache`에 남겨 재시도에 재사용한다. 현재 자산 전체가 이미 준비됐으면 파일·실행 이력·임베딩을 다시 만들지 않는다. 캐시는 검색 결과가 아니며, 현재 검증 자산과 일치하는 검색 투영만 사용할 수 있다.
- `server/data-quality.js`, `server/data-store.js`: 저장 모델 `1.4`에 `embeddingCache`, `searchIndexRuns`를 추가했다. 이전 저장소는 읽을 때 기본 필드를 보완하고 다음 쓰기에 반영한다. 모든 읽기·쓰기에서 현재 검증 자산·버전·모델과 맞지 않는 검색 자료를 제거한다. 검수 수정·제외·콘텐츠/공식 원문 변경으로 검증 자산이 무효화되면 검색 가능 상태도 해제한다. 읽기만으로 파일을 변경하지는 않는다.
- `searchIndexRuns`에는 시작·완료 시각, 상태, 소요시간, 새 임베딩·재사용 건수, 성공 계산의 입력 토큰·문자 수·절단 건수, 외부 API 호출 0회·API 비용 0달러를 기록한다. 토큰 수는 유료 API 청구량이 아닌 로컬 모델의 실제 입력량이다. 중단된 `RUNNING`은 재시작 후 조회에서 `INTERRUPTED`로 표시하고 다음 준비 때 이력을 확정한다. 디스크에 기록 자체가 실패한 경우 재시작 후 계산량을 완전히 복구할 수는 없다.
- `server/server.js`: `GET/HEAD /api/curibase/search-index?contentCuriId=...` 상태 조회, `POST /api/curibase/search-index` 준비·재시도를 추가했다. POST는 콘텐츠·실행·검수 ID·콘텐츠 버전을 확인하며 검수·저장·연계·가져오기와 같은 서버 쓰기 잠금을 사용한다. 보장 범위는 한 로컬 서버이며 여러 프로세스가 동시에 같은 JSON 파일을 쓰는 운영 환경은 지원하지 않는다.
- `public/review-search-index.js`, `public/review.html`, `public/review.js`: `검증 자산의 검색 준비`, `검색 준비·재시도`, `검색 준비 상태 재확인`과 실행 사용량 표시를 추가했다. 화면에서 CuriBase 저장 후 자동으로 준비하고 기존 저장 자산은 버튼으로 준비한다. 저장 실패와 검색 준비 실패를 구분하며, 준비 중 검수·저장·중복 실행을 막는다. 조회·새로고침은 모델을 실행하지 않는다. API로 직접 CuriBase에 저장한 경우에는 별도로 검색 준비 POST가 필요하다.
- `server/search-index-check.js`, `npm run data:search-index:check`: 임시 저장소·모의 임베딩·화면·API로 실패, 재시도, 버전, 모델 변경, 제외, 중단 복구, 쓰기 실패, 공용 잠금을 확인한다. 기존 검수·저장 검증도 새 화면 모듈과 서버 의존성에 맞춰 갱신했다.
- 기존 로컬 JSON 저장 구조를 유지한다. 교사 검색의 질의 임베딩·유사도 계산·결과 연결은 후속 02-08에서 구현한다. 현재 `검색 준비 완료`는 검색 자료가 준비됐다는 뜻이며 교사 검색 화면은 아직 예시 화면이다.

참고: [모델과 Transformers.js 사용 안내](https://huggingface.co/Xenova/multilingual-e5-small), [Transformers.js 저장·캐시 설정](https://huggingface.co/docs/transformers.js/api/env). 현재 모델은 구현 선택이며 한국어 교육과정 검색 품질이 검증됐다는 뜻은 아니다.

## 수동 작업

- 추가 계정·API 키·사람 승인 입력은 필요하지 않다. 현재 작업 환경에는 라이브러리와 모델을 설치했다. 새 환경에서는 먼저 `npm ci`로 설치하고 최초 검색 준비 시 인터넷 연결을 유지한다.
- 실제 검수 판단을 바꿀 때만 사람이 원문을 다시 검토해 판단·사유·근거를 입력한다. 테스트를 위한 허위 승인·제외 기록은 만들지 않는다.

### 수행한 검증

- `npm run data:search-index:check`: 미저장·오래된 검수 요청 거절, 관계별 중간 실패 후 캐시 재사용, 전체 관계 동시 게시, 동일 요청의 파일·실행 기록 유지, 재검수의 버전 교체, 수정 관계·근거 재색인, 제외와 공식 원문 변경의 색인 제거, 모델 설정/잘못된 벡터 거절, 서버 중단 복구, 게시 저장 실패 후 재시도, 스레드 시간제한을 통과했다.
- 검색 API의 GET/HEAD·RUNNING 조회와 검수·저장·색인 간 공용 잠금, 화면 스크립트의 로딩·실패·재시도·중복 클릭·이전 응답 격리를 확인했다. 기존 저장 화면과 실제 검색 준비 화면 스크립트를 함께 실행한 모의 검증에서 저장 후 자동 준비 연결도 확인했다.
- 실제 로컬 모델로 임시 저장소의 모의 검증 관계 2건을 색인했다. `READY`, 384차원, 입력 합계 152토큰, 외부 API 0회, 반복 호출의 `reused: true`를 확인했다. 모델을 받은 뒤 네트워크가 제한된 환경에서도 실행됐고, 긴 한국어 입력의 512토큰 절단 기록도 확인했다. 실제 사용자 저장 자산과 사람 검수 기록은 변경하지 않았다.
- `node server/verified-save-check.js`, `node server/review-actions-check.js`, `npm run data:candidates:check`, `npm run data:mapping:check`, `npm run data:mapping:failures:check`를 통과했다. 변경 JavaScript의 `node --check`, `git diff --check`와 설치 의존성 취약점 0건을 확인했다.
- 에이전트는 브라우저 제어 도구가 없어 실제 화면의 시각적 확인을 수행하지 않았다. 이후 사용자가 검색 준비·재시작 뒤 상태 유지 확인을 완료했으며, 실제 재검수 사례는 없어 미실행으로 기록한다.
