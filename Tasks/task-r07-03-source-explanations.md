# Task R07-03 - 보관 원문 복구와 근거 있는 내용 설명

## 설명

같은 회차의 보관 원문을 현재 공식 출처와 대조해 복구하고 방송 내용 안내·공개 소개문·검색 이유·인용·출처 상태를 분리한다. 2026-10-05 사용자 요청으로 다섯 task를 작성해 순서대로 구현·검증한다. 사용자 결과 확인은 별도로 남기며 연속 진행 요청에 따라 각 에이전트 검증 후 다음 task를 진행한다. 상태: 진행중 / 구현·검증 완료, 사용자 결과 확인 대기

## 구현 항목

- [x] 보관 감사의 농경문 청동기·냉동인간 등 상세 원문을 원본 ID·판본·출처·현재 페이지로 재대조한다. 확인된 자료만 복구하고 전후 원문/해시·실패·시점을 보존한다.
- [x] 공개 소개문을 그대로 제공하고 서비스의 방송 내용 안내를 별도로 2~3문장 구성한다. 충분한 원문이 없으면 문장을 채우지 않고 부족함을 표시한다.
- [x] 설명별 정확한 근거 문장과 위치를 제공하고 전체 소개문에서 강조한다. 제목 언급·내용/관계 설명·교육과정 확인 수준을 구분한다.
- [x] 확인된 페이지 재생시간·실제 출처·회차 식별·소개문 대조·확인 시점·미확인 재생/장면 상태를 항목별 표시한다.
- [x] 소개문을 다른 판본에 복사하지 않고 저장·재수집 시 풍부한 검증 원문을 보존한다. 원문 변경 후 기존 관계의 무효화를 검증한다.

## 범위 밖

- 유료 생성·영상 분석·동일 제목 간 소개문 복사·실제 사람 승인

## 사전 전제

- R07-02·보관 원문 감사·공식 상세 페이지

## 실제 구현

- `source-enrichment.js`·`source-enrich.mjs`는 공식 회차 ID/제목/주소/현재 내용 해시를 대조한 원문만 같은 회차에 적용한다. 방송 SQLite `source_enrichments`에 전후 원문·해시·출처·응답 지문·시점·결과를 보존하고 본문/FTS/payload를 함께 갱신한다. 목록 재수집에서도 확인된 소개문과 재생시간을 보존한다.
- 2026-10-05 공식 상세 GET3건: 농경문 청동기31→361자, 냉동인간17→331자 복구. 시민 회차226자는 유지. 보관 상세 원문과 현재 원문이 모두 일치했고 페이지 표기 시간298/324/399초를 확보했다. [실행 기록](../docs/r07-03-source-recovery.json). 다른 회차에 복사하지 않았고 재생하지 않았다.
- `source-explanation.js`·`content-preview.js`는 충분한 소개문에서 온전한 문장2~3개를 골라 방송 내용 안내를 구성한다. 원문이 짧으면 문장을 채우지 않는다. 생성 요약/교육과정 판정이 아니라 출처 문장 선택임을 표시한다.
- `teacher-source.js`는 공개 소개문 전체와 정확한 인용 위치를 강조하고, 검색 이유·요청 미확인·회차 식별/소개문 대조/시점/출처/재생시간을 구분한다. 공개 소개문 내 HTML은 실행하지 않는다.
- 원문 복구/보존/다른 판본/해시/설명 인용 계약10개·브라우저5개 통과. [계약](../docs/r07-03-explanation-check.json), [화면](../docs/r07-03-browser-check.json), [모바일](../docs/r07-03-source-mobile.png). 기존 사람 승인 JSON 해시는 유지했다. 방송 DB는 위3회차의 원문/메타·감사 이력만 보강했다.

## 수동 작업

추가 입력·키·계정 설정 없음. 보강 도구는 `node server/source-enrich.mjs --ids=방송ID목록 --apply --report=보고서경로`로 명시적으로 실행한다. Playwright 실행 환경은 기존 화면 검증과 같다.
