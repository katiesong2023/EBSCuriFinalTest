# Task R08 - 관리자용 콘텐츠·연계·품질 관리 분리

## 설명

교사용 자료 탐색·수업 준비 화면에서 관리자 작업을 분리한다. 관리자는 수집·출처·시맨틱 태그·교육과정 연계 검수와 공개 상태를 관리하고, 교사는 그 처리 순서를 알 필요 없이 결과의 확인 수준을 볼 수 있게 한다. 화면 분리 방향은 사용자 확정이며 관리 진입점과 서버 세션 기반 접근 통제를 구현했다. 상태는 진행중이며 사용자 결과 확인을 기다린다.

## 구현 항목

- [x] 관리 진입 화면에서 수집 상태·출처 오류·검수 대기 목록을 확인
- [x] 자료를 선택한 뒤 원문·태그·교육과정 연계 상세와 검수 작업으로 이동
- [x] CuriMap 초안 생성·사람 검수·승인 자산 저장·검색 준비를 관리자 동선에 배치
- [x] 원문 불일치·태그 근거 부족·관계 추론 미확인·교육과정 승인 상태를 구분
- [x] 교사 화면의 개인 수업 모음과 관리자 승인 기록을 별도로 보존
- [x] 관리 화면 분리와 API 접근 통제를 구분해 권한 정책을 정의하고 검증
- [x] 직접 접근·미선택 자료·실패·재시도 상태에서 유효한 다음 행동 제공
- [x] 기존 승인 Gate·수정/제외 이력·원문 지문 무효화 계약 회귀 검증

## 실행 순서

1. R07의 교사 메뉴 개편과 맞춰 관리자 진입을 분리하고, 자료 미선택 시 상세 검수 화면 대신 관리 대상 목록으로 안내한다.
2. 수집·출처·태그·연계·검수 상태를 운영 흐름으로 연결한다. 기존 승인 기록과 교사의 개인 수업 준비안을 별도로 유지한다.
3. 운영 환경의 관리자 권한 정책을 확정하고 화면 직접 접근과 관리 API 접근을 검증한다. 메뉴 분리만 끝난 상태는 접근 통제 완료로 기록하지 않는다.

## 범위 밖

- 화면 메뉴를 숨기는 것만으로 관리자 인증이 구현됐다고 주장
- 교사의 자료 모으기를 교육과정 승인으로 취급
- 미실행 검수 생성·유료 API 호출

## 사전 전제

- R09에서 이미 확보한 원문 표본·검수 후보·기존 승인 저장소 계약. R09 전체 사람 평가 완료와는 별개다.
- R07와 공유하는 교사·관리자 역할 경계. R07 전체 완료를 선행 조건으로 두지 않는다.

## 실제 구현 — 2026-10-02

- `public/admin.html`, `admin.js`, `admin.css`: 자료 목록·상태 필터·30건 페이지·개별 원문/태그/연계/검수 이력. 관리 목록은 교사 판본 묶음과 달리 모든 방송 ID를 유지한다.
- `server/admin-workspace.js`: 방송 SQLite와 검수 JSON을 읽는 `/api/admin/workspace`. 실제 조회 기준 23,362개 관리 자료·방송 22,753 ID·원문 불일치 1개·검수 대기 3개·승인 자산 보유 4자료. 지표는 저장 상태에 따라 바뀐다.
- `public/admin-login.*`, `admin-session.js`, `admin-nav.css`, `server/admin-auth.js`: 로그인·세션 만료·로그아웃, 교사 화면과 관리 화면/API의 접근 경계. 기존 관리 화면에도 목록 복귀와 재로그인을 연결했다.
- 검수 저장소에 없는 자료는 기존 `ingestion.html`에 입력만 준비한다. 관리자가 원문과 교과를 확인하고 미리보기·저장을 실행한다. 원문 수정·제외·승인·검색 준비는 기존 Gate와 저장 경로를 사용한다.
- `server/discovery-catalog.js`: 방송 ID를 검수 저장소에 가져왔을 때 중복 충돌을 막고 수정 원문·비활성 상태를 검색에 반영한다. 원문 지문이 달라져 기존 승인이 무효화된 자료는 관리 목록의 재검수 대상으로 표시한다.
- 태그는 현재 원문에서 로컬 규칙으로 재산출한다. 태그 수동 승인·관계별 검수 이력 DB는 추가하지 않았다. 기존 원문 수정/연계/사람 검수/승인 무효화 이력과 원문·태그 변경 회귀를 확인한다.
- 상세의 출처 대조는 현재 ID·제목·URL이 맞는 기존 대조 기록을 사용한다. 이번 작업에서 외부 원문을 새로 수집·대조하거나 실제 사람 검수를 수행하지 않았다.

## 권한 정책

- 단일 운영자 코드로 로그인한다. 개인별 관리자 계정·권한 등급·SSO는 이번 MVP에 없다. 교사 개인 localStorage는 로그인·로그아웃 시 변경하지 않는다.
- 개발 환경: 서버는 `127.0.0.1`에서 실행된다. `CURI_ADMIN_TOKEN`이 없으면 실행마다 무작위 32바이트 코드를 터미널에 한 번 출력한다. 고정 코드는 32자 이상이어야 한다.
- 세션은 서버 메모리, 8시간 절대 만료, HttpOnly·SameSite=Strict 쿠키다. 로그아웃·서버 재시작 시 무효화한다. 1분 내 실패 5회 이후 로그인 시도를 제한한다.
- 운영 환경(`NODE_ENV=production`): 32자 이상 `CURI_ADMIN_TOKEN`과 정확한 HTTPS origin인 `CURI_ADMIN_ORIGIN`이 없으면 서버 시작을 거절한다. HTTPS reverse proxy 뒤에서 사용하며 Secure·`__Host-` 쿠키를 적용한다. 프록시는 허용된 내부 Host 또는 설정 origin Host를 전달해야 한다. 임의의 forwarded 헤더는 신뢰하지 않는다. 실제 운영 배포는 수행하지 않았다.
- `/admin.html`, `/curimap.html`, `/review.html`, `/ingestion.html`은 세션을 요구한다. 나머지 관리 API는 GET·HEAD를 포함해 401로 차단하며 새 `/api/` 경로도 기본 보호한다. 로그인 엔드포인트는 코드 인증만 허용한다.
- 공개 API는 `/api/curi/search`, `/api/curi/discover`, `/api/curi/discover/resources`, `/api/curi/discover/context`, `/api/runtime`이다. 교사 기능은 로그인 없이 이용한다.
- 관리 쓰기는 허용한 Origin과 세션을 함께 요구하고 Host를 검증한다. 관리 응답은 `no-store`. 유료 API 차단과 승인 Gate는 인증 이후에도 독립 적용한다.

## 수동 작업

- 로컬 일회용 코드 사용에는 별도 설정이 없다. 고정 코드가 필요한 운영자는 32자 이상의 무작위 `CURI_ADMIN_TOKEN`을 서버 실행 환경에 설정한다. 실제 코드는 저장소·문서에 기록하지 않는다.
- 운영 배포 시 운영자가 HTTPS reverse proxy와 정확한 `CURI_ADMIN_ORIGIN`을 설정한다. 이번 로컬 결과 확인의 필수 작업은 아니다.
