# Task R07-14 - 원문 내용 키워드·표시 확대

## 설명

등록 개념이 없는 자료도 원문 내용 단서로 이해할 수 있게 하고 카드의 제한된 키워드 표시를 확대한다. 기존 등록 개념·원문 키워드·추정/교육과정 승인을 구분한다. 상태: **진행중**.

## 구현 항목

- [x] 등록 개념 외 원문에서 확인한 구체 소재/내용 키워드를 제공한다.
- [x] 카드에서 기본8개와 나머지 펼치기를 제공하고 반복 ‘등록 태그 없음’ 배지를 제거한다.
- [x] 제목만 있는 자료와 소개문 근거를 구분하고 키워드 원문/위치를 보존한다.
- [x] 기존 검색·개념 필터·교육과정/승인·자료 저장·원문 안내의 의미를 보존한다.

## 범위 밖

- 영상 내용 추정·키워드로 교육과정 승인·새 검색 개념 규칙 전수 확장
- 유료 API·자료 재수집

## 사전 전제

- 기존 등록 개념·내용 미리보기·교사 카드

## 수동 작업

추가 키·계정·외부 자료 입력은 필요하지 않다.

## 완료 조건

### 에이전트 확인

- [x] 원문 키워드/오프셋·표시/펼침·HTML 안전성 확인
- [x] 실제 커버리지·검색/저장/모바일 회귀 확인
- [x] task/구조/상태 갱신

### 결과 확인

- [ ] 자료 찾기를 새로고침하고 ‘사찰음식’을 검색한다. 등록 개념이 없어도 사찰음식·식재료·수행·요리 등 원문 키워드가 표시되는지 확인한다.
- [ ] 키워드가 많은 카드에서 기본 최대8개와 ‘키워드 N개 더 보기’를 확인한다. 펼치면 나머지 키워드가 보이는지 확인한다.
- [ ] 카드에 ‘등록 개념 태그 없음’ 배지가 반복되지 않는지 확인한다. 제목만 있는 자료는 기존 원문 부족 안내가 유지되는지 확인한다.
- [ ] 검색 관련 이유에서 공개 소개문을 열어 키워드 근거를 확인하고 모바일 화면·내 자료 저장이 정상인지 확인한다.


## 구현 결과

- 기존 표시 문제: 등록 개념 어휘가 좁고 `teacher-discovery.js`가 카드용 태그를3개로 제한했다. 최초 대표 자료 집계는 등록 개념1,496개였으며, 전체 판본을 포함해 재측정하면23,360자료 중1,612자료다. 소개문이 빈 자료는13,076개다.
- `server/content-keywords.js`는 기존 내용 미리보기 추출기를 재사용해 공식 단원 탐색 어휘·구체 사회/과학 소재·생활/음식/지명 어휘와 제목/소개문의 교차 표현을 제공한다. 기존5개 미리보기 기본 동작은 유지하고 표시용 호출만 어휘·상한·제목/본문 교차 조건을 확대한다.
- `content-preview.js`에 선택적 키워드 옵션을 추가했다. `contentKeywords`는 원문에서 다시 확인한 label/kind/evidence(field,start,end,quote,sourceUrl)를 반환한다. 등록 개념은 REGISTERED_CONCEPT, 추가 원문 어휘는 SOURCE_KEYWORD다. 제목만 있으면 제목 근거만 사용하며 비유 심장·인명 화석·부분 문자열 오탐과 추론 상위 개념을 걸러낸다.
- `teacher-discovery.js`는 모든 직접 등록 개념을 응답에 보존하고 내용 키워드를 추가한다. 새로운 표시용 어휘를 검색 개념/개념 필터/자동 관계 규칙·학교 적합성으로 등록하지 않는다. 기존 검색·승인 저장소는 변경하지 않았다.
- `public/teacher-cards.js`는 내용 키워드를 기본 최대8개 표시하고 나머지는 단일 펼치기로 제공한다. 등록 태그 없음 배지는 제거했다. 키워드의 제목/소개문 근거는 툴팁에 표시하고 `teacher-source.js`의 기존 공개 소개문 강조에 연결한다. 태그가 없는 경우 원문 품질/내용 안내를 유지한다. 추정으로 빈 칸을 채우지 않는다.
- 전체 카탈로그에서 표시 가능한 내용 키워드가 있는 자료는6,320개, 기존 등록 개념 없는4,708자료에 새 단서가 생겼다. 기존 개념 태그 목록/승인 분모와 이 표시 범위는 별도다. 현재 자료의 약27%이며 제목만 있는 자료·등록되지 않은 소재·짧은 소개문은 여전히 제한된다.

## 검증 기록

- 신규 계약6개(전체 커버리지/원문 위치/HTML 안전성 포함)·격리 화면3개·기존 필터10/수업 폴더12 통과. [계약/커버리지](../docs/r07-14-content-keywords-check.json), [화면](../docs/r07-14-content-keywords-browser-check.json), [필터](../docs/r07-14-http-browser-check.json), [폴더](../docs/r07-14-folder-browser-check.json).
- 390px 기본8개/펼침·원문 열기·등록 개념 없는 소재·저장/새로고침·필터 조건 보존·HTML 이스케이프 확인. 모바일 캡처 육안 확인, 페이지 오류0·유료API0·보호4저장소 SHA 동일.
- 기존 `content-preview-check.js`의 도입 문장 제외 기대는 변경 전에도 실패한다. 기존 안내가 문맥 첫 문장을 보존해 ‘1월’ 문장을 포함하기 때문이다. git HEAD의 변경 전 코드와 현재 기본 옵션의 결과가 완전히 동일함을 확인했고 표시용 키워드 범위를 넘어 미리보기 안내를 바꾸지 않았다. [기준선 대조](../docs/r07-14-preview-baseline-check.json). 해당 기존 실패를 통과로 기록하지 않는다.
- 실제3000서버를 재시작하고 사찰음식·볼리비아·생태계 다큐 검색의 원문 키워드를 확인했다. [실행 서버](../docs/r07-14-running-server-check.json). JS 구문·차이 공백 검사 통과, 사용자 결과 확인 대기로 진행중이다.
- 재현: `node server/content-keywords-check.js`, `node server/content-keywords-browser-check.js`(기존 Playwright 환경 변수). 필터 검사는 기존 스크립트 출력 접두사를 R07-14로 바꿔 과거 기록을 보존했다.
