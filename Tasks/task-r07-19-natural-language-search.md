# Task R07-19 - 교사 자연어 검색 개선

## 현재 후속 실행 — 2026-10-14

현재 후속 순서는 [R12 실행 계획](task-r12-lesson-preparation.md)을 따른다. 아래 2026-10-14의 모델 계약/A·B 우선 순서는 과거 제안으로 보존하고 필수 선행으로 사용하지 않는다. 실제 요청·독립 평가/공통 원인 개선/교사 선택 검증은 R12-01/03/06으로, UX 검토·수정 지시 먼저 제시/반영은 R12-04/05로 이관한다. 모델은 남은 원인의 선택 비교다. 기존120요청과 이미 노출된 최종40개·외부12질문은 개발 회귀이며 새로운 독립 평가로 재사용하지 않는다. 기존 완료 체크·계약·결과 확인 대기는 유지하고 중복 구현/실적 집계를 하지 않는다.

## 설명

교사의 요청을 핵심 주제·원하는 관계/내용·필수 조건·선호·수업 문맥으로 구분하고, 다른 표현으로 소개된 방송도 발견하여 원문 근거에 따라 추천한다. 현재의 규칙 분해 후 모든 잔여 단어를 요구하는 검색을 개선하며, 부분 문자열 오탐 방지와 명시적 조건은 보존한다. API 없이 수행할 개선을 먼저 검증하고, 모델이 필요한 요청 해석·후보 재정렬은 별도 비용과 효과를 비교해 도입한다. 상태: **진행중**. 2026-10-13 사용자 변경 승인으로 API 없는 개선·평가를 진행한다. 유료 API 실행은 별도 승인 대상이다.

## 현재 진단과 목표

- 정본 진단: [실제 검색 13입력](../docs/r07-19-natural-language-diagnosis.json). 연소2건/다문화10건/지구 자전2건과 달리 해당 주제의 일부 자연어 요청은0건이다. 진단 입력13개는 개발 사례이며 독립 정답률 표본이 아니다.
- 현재 교사 화면은 규칙 해석과 키워드/등록 개념 검색을 사용한다. 기존 로컬 임베딩은 별도의 승인 자산 검색 경로이며 전체 방송 검색에는 연결되지 않았다.
- ‘필요한’, ‘설명해주’, ‘알려주’ 같은 요청 표현이 필수 내용어로 남아 후보를 제거한다. 정해진 일부 표현 외에 유사한 뜻의 문장을 일반화하지 못한다.
- R07-17 기준 전체23,360건 중 문맥 검사에 사용 가능한 소개문은6,235건이다. 이 수는 의미 정확도 판정이 아니다. 정보 공백과 검색 실패를 별도로 측정한다.
- 결과 수 증가를 목표로 삼지 않는다. 요청을 충족하는 자료의 발견, 상위 결과의 관련성, 원문 근거, 명시적 제외 조건 준수를 목표로 삼는다.

- [x] ‘연소에 필요한 조건을 설명해주는 영상’에서 연소/연소 조건/설명 목적을 구분하고, 요청 동사가 필수 내용어로 남지 않게 한다.

- [ ] 모델 사용의 대상과 호출 시점을 정하고, 기존 규칙/로컬 의미 검색 대비 효과와 비용을 비교한다. 전체 자료를 매 검색마다 모델에 보내지 않는다.

- [ ] 발견된 후보의 원문을 근거로 ‘주제 언급’과 ‘요청한 관계/방법 설명’을 구분하여 순위를 정한다. 근거가 부족하면 미확인으로 남긴다.

## API가 필요한지 판단하는 지점과 별도 작업

API는 자연어 검색의 필수 조건이 아니다. 아래 A/B는 현재 규칙의 한계를 보완하기 위해 권장하는 모델 적용 지점이며, 로컬 모델로 목표 품질/지연을 만족하면 외부 API 없이 대체할 수 있다. C는 로컬 임베딩 평가 후 선택한다. 특정 공급자/모델/단가/호출량은 이 문서에서 확정하지 않는다.

| 지점 | 도입 이유·결정 시점 | 별도로 수행할 작업 | 비용이 발생하는 대상 |
| --- | --- | --- | --- |
| A. 요청 의미 해석 | 긴 문장의 주제·관계·부정·필수/선호를 규칙만으로 안정적으로 분리하지 못할 때 | 원래 요청에서 의미 항목을 추출하고, 요청 표현과 추출 결과를 대응한다. 모호함은 보류한다. 고유명/제외/필수 조건 보존과 API 없는 해석 대비 품질을 검사한다. | 호출 대상 요청의 입력·출력. 모든 검색에 쓸지 어려운 요청에만 쓸지는 비교 후 결정한다. |
| B. 후보 의미 재정렬 | 임베딩 유사도와 키워드 점수만으로 요청한 원인·과정·관계를 설명하는지 구분하기 어려울 때 | 제한된 후보의 ID·제목·소개문을 요청과 비교하고, 관련성 판단·원문 인용·보류를 반환한다. 존재하는 후보/원문인지 검증하고 순위 개선을 평가한다. | 선택 후보의 원문과 요청 입력, 판단/인용 출력. 후보 수·텍스트 길이에 따라 달라진다. |
| C. 외부 임베딩 비교 | 전체 방송에 연결한 로컬 임베딩의 한국어/교육 표현 품질 또는 운영 성능이 목표에 부족할 때 | 같은 자료/질의로 로컬과 외부 임베딩을 비교하고, 문서/질의 표현의 호환성과 원문 변경 시 갱신을 확인한다. | 처음 준비하는 문서, 변경 문서의 재처리, 검색 질의. 저장/호스팅 비용은 선택 구성에 따라 별도다. |

### 유료 실행 전 비용·효과 확인

- [x] 현재의 유료 API 미사용 조건을 유지하고, 먼저 API 없는 기준선/개선을 준비한다. 이 task 작성은 유료 호출 승인이 아니다.
- [x] A/B/C를 각각 사용/미사용하는 비교안, 후보 수·전송 원문·모델·예상 호출 수·재시도 한도·예산 상한을 검토 가능한 형태로 제시한다. 키의 실제 값은 읽거나 출력하지 않는다.
- [x] 요청 해석과 재정렬 각각의 예상 입력/출력 분량을 측정하여, 시험 실행 비용·검색1회 비용·1,000회 비용을 따로 산정한다. 초기 색인 비용과 운영 검색 비용을 분리한다.

- [x] 유료 호출은 사용자가 구체적 실행 범위와 예산을 승인한 후 진행한다. 승인 전에는 비용 산정과 비호출 준비를 완료하고 API에 의존하지 않는 작업을 계속한다.
- [ ] 승인된 소규모 비교부터 실행하고 실제 비용·지연·품질을 기록한다. 전체 적용은 효과가 확인된 범위와 예산 안에서 진행한다.

소개문 전수 모델 분석은 [R07-17](task-r07-17-full-context-index.md)의 별도 검토다. 그 완료를 본 검색 개선의 필수 선행 조건으로 두지 않으며, 기존 전수 분석 비용을 실시간 검색 비용으로 재사용하지 않는다. 검색은 확보한 콘텐츠를 찾고 비교하는 역할이며 원문에 없는 내용을 모델로 복원하지 않는다.

## 평가·완료 판단 기준

- 원문과 요청의 의미에 따른 정답/부분 적합/보류를 기록한 후 비교한다. 정답 자료를 알 수 없는 요청은 누락률 계산에서 구분한다.
- 기능 회귀와 의미 품질 평가는 별도 보고한다. 빈 결과를 없애기 위해 부적합한 자료를 반환하지 않는다.
- 개발 표본에서 발견한 개선은 최종 평가40개로 다시 확인한다. 관계/부정/긴 문장별 악화 사례도 공개한다.
- 최종 표본의 상위5개 관련성과 알려진 정답 상위20개 발견률이 기준선 대비 개선되어야 한다. 조건 위반0건을 회귀 사례에서 확인하며, 통과가 모든 자연어 요청에 대한 무오류 보장은 아니다.

### 같은 질문의 LLM 전후 비교 기준

1. 현재 로컬만 → 로컬+요청 해석 A → 로컬+A+후보 비교 B를 같은 질문/자료·회차·원문 지문/필수 조건/판정 기준으로 비교한다. 공식 원문 보강은 별도 데이터 변경 비교로 분리한다.
2. A는 주제·관계·조건/목적의 요청 구절 대응, 조건 누락/임의 추가, 후보 발견 개선을 확인한다. 추출한 조건이 검색에 실제 적용되는지도 별도로 검사한다.
3. B 자체 효과는 동일 후보ID/원문 집합의 재정렬 전후로 비교한다. A가 후보 집합을 바꾼 전체 A+B 효과와 혼합하지 않는다.
4. 상위5 관련성·알려진 정답 상위20 발견률·조건 위반·요구 관계별 원문 인용/보류·실제 비용/지연/실패 fallback을 기록한다. 정답 미확보와 미검토는 분모에서 구분하고 LLM 판단만으로 정답을 확정하지 않는다.
5. 현재 A/B는 **미실행**이므로 개선 효과를 수치로 채우지 않는다. 실행 범위/예산은 기존 비호출 비교안을 기준으로 별도 승인한다. 먼저 실패 원인이 데이터 보유/인용/검색 연결/지역 강제에 있으면 그 구현을 해결하고, 의미 해석/후보 비교에 남는 한계를 모델 전후로 검증한다.

상태는 진행중이다. 책임 구분과 비교 기준을 작성한 것은 LLM 도입 효과나 수업 적합성 검증의 완료가 아니다.


## 1단계 요청 해석 계약 수신·재현 — 2026-10-13

사용자가 제공한 `curi-request-v1`을 **1단계 요청 해석의 참조 계약**으로 보존했다. [수신 계약](../docs/r07-19-request-interpretation-contract.md), [출력 Schema](../docs/r07-19-request-interpretation.schema.json), [시스템 입력 봉투 Schema](../docs/r07-19-request-input-envelope.schema.json), [검증 재현 결과](../docs/r07-19-request-contract-validation.json), [원본12파일 지문](../docs/r07-19-request-contract-manifest.json), [원본 묶음](../docs/r07-19-request-contract-bundle.zip)을 제공한다. 묶음 안의 `request-contract/check.cjs`로 같은 검사를 재현할 수 있다. 사용자 외부 원본은 수정하지 않았다.

수신 당시 계약의 범위는 요청 구조/책임 분담/수작성 예시 검증이며 제품 연결은 제외했다. 원본 묶음과 지문은 당시 상태로 보존한다. 이후 사용자의 입력 봉투·선택 조건 보존·런타임 검증·검색 계획 연결 요청에 따른 현재 제품 연결은 아래 후속 절에 기록한다. 실제 LLM 호출은 연결하지 않았다. JSON Schema의 형태 준수·원문 위치 준수와 임의 응답의 의미 보존은 별도 검증이다.

### 고정할 의미와 책임

- 사례의 필수 논리는 **화산 지형 AND 국내 AND 지역 사례**, 수업자료는 `purpose/context`다. ‘해당하는/수업자료’를 방송의 필수 등장 단어로 사용하지 않는다.
- 원문에 없는 ‘한라산/제주도’ 필수 지역이나 화산 형성 과정 요구를 추가하지 않는다. ‘용암 지형’ 같은 가설적 확장은 후보 발견에만 사용하며 새 필수 조건·조건 충족 근거가 아니다.
- LLM은 원문 구절에 대응한 주제/관계/필수/제외/선호/문맥과 보류를 반환한다. 후보ID·영상 내용·사람 승인·교육과정 적합성은1단계 출력에 넣지 않는다.
- 검색 시스템은 원문/UTF-16 위치·Schema·참조/논리·의미 보존 검사와 기존 `lockedConditions` 보존을 맡는다. 지역/프로그램/형태/기간/공식 기준의 실제 대조, 조건 적용과 후보 확보는 검색·데이터 책임이다.
- 요구별 `MATCH/MISMATCH/UNKNOWN`을 구분한다. 국내/제외 대상의 부재나 관계 설명을 확인하지 못하면 필수 강도를 낮추지 않고 미확인으로 남긴다. 탐색 후보와 모든 필수 조건의 충족 결과를 구분한다.
- 학년은 수업 문맥이다. 계약이 학년을 반환해도 수집 제한/영상 적합성 판정으로 사용하지 않는다. 공식 학년군·중1 참고 편성과 학교 진도는 별도다.

### 23개 검증의 의미

복제한 임시 묶음에서 직접 재실행해 **23통과·실패0·LLM/API0**을 확인했다. 정상10개 + 계약 구조 검사로 거절한 오류8개 + **수작성 기대 의미 대조로 거절한 오류5개**다. 마지막5개는 국내 누락/선호 강등·AND/OR 변경·미등록 이름 훼손·임의 지역 추가가 형식 검사를 통과할 수 있음을 보여준다. `semanticExampleErrors`는 주어진 개발 기대값과 비교하는 함수이며 임의의 실제 모델 응답 의미를 보장하는 범용 검증기가 아니다. 현재 계약 로컬 검증기는 이 Schema에서 사용하는 키워드의 일부만 지원한다. 실제 LLM 이해 성능/후보 검색/관련성/교사 효용으로23개를 보고하지 않는다.

## 입력 봉투·런타임 검증·검색 계획 연결 — 2026-10-14

사용자가 지정한 네 항목을 제품 검색 경로에 연결했다. 기존 GET은 로컬 검색을 유지하면서 `requestExecution.envelope`에 원문 질문과 시스템 소유 선택 조건을 제공한다. 모델 응답을 생성하지 않는다. 구조화 응답은 읽기 전용 `POST /api/curi/discover/interpretation`의 `{ "input": { "q": "원문 질문", "program": "기존 선택 프로그램" }, "interpretation": 계약응답 }`으로 전달할 수 있다. `input`은 기존 교사 검색 조건만 받으며 `lockedConditions`를 호출자가 지정하거나 덮어쓸 수 없다. 수작성 응답을 연결한 테스트와 실제 LLM 실행을 구분한다.

- `request-envelope.js`: 200자 제한을 자르지 않고 검사하며 공백을 포함한 원문과 공식 기준·유형·프로그램·기간·정렬·페이지·장소·보기 등 검증된 선택 조건을 보존한다. 모델 출력으로 선택 조건을 변경하지 않는다.
- `server/data/request-*.schema.json`과 `request-contract-validation.js`: 수신 Schema에서 사용하는 전체 타입/키워드를 동등하게 검사한다. 깊이32·배열256 제한, UTF-16 구절·전체 내용 구절 대응·참조·필수/제외·AND/OR 분기·국내 누락·고유명/임의 장소·문맥의 필수화·날짜/길이 변경 등을 명시 규칙으로 검사한다. 개발 기대값 비교를 런타임 채택 기준으로 쓰지 않는다. 새로운 표현의 범용 의미 보장은 아니며 보수적 검증이 유효 응답도 보류할 수 있다.
- `request-search-plan.js`: 주제/고유명과 후보용 확장을 검색에 전달하고 원래 논리 트리로 조건을 대조한다. 국내/장소·프로그램·형태·방송 날짜는 실제 원문/메타데이터로 검사한다. 길이는 출처 있는 실제 길이가 있을 때만 대조한다. 선호는 가점, 수업 목적/대상은 문맥이며 필터로 승격하지 않는다. 기존 공식 선택 기준은 기존 교집합 경로로 보존한다.
- 요구별 `MATCH/MISMATCH/UNKNOWN`과 근거를 기록한다. 필수 지역/프로그램/형태/날짜/교육과정이 미확인이면 해당 논리 분기의 충족 후보로 제공하지 않는다. 일반 관계 설명·장면·자막·지원되지 않은 조건은 미확인/미지원으로 남는다. 일부 주제·관계 미확인 후보는 `DISCOVERY_ONLY` 탐색 후보로 구분한다. `SOURCE_REQUIREMENTS_MATCH`도 원문/메타데이터 대조이며 영상·난이도·교사 효용·사람 승인이 아니다.
- 무응답 `LOCAL_ONLY`, 검증 실패 `FALLBACK_INVALID`, 모호함/충돌 `NEEDS_CLARIFICATION`, 전달 응답 채택 `SUPPLIED_CONTRACT_APPLIED`를 구분한다. 실패/보류에서는 원래 질문·선택 조건으로 로컬 탐색하며 해석 미적용과 조건 충족 미보장을 알린다. 프로그램/기간 충돌은 AND/OR의 양립 가능한 분기를 고려한다. 미지원 절ID를 실행 결과에 남긴다.
- 기존 카드 원문 영역에 요청별 대조와 영상 미확인을 표시한다. 새 공개 경로는 검색만 수행하며 관리자 인증과 저장 경로는 보존한다.

## A·B 비호출 연결 준비 구현 — 2026-10-14

사용자의 다음 작업 진행 요청에 따라 제품 코드를 준비했다. [계약 차이·연결 방법](../docs/r07-19-model-contract-differences.md)에 제품 v1과 실험 v2의 차이, 수신 응답과 실제 모델 실행의 구분을 기록했다. v2의 버전명 변경이나 value 삭제로 암묵 변환하지 않는다. 이후 공통 실패·효용 검증은 현재 R12 실행 계획에서 이 준비를 재사용하며 중복 실적으로 집계하지 않는다.

- `request-model-preparation.js`는 A 요청 해석과 B 후보 원문 비교의 생성용 Schema·지시문·Responses 응답 처리를 준비한다. `request-model-client.js`는 기본 차단 상태다. 외부 호출 허용 옵션은 공개 API에서 받지 않으며 이번 경로는 이 클라이언트를 실행하지 않는다. 예산 값은 승인 범위 기록으로, 실제 금액 상한 기능은 후속이다.
- `POST /api/curi/discover/model-preparation`은 `{input}`으로 A 요청 준비, `{input,aResponse}`로 검증된 v1 검색과 B 준비, `{input,aResponse,bResponse}`로 B 원문 검증·후보 비교를 수행한다. 일반 GET/화면은 모델을 자동 실행하지 않는다. 기존 선택 조건·성취기준 교집합·정렬·페이지를 유지한다.
- `candidate-review.js`와 `server/data/candidate-review.schema.json`은 요청/선택 조건 지문, 자기 회차 ID·원문 지문·전송 구절의 UTF-16 위치/인용·요구 누락/중복을 검사한다. 최대10후보·소개문 앞600자를 전송하며 잘림을 표시한다. 잘못된 B 묶음은 전체 미채택한다. 지역/프로그램/날짜 등 시스템 조건과 제외 조건은 B가 덮어쓰지 못한다. 인용의 문자 일치는 의미 판단 정확성을 보증하지 않는다.
- 명시한 현무암·용암·분화구와 고유명을 상위 화산 주제로 대체하지 못하게 하고, 좁은 요청의 원문 단서 없는 탐색 후보를 억제했다. 전체 어휘의 좁은 개념 분류나 일반 관계 판정을 완성한 것은 아니다.
- 기존 카드의 `teacher-source.js`/`teacher-cards.js`/`teacher-workspace.css`에 선택 이유 → 검증 인용 최대2개 → 남은 확인 → 원문 열기를 우선 표시한다. 전달된 B 비교와 영상 미확인을 표시하며 기존 개인 저장·교육과정 상세를 유지한다.

### 검증 및 한계

[비호출23검사](../docs/r07-19-model-preparation-check.json)와 [복제 서버 HTTP8검사](../docs/r07-19-model-preparation-http-check.json)가 통과했다. 다른 요청/회차/변경 원문·잘못된 인용·조건 주입 거절, 공식 기준 밖 B 후보 제외, 관리자401과 기본 외부 실행 차단을 포함한다. [기존 질의27검사](../docs/r07-19-model-query-regression.json)와 [결합 검색20검사](../docs/r07-19-model-combined-regression.json)도 통과했다. 보호4저장소의 이번 검사 전후 지문은 동일하며 유료 호출0이다.

기존 연결 검사를 다시 실행한 결과 기능38개는 통과했지만 마지막 과거 원본 보존 검사는 고정 지문과 현재 방송 DB의 차이로 실패했다. [별도 기록](../docs/r07-19-model-historical-baseline-check.json)에 실제 차이를 보존했으며 기존 검사·기준선·DB를 이 실패에 맞춰 수정하지 않았다. 이전39개 통과 기록과 현재 실패를 구분한다. 개발 중 명령의 phase 지정 오류로 `docs/query-regression-before.json`이 재생성됐으며, 이를 독립 평가의 새 기준선으로 사용하지 않는다. 이번 질의 회귀는 별도 model-query 보고서다.

실제 localhost:3000 서버는 재시작하지 않았다. 화면 검사는 VM의 마크업/escape 검사이며 브라우저·모바일 시각 검증은 남아 있다. 수신12질문과 기존 평가 질문은 개발 회귀로만 사용하고 모델 품질 성공률을 산출하지 않았다. 실제 A→검색→B 운영 실행, 공급자 호환성·비용/지연·새 질문 의미 품질·원문 보강·영상/교사 확인은 남아 있어 진행중이다.

이번 준비의 결과 확인:

- [ ] 계약 차이 문서의 비호출 연결 범위와 실제 호출 후 검증할 범위를 확인한다.
- [ ] 최신 서버 적용 후 기본 카드의 선택 이유·인용·남은 확인·원문 링크와 모바일 표시를 확인한다.
- [ ] 새 독립 질문에서 실제 A/B 의미 품질과 같은 후보의 비교 효과를 확인한다. 이 항목은 유료 미호출 단계에서는 완료하지 않는다.


## R07-21 원문 보강 인계 — 2026-10-14

[원문 보강 비교](../docs/r07-21-improvement-report.json)에서 원문 부족12회차 중9개(공식소개4/자막5)를 보강했다. 자석0→2·제시 피난생활0→1·천연벽지 제작0→1은 원문에 근거한 좁은 발견 개선이다. 수신된 긴12질문은 로컬 경로에서0→0이므로 실제 A/B·관계/형태 조건 처리의 완료로 보고하지 않는다. 공식 자막은 소개문과 별도인 검증된 보조 원문이며 B의 현재 title/summary 인용 계약과 확장 연결은 별도 검증이 필요하다. 다른 회차 원문이나 제목만으로 관계 충족을 만들어내지 않는다.
