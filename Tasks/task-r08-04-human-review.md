# Task R08-04 - 관계별 사람 확인과 결정·자산 저장 통합

## 설명

사람 검토 기능을 후속 운영에서 선택적으로 사용할 수 있도록 관계별 비교·판단·저장을 한 흐름으로 줄인다. 이 기능의 구현은 이번 개편 범위지만 전량 사람 검토의 수행은 자동 연계 제공의 필수 조건이 아니다. 2026-10-05 구현·에이전트 검증을 마쳤으며 상태는 **진행중 / 사용자 결과 확인 대기**다. 자동 결과를 승인으로 바꾸는 것이 아니라 실제 사람이 확인한 관계에만 사람 검토 기록과 승인 자산을 만든다.

## 구현 항목

### 관계별 비교와 판단

- [x] 자료의 원문 인용·위치와 공식 성취기준의 요구를 나란히 확인하고, 연결 부분·부족한 부분·자동 검사 결과·현재 버전을 비교한 뒤 관계별 승인·수정·제외·보류를 결정할 수 있게 한다.
- [x] 자동 후보와 기존 사람 검토용 초안을 함께 다룰 수 있게 하되 유료 AI 초안을 필수로 요구하지 않는다. 실제 사람의 결정·시각·운영자 역할·사유·참조 근거 버전이 남아야 한다. 기존 단일 운영자 세션을 개인별 실명 인증으로 표시하지 않는다.
- [x] 관계별 최신 유효 결정과 이력을 관리한다. 한 관계의 승인·수정·제외가 다른 성취기준 관계를 함께 승인·삭제·무효화하지 않아야 한다. 원문 변경 시에는 그 원문을 공유하는 관계의 유효성을 다시 판단한다.
- [x] 원문 변경·상충·보류 등 예외부터 실제 검토할 수 있게 한다. 같은 제목·검색 대표 그룹·다른 학년이라는 이유로 사람 결정을 전파하지 않는다.
- [x] 필요한 부분만 수정하고 제외·보류 사유를 선택할 수 있게 하며, 목록 조건 유지·다음 자료 이동·키보드 조작으로 반복 입력을 줄인다. 미저장 변경을 감지하고 입력 중 단축키가 의도치 않은 결정을 만들지 않게 한다.

### 결정과 승인 자산 저장

- [x] 한 번의 실제 검토 결정으로 검토 기록과 해당 관계의 승인/수정 자산 저장을 이어 처리한다. 기존처럼 검수 저장 뒤 별도 CuriBase 저장을 다시 해야 하는 필수 절차를 없앤다.
- [x] 제외·보류는 해당 결정을 보존하고 현재 제공 가능 여부에 반영한다. 제외한 관계를 자동 재검사가 다시 공개하지 못하게 하며, 다른 유효 관계와 주제 탐색에는 결정 범위에 맞는 영향만 준다.
- [x] 서버가 실제 사람의 확인 기록·원문/공식 기준/관계 버전·권한을 검증한다. 오래된 화면이나 자동 결과만으로 사람 승인 자산을 만들 수 없어야 한다.
- [x] 반복 클릭·응답 유실 뒤 재시도·동시 수정이 중복 결정·중복 승인 자산·판단 덮어쓰기를 만들지 않게 한다. 기록과 자산 저장의 일부만 성공한 상태를 최종 성공으로 안내하지 않으며 복구 후 일관된 결과를 제공한다.
- [x] 승인 자산 저장 후 이미 자동 실행되는 검색 준비를 유지한다. 결정/자산 저장 성공과 검색 준비 실패를 따로 표시하고, 검색 준비만 재시도할 때 새 사람 결정이나 재승인을 요구하지 않는다.

### 기존 승인과 데이터 호환

- [x] 현재 콘텐츠 최신 실행·검토 하나에 묶인 Gate를 관계별 결정에 맞게 보완하면서 공식 근거·실제 사람 확인·버전 일치의 기존 조건을 유지한다. 자동 실행만 추가해도 기존 승인이 무효화되는 일이 없어야 한다.
- [x] 기존 승인 자산 4개·검토 시각·결정·공식 근거·무효화 이력을 보존한다. 기존 묶음 검토를 관계별로 참조할 때도 새로운 검토를 한 것처럼 행위자·시각을 만들지 않는다.
- [x] 자동 관계·사람 결정·승인 자산·검색 준비의 참조와 우선순위를 R08-02의 데이터 구조에 연결한다. 원문 변경, 특정 기준 변경, 실제 사람 제외, 자동 규칙 변경의 영향을 구분한다. 자동 규칙 변경만으로 여전히 유효한 사람 승인을 취소하지 않는다.
- [x] 기존 검수 화면 직접 접근과 관리자 작업공간의 처리 결과가 일치하고 권한·원문 변경 감지·승인 필터가 유지되게 한다.

## 범위 밖

- 전량 사람 검토, 고정 검수량 달성, 에이전트가 실제 사람 판단을 대신 입력
- 자동 통과의 `HUMAN_VERIFIED` 승격, 다른 판본·학년에 대한 일괄 승인
- 다중 관리자 계정·실명 추적, 실제 영상의 난이도·장면·학년 적합성 자동 보증

## 사전 전제

- 구현 전 Gate는 같은 콘텐츠의 모든 관계를 최신 검토 한 건에 묶었다. 이번 변경은 UI뿐 아니라 기존/새 승인 자산과 검색 투영의 유효성 판단을 관계 단위로 바꿨다.

## 실제 구현

- `public/admin-human-review.js`를 관리자 상세에 연결했다. **원문·관계별 사람 판단 열기**에서 자동 후보·기존 초안·공식 관계 직접 선택을 이용하고, 인용 위치와 기준 요구·연결/미확인 부분·현재/과거 근거를 비교한다. **결정·해당 자산 함께 저장** 한 번으로 관계별 판단과 해당 승인 자산을 저장한다.
- `server/human-review-workspace.js`·`human-review-contract.js`가 공식 목록·원문·정확한 인용·참조 버전·이력을 구성/검증한다. `human-review.js`는 실제 확인·부분 수정·사유, 서버 시각과 단일 운영자 역할을 저장한다. 새 유료 초안을 요구하지 않는다.
- 인증된 `GET/HEAD /api/admin/human-review`는 `contentCuriId` 또는 `resourceId`와 선택 `subject`, `standardId`를 받는다. 같은 경로의 POST는 `target`, `curriculumCuriId`, `expectedVersion`, `requestId`, `decision`, `confirmed`, `reasonCode`, `note`, 선택 `subject/changes`를 받아 저장한다. `POST /api/admin/human-review/search`는 `reviewId`로 검색 준비만 재시도한다.
- `curi-store.json`의 선택 배열 `relationReviews`와 `verifiedAssets`를 같은 원자 파일 교체로 확정한다. 기존 JSON 1.4·자동 SQLite v1을 보존하며 첫 실제 결정 전에는 승인 JSON을 변환하지 않는다. 미가져오기 방송도 원본 ID로 검토할 수 있다. 요청 ID·버전 대조·단일 프로세스 쓰기 잠금으로 반복/충돌을 막고, 응답 유실 때 브라우저가 원래 요청을 보존해 동일 요청으로 재확인한다.
- 실제 제외/보류도 자동 재공개보다 우선한다. 원문 변경은 공유 관계를, 기준/개별 판단 변경은 해당 관계를 재확인한다. 기존 초안 참조 내용이 바뀌면 해당 승인을 무효화한다. 자동 실행/규칙만 바뀌면 사람 승인에 영향이 없다. 삭제된 공식 기준의 새 사람 이력은 읽기 전용으로 남긴다.
- `data-quality.js`·`search-index-contract.js`·`search-index.js`는 기존 묶음 승인도 자산별로 대조하고 형제 관계 투영을 보존한다. 검색 준비 실패 시 결정/자산 저장 성공을 유지하고 **이 관계 검색 준비만 재시도**를 제공한다. 방송 가져오기/보강 후에도 판본을 보존해 기존 제외를 우회하지 못하게 했다.
- `review.html`의 기존 주소는 `review-route.js`를 통해 같은 관리자 작업공간으로 이동한다. 목록 검색/필터/정렬·관계 선택·다음 자료, Alt+S/Alt+N, 미저장 이탈 경고를 유지한다. 입력칸에서는 단축키가 작동하지 않는다. 기존 묶음 API는 호환용으로 남기되 관계별 새 결정이 있는 콘텐츠를 다시 묶음 처리하지 않는다.
- 새 사람 승인도 교사 카드·폴더·내보내기에 확인한 부분/전체 범위·인용·미확인 내용을 표시한다. 관리자 사유 메모는 공개 인용과 별개다. 데이터 구조는 [ERD](../docs/ERD.md), 책임은 [구조](../docs/ARCHITECTURE.md)에 기록했다.

## 실행 검증

- `node server/human-review-check.js`: **18개 통과**. 실제 확인 누락·위조·짧은 원문·인용 불일치 차단, 관계별 승인/수정/제외/보류, 형제 보존, 원자 쓰기 실패, 중복/응답 유실/동시/오래된 요청, 검색 단독 재시도, 원문/기준/초안 변경, 공식 기준 삭제 이력, 자동 규칙 분리, 기존 4개와 원래 검토 기록 보존. [결과](../docs/r08-04-human-check.json)
- `node server/human-review-browser-check.js`: **HTTP·브라우저 9개 통과**. 관리자 인증/Origin, 기존 검수 주소·복귀 문맥, 실제 확인·부분 수정·통합 저장, 입력 중 단축키 차단·이탈 취소·다음 이동, 응답 유실/새로고침/중복 클릭, 형제 관계/자동 재공개 차단, 검색 실패 복구, 원문 변경·공개 필터, 방송 가져오기 후 제외 유지, 1440/390px 표시·교사 폴더 보존. 실행 환경의 `CURI_PLAYWRIGHT_MODULE`, 선택 `CURI_BROWSER_EXECUTABLE`로 Playwright/Chromium을 지정한다. [결과](../docs/r08-04-http-browser-check.json), [PC 화면](../docs/r08-04-human-desktop.png), [모바일 화면](../docs/r08-04-human-mobile.png)
- 기존 관리자 **HTTP/상태 12개·브라우저 6개** 통과. 자동 자산26·관리 상태13·교사 계약9 및 기존 검수/초안 실패/승인 저장/검색 준비/자연어 검색 회귀 통과. 과거 콘텐츠 전체 무효화 검사의 기대값은 변경된 해당 관계만 제외하도록 바꿨다. [기존 관리자 결과](../docs/r08-04-legacy-admin-check.json)
- 모든 결정 입력은 **합성 자료 또는 임시 복제본의 기능 시험**이다. 브라우저의 임베딩은 성공/실패 복구용 고정 시험 대역이므로 검색 모델 품질을 측정한 것이 아니다. 실제 자료에 새 사람 결정을 입력하지 않았다. 실제 승인4개·검토 이력과 JSON/방송/시맨틱/자동 DB의 SHA 보존, 유료 API 0회 확인.

## 수동 작업

필수 환경변수·새 계정·DB 이전 작업은 없다. 실제 관계를 공개 승인하려는 경우에만 운영자가 현재 원문과 공식 요구를 직접 검토하고, 판단 사유·필요한 수정·실제 확인 여부를 입력한다. 전량 검토나 고정 승인량은 이번 기능 완료의 전제가 아니다. 같은 JSON에 여러 서버/CLI를 동시에 쓰는 운영은 지원하지 않는다.

### 결과 확인

- [ ] 실행 중인 서버를 새 코드로 시작하고 `/admin.html`에 로그인한다. 자료 상세의 **원문·관계별 사람 판단 열기**에서 원문·인용 위치와 공식 요구가 나란히 보이는지 확인한다.
- [ ] 자동 후보 또는 기존 초안을 열어 연결/미확인 부분·자동 검사·이전 사람 이력·현재 버전을 확인한다. 사람이 실제 확인했다는 체크가 기본으로 꺼져 있고 단일 운영자를 실명 인증으로 표시하지 않는지 확인한다.
- [ ] 실제 검토할 관계가 있다면 승인 또는 수정을 선택하고 사유·확인을 입력해 **결정·해당 자산 함께 저장**한다. 별도 CuriBase 저장 없이 결정/자산과 검색 상태가 표시되고 다른 관계의 판단은 유지되는지 확인한다. 시험만 할 경우 실제 자료 대신 격리 검증을 사용한다.
- [ ] 입력 중 다른 자료로 이동해 이탈 경고를 취소하면 내용이 남는지, 입력칸에서 Alt+S/Alt+N이 저장·이동하지 않는지 확인한다. 저장 뒤 다음 자료로 이동할 때 목록 조건이 유지되는지 확인한다.
- [ ] `/review.html?contentCuriId=자료ID` 또는 원본 `resourceId` 주소가 같은 관리자 관계 작업공간으로 이어지고, 기존 검토 시각/결정과 승인 4개가 새 검토로 변환되지 않았는지 확인한다.
- [ ] 응답 미확인·검색 준비 실패를 만난 경우 안내에 따라 **같은 요청으로 저장 결과 재확인** 또는 **이 관계 검색 준비만 재시도**를 사용한다. 새 사람 결정이 중복되지 않고 저장과 검색의 상태가 구분되는지 확인한다. 실패를 재현하지 않은 경우 위 격리 시험 보고서로 동작을 확인한다.
