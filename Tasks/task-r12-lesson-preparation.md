# Task R12 - 실제 교사 수업 준비 중심 제품 개선

## 설명

실제 교사의 요청 → 자료 발견 → 내용/근거 확인 → 선택 → 수업 폴더 저장/재사용까지 성공하는 제품을 만든다. 2026-10-14 사용자 요청으로 기존 계획을 재정리했다. 개별 회차 복구·기능 검사 건수를 주된 제품 성과로 삼지 않고, 공통 실패 원인과 자료 선택 성공을 기준으로 수집·검색·UX를 개선한다. UX는 먼저 검토·수정 지시를 제시하고 이를 반영하는 별도 트랙으로 진행한다. 상태: **진행중**. 이번에 완료한 것은 계획·task 재정리이며 제품 구현과 교사 검증 착수를 뜻하지 않는다.

## 구현 항목

- [ ] R12-01에서 실제 요청·현재 제품 기준선·개발/새 평가 구분·실패 원인군을 고정한다.
- [ ] R12-02에서 요청 공백과 공통 수집 원인에 따라 공식 원천 자료를 보강하고 검색에 반영한다.
- [ ] R12-03에서 요청 해석/후보 누락/순위/근거의 공통 실패를 개선하고 데이터 변경 효과를 분리한다.
- [ ] R12-04에서 현재 UX 문제·근거·수정 지시·확인 기준을 먼저 정리해 제시한다.
- [ ] R12-05에서 제시한 UX 지시를 반영하고 실제 화면·기존 개인 기록·자료 선택 동선을 확인한다.
- [ ] R12-06에서 새 요청 품질·실제 교사 선택/재사용을 확인하고 남은 공백과 다음 원인군을 정한다.

기술적으로 수집과 검색 진단, UX 검토는 서로의 전체 완료를 기다리지 않고 준비할 수 있지만 제품 반영은 해당 선행 산출물과 현재 task 범위를 따른다. 실제 교사 요청 확보가 늦어지면 기존 사례로 개발 진단·공식 자료 대조·UX 검토를 계속하고, 실제 요청 기반 기준선/교사 효용 검증은 미완료로 남긴다. 기존 task의 사용자 확인 대기를 없애거나 새 구현의 모든 선행 조건으로 요구하지 않는다. 다음 착수는 R12-01이며 UX는 R12-04 정리본을 먼저 제시한 뒤 R12-05에서 반영한다. 기간은 작업량/접근 상황을 측정한 후 정하며, 교사 후속 재사용 관찰은 첫 사용 후1주를 목표로 한다.

## 제품 판단 지표와 1차 목표

아래 수치는 이번 계획의 **초기 목표**이며 실측 결과나 사용자 검증 완료가 아니다. R12-01에서 현재 성공률과 요청 난이도를 확인하고 구현 변경 전에 최종 평가 기준을 고정한다. 바꾼 경우 이유와 이전 목표를 보존하며 결과를 본 뒤 목표를 낮춰 성공으로 처리하지 않는다.

| 지표 | 정의·분모 | 1차 목표 |
| --- | --- | --- |
| 자료 선택 성공 | 실제 요청에서10분 내 요청에 맞는 자료≥1건, 선택 이유/활용 목적 설명, 공식 원문 또는 영상에서 내용 확인, 저장/재열기 완료 | 실제12회 중10회 이상, 사회/과학 각6회 중5회 이상 |
| 기준선 대비 개선 | 같은 난이도/교과 구간의 대응 요청에서 성공 수와 실패 포함 소요 시간 비교 | 12회 기준 성공≥3회 증가; 기준선이 이미10회 이상이면 성공 유지와 시간 중앙값≥30% 감소 |
| 새 요청 검색 품질 | 미노출12요청의 상위5 관련성, 적합·부분·부적합·원문 부족 각각의 비율 | 과목별 상위5 적합 비율 개선, 필수/제외 조건 위반0건; 소표본의 범용 무오류를 주장하지 않음 |
| 알려진 정답 발견 | 근거 있는 정답을 알고 있는 요청/자료만 분모로 상위20 발견 측정 | 기준선 대비 유지 또는 개선; 정답 미확보 범위는 별도 미측정 |
| 요청 공백 보강 | 개발 요청별 선택 근거가 있는 후보 수와 원문으로 판단할 수 있게 된 요구 | 과목별 우선 원인군≥1개에서 공백 해소 확인, 무관 자료 증가를 성공으로 합산하지 않음 |
| 접근·영상 확인 | 공식 링크 도착/자기 회차 일치/실제 재생/내용 확인/장면 시간 확인 | 각 단계 실측을 별도 집계; 재생 미확인을 사용 가능으로 확정하지 않음 |
| 반복 사용 | 후속 실제 요청으로 자발적으로 다시 탐색·선택한 교사 수 | 최소2명, 첫 사용 후1주 내 관찰 목표; 재방문 의향과 실제 재방문 구분 |
| 실제 수업 활용 | 선택한 자료가 실제 수업에 사용됐는지·활용 부분·추가 확인 | 가능한 참여자의 실제 기록 수집; 미수행은 미확인, 선택 성공과 별도 보고 |

소요 시간은 실패/포기10분을 포함한 전체 요청 중앙값과 성공 요청만의 시간을 함께 보고한다. 사람이 판단한 관련성 분모와 에이전트 대리 판단을 섞지 않는다. 원문만으로 선택한 자료와 영상까지 확인한 자료의 성공을 따로 공개한다. 대응 요청의 난이도 차이·학습 효과·참여자 편향을 기록하며 통계적 대표성을 주장하지 않는다. 의미 품질·교사 사용 목표가 미달하면 기능 검사가 통과해도 제품 효용 검증을 완료 처리하지 않는다.

원인군 우선순위는 개발 요청에서 영향받는 수·과목 균형·공식 근거 확보 가능성·작업량으로 결정한다. 평가 질문에 맞춰 수집할 주제를 골라 독립 평가에 유리하게 만들지 않는다. 수집량 자체의 고정 증가는 목표가 아니며 요청 공백이 남고 확보 가능성이 확인되면 다음 배치를 늘린다.

R12-01~06을 생성하고 기존 task의 후속 실행 책임을 연결했다. 제품 코드·저장소·색인·서버 변경, 공식 원천 수집, 실제 교사 평가와 UX 화면 검토/반영은 아직 수행하지 않았다. 계획 문서 재정리를 제품 개선 완료로 표시하지 않는다.

## R12-01·UX 검토 착수 결과 — 2026-10-14
