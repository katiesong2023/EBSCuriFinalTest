# Task R06 - 검증 자산 검색의 주제 오탐 수정

## 설명

`/index.html`에서 “우주 관련 수업을 하고 싶어 주제를 선정해줘”를 과학·초등 5~6학년군·오래된 방송순으로 검색하면 무관한 날씨 자료가 나오는 오류를 수정한다. 승인 여부와 현재 질의 적합성을 별도로 검사한다.

## 구현 항목

- [x] 최신 서버에서 사용자 질의·필터·정렬 그대로 재현
- [x] 임베딩 유사도만 높은 무관 자료를 주제 근거로 차단; 기존 승인 Gate 유지
- [x] 요청 문맥·학년·교과와 내용 주제를 분리하고 정상 검색·정렬·페이지 유지
- [x] 빈 결과에서는 검증 자료 범위를 설명하고 콘텐츠 탐색으로 연결
- [x] 같은 고정 자료에서 전후·새 표현·기존 회귀·실제 브라우저 확인

## 범위 밖

- 미확정 화면 통합·수업 설계 기능 구현

## 사전 전제

- [ ] 검증 자료가 없을 때 안내와 전체 콘텐츠 탐색 연결이 이해되는지 확인한다.

## 구현·검사 결과 — 2026-10-01

- 재현 전: 사용자 질의·초등 5~6학년군·과학·오래된 방송순에서 날씨 자료 1건, cosine 0.8504538431로 임계값 0.82 통과. [기준선](../docs/verified-topic-before.json).
- `verified-topic-filter.js`는 수업 요청 어미·학년·교과를 분리하고 기존 로컬 주제/AND/OR/제외 규칙을 현재 승인 관계의 제목·공개 텍스트·검수 내용·성취기준에 적용한다. 이 조건과 기존 벡터 임계값을 모두 통과해야 반환한다. 검증되지 않은 방송을 승인 결과에 섞지 않는다.
- `natural-search.js`의 승인 Gate·최신 저장소 재조회·정렬·페이지·캐시는 유지했다. 내용 주제가 200자를 넘으면 서버 오류 대신 질의 축소 안내를 반환한다. 직접 표현·동의어가 없는 관련 자료는 보수적으로 누락될 수 있으며 범용 의미 판정이 아니다.
- `index.js` 빈 결과는 승인 자료 범위를 설명하고 내용 주제를 유지한 전체 탐색 링크를 제공한다. 같은 우주 요청은 0건, 정상 날씨 검색은 1건이다.
- `node server/natural-search-check.js`의 기존 조건·정렬·페이지·캐시·동시성·승인 무효화·API·UI 검사 통과. `node server/verified-topic-check.js`의 고유사도 가상 벡터 계약 13건, 실제 로컬 임베딩 2질의 통과. [현재 결과](../docs/verified-topic-after.json).
- Chrome 실제 화면에서 동일 질의·필터·정렬의 0건 안내를 확인하고, 전체 탐색 링크가 우주 후보 151건으로 연결되는 것을 확인했다. 승인·수집 저장소는 변경하지 않았고 유료 API는 호출하지 않았다.

## 교사를 가정한 UX 크리틱 1회

실제 교사 연구가 아니라 “우주 수업 주제를 아직 정하지 못한 교사”의 흐름을 현재 화면에서 따라간 에이전트 점검이다. 이후 사용자가 교사·관리자 화면 분리를 확정했다. 구체적 큐레이션 기능·메뉴 구현은 R07/R08 후속 범위다.

| 실제 관찰 | 교사에게 생기는 부담 | 제안 |
| --- | --- | --- |
| 1번 긴 요청은 0건, 우주 핵심어는 151건·17페이지 | 자연스러운 요구를 검색어로 번역하고 자료를 전부 비교해야 함 | 모호한 주제를 2~3개 방향으로 좁히고 자료 근거가 있는 대표 후보부터 제시 |
| 우주 첫 화면 9개 중 8개가 지식채널e, 추천 이유는 원문 주제 언급 수준 | 순위가 수업에 가장 적합한 순위인지 판단하기 어려움 | 주제 적합성·근거 충실도·프로그램/관점 다양성을 함께 고려하고 선정 이유 표시 |
| 모음에 담은 뒤 다음 행동은 원문 열기·빼기·준비 메모 다운로드 | 모았지만 도입/탐구/정리 배치와 발문을 다시 만들어야 함 | 수업 준비안으로 이어지는 역할 배치·자료 교체·메모 기능 |
| 2번은 유사한 검색 화면이나 검색 가능한 승인 콘텐츠는 4개 | 앞 화면에서 있던 자료가 왜 사라지는지 이해하기 어려움 | 승인 상태는 탐색 필터/표시로, 두 번째 주 기능은 수업 준비안으로 발전 제안 |
| 3번 주 메뉴는 콘텐츠 ID 없는 검수 상세로 진입, NO_CONTENT·비활성 조작 표시 | 교사가 CuriMap의 선행 처리 순서를 알아야 함 | 관리 입구는 검수 대기 목록, 상세는 자료 선택 후 진입; 일반 교사 동선에서는 보조 기능 |
| CuriMap·CuriBase·검색 준비와 서로 다른 3/4개 메뉴 | 내부 시스템 구조를 배워야 수업 자료를 사용할 수 있음 | 교사 행동 중심 명칭과 일관된 메뉴, 운영 기능 별도 영역 |

권장 역할: 1번 자료 발견·짧은 후보 비교, 2번 내 수업 준비안, 관리자 별도 연계·품질 관리. 사용자 확정인 역할 분리는 [R07](task-r07-teacher-workspace.md)·[R08](task-r08-admin-workspace.md)로 분리했다. 모든 교사가 1→2→3을 의무적으로 거치는 흐름은 피한다. 3번은 검수 담당자 또는 필요 시 교사가 쓰는 보조 동선으로 제안한다.

우선순위: 무관 결과 차단(P0, 이번 수정) → 1번 대표 후보·중복 판본 정리(P1) → 모음에서 수업 준비안 연결(P1) → 검수 목록·내부 용어 정리(P2). 발문/활동은 수업 제안으로, 원문 내용·학년 적합성·영상 길이는 확인 상태로 구분한다. 추천 품질은 결과 개수보다 주제 선택·자료 선택·준비안 완료에 필요한 노력과 이유 설명 가능성으로 확인한다.

점검 중 담은 1개 자료는 다시 제거하여 내 자료 0 상태로 돌렸다. 승인/수정/제외 저장과 AI 연계 버튼은 실행하지 않았다.
