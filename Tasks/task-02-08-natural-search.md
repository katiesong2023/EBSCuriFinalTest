## 실제 산출물

- `server/search-conditions.js`: 1~300자 질의, 학년군·교과·정렬·페이지를 검증한다. 숫자 학년·학년 범위·저/중/고학년과 교과 이름을 규칙으로 해석한다. 학년만 언급하면 초등 학년군으로 해석하며, 단일 학년도 해당 공식 학년군으로 검색한다. 직접 선택한 필터가 우선이고 질의 조건과 충돌하면 어떤 조건을 우선했는지 안내한다. 여러 학년군·교과 또는 초등 범위 밖 조건이 있으면 해당 필터 선택이나 질의 수정을 요청한다. 자연어 전반을 이해하는 생성 모델은 사용하지 않으므로 부정·복합 표현은 필터로 명확히 지정한다.
- `server/natural-search.js`: 최신 검수·원문·버전 Gate를 통과한 검증 자산과 일치하는 검색 투영만 사용한다. 공식 성취기준의 학년군·교과를 먼저 적용하고, 기존 로컬 모델의 `query:` 질의 벡터와 관계별 문서 벡터의 코사인 유사도를 계산한다. 최소 기준을 통과한 관계만 콘텐츠 ID로 묶고, 그중 최고 점수로 콘텐츠를 정렬한다. 상위 N개 제한 없이 기준 통과 콘텐츠 전체를 집계한 뒤 10개 단위로 반환한다.
- `CURI_SEARCH_MIN_RELEVANCE`를 `.env.example`에 추가했다. 기본값은 `0.82`이며 0~1의 값만 허용한다. 초기 구현값으로 검색 품질이 검증되거나 동결된 값은 아니며, 후속 DEV 조정에서 확정한다. 값을 바꾸면 서버를 재시작한다. 날짜 정렬에도 같은 최소 기준이 적용된다.
- 관련도순은 점수 내림차순·동점 방송일 최신순·최종 콘텐츠 ID순이다. 최신/오래된 방송순은 기준을 통과한 결과 안에서 날짜로 정렬하고 같은 날짜에는 관련도와 ID를 사용한다. `content.metadata.broadcastDate`의 유효한 `YYYY-MM-DD`만 방송일로 사용하며 미상·잘못된 날짜는 날짜 정렬의 뒤에 둔다. 기존 실제 자산에는 방송일이 없어 `방송일 미확인`으로 표시한다. 수집일을 방송일로 대체하지 않는다.
- 질의 벡터는 프로세스 메모리에서 최근 32개까지 재사용하며, 결과와 검증 자산은 캐시하지 않는다. 임베딩을 기다린 뒤에도 저장소를 다시 읽어 중간에 수정·제외된 관계를 제거한다. 같은 질의의 동시 계산은 공유하고 다른 새 질의 계산은 재시도 안내로 제한한다. 서버 재시작 후 첫 질의는 다시 계산한다. 검색 호출은 CuriMap 실행·전체 재색인·저장소 쓰기·유료 생성 API를 호출하지 않는다.
- `server/server.js`: `GET/HEAD /api/curi/search?query=...&grade=...&subject=...&sort=...&page=...`를 추가했다. 결과·총수·페이지·적용 조건·안내·상태·기준값·질의 계산 재사용 여부를 반환하며, 응답은 `no-store`다. 기본 필터 값 `all`은 질의에서 해석하고 조건이 없으면 전체를 뜻한다. 현재 화면에서 명시 선택할 수 있는 교과는 사회·과학이고, 학년군은 초등 1~2·3~4·5~6이다. 현재 저장 Gate의 검증 가능 범위는 초등 5~6학년군 사회이며, 다른 조건은 자산이 없으면 빈 결과가 된다.
- `public/index.html`, `public/index.js`, `public/index.css`: 예시 데이터·상태 미리보기를 실제 검색으로 교체했다. `적용 조건`, 충돌·모호함 안내, 로딩·성공·빈 결과·실패, 정렬과 페이지를 표시한다. 입력 조건을 변경하면 이전 결과를 지우며 늦게 도착한 이전 응답을 무시한다. 카드에는 저장된 검증 관계의 성취기준·추천근거·수업 활용·핵심개념과 해당 콘텐츠의 EBS 원문 URL을 표시한다. 텍스트는 HTML로 삽입하지 않고, 원문 링크는 EBS 주소만 허용한다. 검색 실패는 같은 `검색` 버튼으로 재시도한다.
- `server/natural-search-check.js`, `npm run data:search:check`: 실제 저장소를 변경하지 않는 메모리 자료로 조건 해석·검증 Gate·검색·API·화면 동작을 확인한다. 기존 검수·연계 실패 검증의 의존성 허용 목록도 새 검색 모듈에 맞춰 갱신했다.

## 수동 작업

### 수행한 검증

- `npm run data:search:check`: 단일/범위 학년·교과 해석, 명시 조건 우선·충돌 안내, 여러 조건과 지원 밖 학년 확인 요청, 잘못된 입력·설정 거절을 통과했다. 모의 검증 콘텐츠 24건 중 기준 통과 23건이 관계 중복 없이 10/10/3건으로 나뉘며, 관련도 우선·날짜 동점 보조·최신/오래된순·날짜 미상 후순위·기준 미달 제외를 확인했다.
- 질의 캐시 재사용 중에도 검수 제외·이전 버전 제거가 적용되고, 계산 대기 중 제외된 자료가 노출되지 않는지 확인했다. 동시 질의 공유·다른 새 계산 제한·실패 후 재시도와 저장 자료 불변을 확인했다. GET/HEAD·잘못된 요청·POST 거절·HTTP 캐시 비활성화·CuriMap 미호출을 확인했다.
- 실제 화면 스크립트의 DOM 모의 검증으로 로딩·버튼 상태·카드·텍스트 안전 처리·페이지 요청·입력 변경 중 이전 응답 무시·서버 404 재시작 안내·오류 재시도·빈 결과·조건 확인 안내를 통과했다. 실제 브라우저의 시각적 확인은 수행하지 않았다.
- 실제 로컬 모델과 기존 저장소를 읽기 전용으로 확인했다. `초등 5학년 사회 동고서저 지형과 산맥`은 `동고서저 지형, 산맥` 1건, 유사도 약 0.922를 반환했다. 같은 질의의 정렬 변경은 질의 벡터를 재사용했다. 명시 교과 `과학`은 0건, `사회 과학 수업 자료`는 조건 확인 요청, `프랑스 디저트 마카롱 조리법`은 0건이었다. 외부 API 호출은 0회이며 저장 파일의 전후 SHA-256이 같았다. 이 소수 사례를 검색 품질 평가나 전문가 관련도 검증으로 해석하지 않는다.
- `npm run data:search-index:check`, `node server/verified-save-check.js`, `node server/review-actions-check.js`, `npm run data:candidates:check`, `npm run data:mapping:check`, `npm run data:mapping:failures:check`를 통과했다. 변경 JavaScript의 구문 점검과 `git diff --check`를 확인했다.

### 결과 확인

- [x] 기존 서버를 `Ctrl+C`로 종료한 뒤 프로젝트 루트에서 `npm start`로 다시 실행하고 [교사 검색 화면](http://127.0.0.1:3000/)을 새로고침한다. 예시 카드와 상태 미리보기 버튼이 사라지고 `적용 조건` 영역과 빈 검색 입력창이 보이는지 확인한다.
- [x] 학년군·교과를 기본값 `질의에서 해석 · 없으면 전체`로 두고 `초등 5학년 사회 동고서저 지형과 산맥`을 검색한다. 적용 조건이 `초등 5~6학년군`·`사회`로 표시되고, `동고서저 지형, 산맥` 카드에 `6사01-01` 원문·저장된 검수 근거·수업 활용·EBS 원문 링크·`방송일 미확인`이 보이는지 확인한다. 현재 실제 준비 자산 기준은 1건이며 이후 자산이 늘면 총수는 달라질 수 있다.
- [x] 같은 질의에서 교과를 `과학`으로 선택한 뒤 `검색`을 누른다. 과학 선택을 우선한다는 충돌 안내와 빈 결과가 보이는지 확인한다. 이후 교과를 기본값으로 되돌리고 `사회 과학 수업 자료`를 검색해 교과 선택 안내가 표시되는지 확인한다. 교과를 `사회`로 정해 다시 검색할 수 있어야 한다.
- [x] 필터를 기본값으로 돌리고 `프랑스 디저트 마카롱 조리법`을 검색한다. 현재 실제 자산에서는 0건과 빈 결과 안내가 나오고 예시 카드·페이지 버튼이 없어야 한다. 다시 지형·산맥 질의를 검색해 정상 결과로 돌아오는지 확인한다.
