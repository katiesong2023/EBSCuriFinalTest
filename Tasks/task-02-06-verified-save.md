## 실제 산출물

- `server/data-quality.js`: 후보 조회·검수와 공유하는 공식 기준 적격성·콘텐츠 버전 계산과 최종 저장 Gate를 구현했다. 활성 콘텐츠, EBS 출처 URL·원본 ID·지문, 입력과 일치하는 공개 원문(20~1200자·SHA-256), 클립·회차·강의 단위, 최신 사람 승인·수정 기록, 공식 원문·버전, 전체 연계 관계의 검수 ID 일치를 확인한다. 텍스트 길이는 기존 초안 생성의 최소 입력 기준이며 의미 정확도를 보증하지 않는다.
- `server/verified-save.js`: 현재 저장소의 검수 결과로만 검증 자산을 만든다. 요청 본문에서 승인·관계 내용을 받지 않으며, 콘텐츠·최신 실행·검수 ID·콘텐츠 버전이 다르면 거절한다. 한 콘텐츠의 선택 관계 전체를 함께 저장하고, 반복 저장은 기존 ID·버전·시각을 반환한다.
- `server/server.js`: `GET/HEAD /api/curibase/verified?contentCuriId=...`로 Gate 사유·저장 관계·버전·시각을 조회하고 `POST /api/curibase/verified`로 저장한다. 검수·AI 연계·가져오기와 같은 서버 쓰기 잠금을 사용한다.
- `server/data-store.js`: 저장 모델 `1.3`에 `verifiedAssetHistory`를 추가했다. 읽기·쓰기 경계에서 Gate를 적용하고, 임시 파일 작성 후 교체하는 기존 저장 방식으로 전체 변경을 확정한다. 쓰기·교체 실패 시 기존 파일을 보존하고 임시 파일을 정리한다.
- `server/data/curi-store.json`: 사용자가 저장하면 `verifiedAssets`에 관계별 원본 ID·출처·공개 텍스트·공식 기준·콘텐츠 버전·사람 검수 스냅샷·저장 버전이 보존된다. 해당 관계는 `VERIFIED`, 콘텐츠의 `isCuriBaseVerified`는 `true`가 된다. 콘텐츠 원본의 분류와 AI 초안·검수 이력은 유지한다. 에이전트는 실제 저장소에 검증 자산이나 사람 기록을 추가하지 않았다.
- 검수 결정을 다시 저장하거나 최신 연계 실행·콘텐츠·공식 기준이 바뀌어 Gate 또는 저장 당시 지문과 맞지 않으면 이전 자산 전체를 활성 영역에서 제거하고 `verifiedAssetHistory`에 무효화 사유와 함께 보존한다. 재저장 시 다음 버전으로 만든다. 연결된 검색 자료가 있다면 무효화하지만 새 검색 인덱스는 생성하지 않는다.
- 읽기는 파일을 변경하지 않는다. 읽기에서 발견한 무효 자산은 응답에서 제외하고, 다음 정상 저장 때 무효화 이력을 파일에 반영한다. 보장 범위는 현재 로컬 서버의 쓰기 잠금과 JSON 파일 교체이며, 여러 서버·CLI 프로세스가 동시에 같은 파일을 수정하는 운영 환경은 지원하지 않는다.
- `public/review.html`, `public/review.js`: `CuriBase 검증 자산 저장`, `CuriBase에 저장`, `저장 상태 재확인`, 저장 관계·교육과정 버전·저장 버전·시각·무효화 건수 표시를 추가했다. 새 검수 판단을 선택한 동안은 먼저 검수 결정을 저장해야 한다. 저장 중 중복 요청과 검수 저장을 차단하며, 충돌·실패 시 새로고침 안내를 표시한다.
- `server/verified-save-check.js`: 임시 저장소와 모의 화면/API에서 Gate 거절, 여러 관계의 원자적 저장, 반복 저장, 오래된 탭, 공용 쓰기 잠금, 검수 수정·제외, 콘텐츠·공식 원문 변경, 재로딩, 부분 쓰기·파일 교체 실패를 확인한다. 실행 명령은 `node server/verified-save-check.js`다.

## 수동 작업

- 기존 사람 승인·수정 결과를 그대로 저장할 때 추가 입력·계정·API 키는 필요하지 않다. CuriBase 저장은 LLM API를 호출하지 않는다.
- 기존 판단을 바꿀 필요가 있다면 사람이 EBS 원문과 공식 근거를 다시 검토해 판단·수정 내용·사유를 정한다. 검증용으로 허위 승인·제외 기록을 만들지 않는다.
