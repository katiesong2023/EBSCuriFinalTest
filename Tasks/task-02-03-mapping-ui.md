# Task 02-03 - 연계 결과와 검수 화면 연결

> 현재 정본: [PLANS](../docs/PLANS.md) · 대응: **R00~R03 기반 / 완료 이력·기반 보존**. 기존 승인·증분·화면·출처 자산을 재사용하며 새 탐색의 완료로 확대 해석하지 않는다. 과거 구현·사람 확인 기록은 보존한다.

실제 연계 결과가 검수 화면까지 전달되도록 연결한다.

## 구현 항목

- [x] `public/curimap.html`의 `검수 화면에서 연계 결과 확인` 링크가 현재 선택 콘텐츠의 `contentCuriId`를 검수 화면으로 전달한다. 검수 화면은 저장된 최근 실행 결과 또는 미실행 안내를 표시하며, CuriMap은 연계 시작·진행·성공·실패를 기존 상태 영역에 구분해 표시한다.
- [x] `public/review.html`은 `GET /api/curimap/contents`와 `GET /api/curimap/draft?contentCuriId=...`의 최근 실행 결과를 이용해 실제 콘텐츠 원문·선택된 공식 성취기준·AI 초안을 표시한다. DRAFT·HELD·FAILED·실행 이력 없음 상태를 구분하며, DRAFT가 아닐 때는 검수 선택을 비활성화한다.
- [x] CuriMap의 후보·연계 실행 응답은 요청한 `contentCuriId`가 현재 선택과 같을 때만 화면에 반영하고, 콘텐츠를 바꾸면 이전 결과와 검수 링크를 비운다. 따라서 이전 콘텐츠 결과가 새 콘텐츠에 붙지 않는다.
- [x] 검수 화면 URL은 `contentCuriId`를 유지한다. 새로고침·뒤로가기는 저장된 최근 실행 결과를 다시 읽고, 실행 중 이탈·실행 이력 없음·보류·실패일 때는 CuriMap에서 다시 실행해야 함을 안내한다.

- [x] 사람 수행·검토가 필요한 브라우저 결과를 AI가 수행한 것으로 기록하지 않았다.

### 결과 확인

- [x] 터미널에서 `npm start`를 실행하고 `http://127.0.0.ㅞ1:3000/curimap.html`을 연다.
- [x] 콘텐츠를 하나 선택했을 때 `검수 화면에서 연계 결과 확인` 링크가 바로 활성화되는지 확인한다. 예를 들어 최근 DRAFT가 있는 `우리나라의 위치 알아보기 · 초등 5학년`을 선택한다.
- [x] 링크를 열었을 때 검수 화면에 같은 콘텐츠 제목·공개 EBS 원문·선택된 공식 성취기준·핵심개념·연계근거·수업 활용·confidence가 표시되고, `REVIEW_REQUIRED`, `CuriBase 저장 전`, `검색 미반영`이 보이는지 확인한다.
- [ ] 검수 화면에서 `승인`, `수정`, `제외` 중 하나를 선택하고 `검수 선택 미리보기`를 눌렀을 때 화면 안내만 바뀌고 실제 저장이나 검색 반영은 일어나지 않는지 확인한다.
- [ ] CuriMap으로 돌아가 다른 콘텐츠를 선택한다. 새 콘텐츠의 실행 이력이 없으면 이전 초안·검수 링크가 남지 않고, 검수 화면에서는 `NOT_RUN` 안내와 비활성화된 검수 선택이 보이는지 확인한다.
- [ ] DRAFT가 아닌 실행 이력(보류 또는 실패)이 있을 때 검수 화면에 해당 사유와 CuriMap 재실행 안내가 보이고, 검수 선택이 비활성화되는지 확인한다.
- [ ] DRAFT 검수 화면을 새로고침하고 브라우저 뒤로가기로 CuriMap에 돌아온 뒤 다시 링크를 열었을 때, 같은 콘텐츠의 저장된 최근 실행 결과가 다시 보이는지 확인한다.
- [ ] 확인 후 터미널에서 `Ctrl+C`를 눌러 서버를 종료하고, 보인 문제나 확인 결과를 응답으로 남긴다.
