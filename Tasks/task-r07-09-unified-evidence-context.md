# Task R07-09 - 통합 화면의 선택 근거와 수업 문맥 연결

## 설명

통합 검색에서도 선택 기준에 대한 근거와 남은 요구를 확인하고, 자료를 담은 이유를 폴더 활용까지 이어간다. 교사에게 필요한 자료 판단 정보와 관리자 운영 지표를 정리한다. R08-07과 R07-05에서 구현한 근거·개인 문맥을 재사용하는 연결 단계다. 상태: **진행중**. 2026-10-11 통합 근거·수업 문맥 연결 구현·에이전트 검증 완료, 사용자 결과 확인 대기.

## 권장 개발 모델

- **GPT-6.1 Sol · Medium** (`gpt-6.1-sol`): 선택 기준·현재 확인·개인 기록의 관계를 유지하면서 통합 화면에 연결한다.
- 확정된 명칭 대조와 단순 표시 변경은 GPT-6 Luna · High가 적합하다. 기존 저장 기능·평가·관리자 승인 경로를 다시 구현하지 않는다.
- 개발 모델이며 공통 사용 원칙은 [PLANS](../docs/PLANS.md#검색-화면-통합-후속-계획--2026-10-11)을 따른다.

## 구현 항목

- [x] 일반 검색 이유와 선택 기준의 연결 근거를 구분해 제공한다. 기준을 선택한 경우 그 기준의 요구·공개 원문에서 확인한 설명·정확한 인용·남은 요구를 확인할 수 있게 한다.
- [x] 공개 소개문·공식 보조문서·영상 장면의 확인 범위를 구분한다. 소개문 확인을 영상 전체 검토처럼 표현하지 않고, 일부 설명을 기준 전체 충족이나 학생의 성취로 표시하지 않는다.
- [x] 미지원·원문 부족·개념만 확인·부분 근거·보류·상충을 자료 선택에 필요한 수준으로 제공한다. 다른 기준의 이력은 선택 기준의 확인과 분리한다.
- [x] 자료 담기부터 내 자료·수업 폴더·재열기·내보내기까지 기존 선택 기준·이번 수업 목표·활용 부분·추가 내용과 복수 선택 이유를 보존한다. 검색 조건을 해제하거나 다른 기준으로 바꾸어도 저장된 이유를 소급 변경하지 않는다.
- [x] 공식 기준의 원문·학년군과 교사의 개인 목표·대상 학년·난이도·선수개념·장면 확인을 구분하고, 저장 당시 문맥과 현재 관계 상태의 기존 구분을 유지한다.
- [x] 비동기 조회·원문 변경·승인 취소·저장 또는 내보내기 실패 때 개인 입력과 기존 저장 자료를 보존한다. 통합 과정에서 새로운 저장소·계정 동기화를 도입하지 않는다.
- [x] 확보·규칙 지원·전체 승인·공백 집계는 관리자 작업공간에서 확인하게 하고 교사 검색 화면의 운영 지표는 정리한다. 개별 자료의 실제 확인 상태·원문 범위·출처는 유지하고 관리자 권한을 우회하는 이동이나 쓰기를 추가하지 않는다.

## 구현 결과와 검증

- `public/teacher-evidence.js`는 통합 카드의 선택 기준 요구·제한 자동 비교/원문 충실도/현재 상태·제공 내용·정확한 소개문 인용/출처·남은 요구를 표시한다. 후보 발견 인용과 요구 근거를 구분하며 공식 보조 원문은 후보 발견 전용, 영상 장면·전체 기준 충족·학생 수행은 별도 확인으로 유지한다. 다른 기준의 승인/자동 이력도 별도 영역에 남긴다.
- `public/shelf-context.js`는 기존 `lesson-context.js`의 선택 이유 편집·저장 기능을 ‘내 자료’에 연결한다. 활용 기준·목표·활용 부분·추가 내용·난이도/선수개념/장면의 개인 확인·사용/제외 이유를 입력하고 복수 이유를 추가할 수 있다. `discover.js`에서 선택 당시 문맥을 캡처하고 기존 수업 폴더로 담기·재열기·Markdown 내보내기를 유지한다.
- 선택 문맥의 `courseLabel/officialGradeBand`는 공식 기준 과정/학년군이며 `targetGrade/targetNeedsClarification`은 선택 당시 교사 대상이다. 같은 기준을 다른 대상으로 담으면 별도 이유로 보존한다. 기준을 개인 편집해도 최초 `snapshot`과 다른 이유는 소급 변경하지 않는다. 이전 문맥은 기존 값과 빈/미기록 기본값으로 읽는다.
- 내 자료의 비동기 확인은 현재 관계 표시만 갱신하고 입력 영역·커서를 다시 만들지 않는다. 저장 실패 때 입력을 메모리에 유지하고 ‘내 자료 다시 저장’과 이탈 경고를 제공한다. 내보내기는 시작 시점 사본으로 생성하며 도중의 추가/삭제·개인 편집을 현재 모음에 보존한다. 폴더별 입력은 기존 독립 저장 방식 그대로다.
- 재조회는 기존 자료 읽기 API로 현재 원문·승인/자동 관계를 대조한다. 저장 때의 비교 표시는 현재 승인으로 재사용하지 않는다. 요구별 자동 비교는 통합 검색에서 표시하며 개인 자료 재조회에서 새 요구 비교가 제공되지 않으면 현재 관계는 미확인으로 안내하고 선택 당시 표시와 개인 기록을 보존한다. 새 자동/사람 승인·영상 판정을 만들지 않았다.
- 교사 검색의 자료 규모·프로그램 수·등록 개념 집계를 제거하고 기존 `/admin-curriculum.html`의 확보/규칙 지원/공백/현재 승인 집계로 안내한다. 결과 건수·필터 건수·각 자료의 원문 품질/출처/실제 관계 상태는 유지한다. 관리자 세션·쓰기 API는 변경하지 않았다.
- [통합 문맥 검사](../docs/r07-09-context-check.json): 격리 복제 서버·합성 방송의 근거/인용 위치·확인7종/보조 원문·대상별 복수 이유·편집/폴더/재열기·지연/실패·내보내기/권한/390px8개 검사 통과. 실제4저장소 SHA 동일·유료API0.
- [기존 개인 문맥 회귀](../docs/r07-09-regression-browser-check.json)12개와 [선택/내보내기 리뷰 회귀](../docs/r07-09-regression-review-check.json)3개 통과. R07-05의 과거 화면 대기/카드 선택 구간만 실행 시 통합 화면 기준으로 바꾸고 기존 검증 파일·역사 보고서는 보존했다. `server/standard-evidence-check.js`의 선택 근거 계약7개도 통과했다.
- [모바일 내 자료](../docs/r07-09-shelf-mobile.png)와 [기존 폴더 모바일](../docs/r07-09-regression-lesson-mobile.png)에서 개인 문맥 편집 표시를 확인했다. 실제 교사 의미 평가·원문 보강/새 승인·사용자 서버 재시작은 수행하지 않았다.

- [ ] 최신 코드로 서버를 실행하고 `http://127.0.0.1:3000/`에서 질문 ‘지구 자전’과 기준 `6과12-02`를 선택한다. 카드의 교육과정 근거를 열어 요구·제공 내용·소개문 인용/출처·남은 요구가 보이며 일반 검색 이유와 구분되는지 확인한다.
- [ ] 소개문/공식 보조 원문의 후보 발견과 실제 영상·학생 수행의 미확인이 구분되는지 확인한다. 미지원 기준에서는 이를 자료의 부적합이나 사람 승인으로 표시하지 않는지 확인한다.
- [ ] 자료를 담고 ‘내 자료’의 ‘선택 이유’를 열어 이번 수업 목표·활용 부분·추가 내용을 작성한다. 개인 난이도/선수개념/장면 확인을 입력하고 ‘이 자료의 선택 이유 추가’로 다른 활용 기준·목표를 기록한다.
- [ ] 검색 기준·수업 대상을 바꾸거나 해제한 뒤 ‘내 자료’를 다시 열고 새로고침한다. 최초 선택 표시·공식 학년군·선택 당시 수업 대상·복수 이유/개인 입력이 유지되는지 확인한다.

- [ ] 내 자료와 수업 폴더의 목록을 내려받아 선택 당시/현재 상태·각 기준 원문·목표/활용/추가 내용·개인 확인이 구분되는지 확인한다. 조회 실패 때 저장 당시 확인을 현재 승인처럼 표시하지 않는지 확인한다.
- [ ] 교사 화면에서 운영 규모 집계 대신 자료별 확인 정보가 보이고, 관리자 교육과정 작업공간은 로그인 후 기존 확보·규칙 지원·공백/관계 집계를 제공하는지 확인한다.
- [ ] 휴대전화 폭에서 인용과 선택 이유 입력칸을 읽고 조작할 수 있는지 확인한다. 저장 실패가 생기면 표시 문구와 재시도 결과를 기록한다.
