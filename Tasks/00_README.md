- 개인 참가. 사용자 계획은 2026-09-16 아침 신청이며 신청 완료로 기록하지 않는다.

## 기획 검토와 범위 선택

기획의 강점은 공식 교육과정 후보 제한, 사람 검수, 검증 자산 누적, 검색 재사용과 실측 평가의 연결이다. 검색 화면을 넘어 콘텐츠 연계 담당자의 업무 흐름을 보여주어야 Track 1 적용 가능성을 설명할 수 있다.

먼저 해결할 내용은 다음과 같다.

- Raw Catalog 약 600건(현재 604건)은 동일 품질의 학습/연계 데이터가 아니다. 후보 풀 300~400건도 자동으로 검증 자료가 되지 않는다.
- 준비 Seed 75건 중 상세 synopsis 보유는 PD로그 35건이며, 클립 40건은 Silver와 단원 정보의 충분성·2022 정합성을 재검토한다.
- 사회 27건은 사람 승인 완료, 과학 51건은 자동 추출·사람 검토 권장 상태다. 과학 공식 원문 QA를 다음으로 완료한다.
- Working Set 200~250 목표와 실제 적격 건수를 구분한다. 소개문이 부족한 후보를 숫자만 채우기 위해 승인하지 않는다.
- 초기 CuriBase는 사람 승인·수정이 끝난 100~150건을 목표로 하며, 이후 여유가 확인될 때 200건 이상으로 확장한다.
- CuriBase는 사람 승인·수정 자산만 검색에 사용한다. 이 영역에서 승인 boost는 모두 같은 값이므로 효과가 없으면 추가하지 않는다.
- 기획의 신청 문안 Appendix는 옛 제목이 남아 있으므로 현행 기획 01·메시지 07의 공식 과제명을 우선한다.
- AGENTS.md는 Curi 주제와 CuriMap → 사람 검수 → CuriBase → Curi 흐름에 맞게 정리되어 있다. Task 00-01에서 대조를 마쳤으며 AGENTS.md 수정은 필요하지 않다.

필수 P0: 사회·과학 콘텐츠 입력, 만점왕 사회·과학 공개 강좌 인벤토리, 신규/변경 증분 가져오기, 공식 후보 연계·근거·사람 검수·저장·자연어 검색·최소 연관도 기준 통과 결과의 순위·페이지 제공·EBS 원문 링크·공식근거·기능검증·안정화·제출이다. 만점왕은 교육과정형 검색 후보이자 알려진 항목·조건 검색의 공식 기준 자산이며, 일반 방송·아카이브는 CuriMap 입력·검수 흐름 검증 대상으로 사용한다. 국어·수학, 접근조건 배지, 프로그램 필터, 공개 교재 단원 Bridge는 후속 또는 선택 확장이다. 영상 분석·결제·회원/SSO·퀴즈/교안 생성·운영 TCO 기능은 제외한다.

## 한 task씩 진행하는 방법

1. PLANS에서 선행 task의 사용자 결과 확인이 끝난 다음 task를 고른다.
2. task에 기입된 추천 모델·추론 수준을 선택하고 해당 문서의 시작 요청을 사용한다.
3. 에이전트가 구현한 뒤 기록하는 실제 결과 확인 절차로 동작·산출물을 확인한다.
4. 오류가 있으면 현재 화면/동작·오류 문구·기대 결과만 전달해 같은 task에서 수정한다.
5. 사용자 결과 확인 전에는 완료로 표시하거나 다음 단계 구현을 시작하지 않는다.

구현 전 task는 결과(What)를 고정한다. 코드 폴더·프레임워크·DB·내부 함수와 실제 버튼명·실행 경로는 미리 확정하지 않았다. 수동 작업·결과 확인 구역은 현재 비워 두며 실제 구현 또는 자료 준비 후 구체화한다. 작업 승인은 기존 WORKFLOW를 따르고, 새로운 기술·폴더 선택은 해당 task에서 이유와 범위를 제안한다.

준비 task가 문서·데이터를 다루어도 사람 QA와 원자료 수집이 산출물이다. 사람 판단이 필요한 교육과정 의미 정답은 모델 성능을 높여 대체하지 않으며, 제작자가 교육과정 전문가가 아니면 의미 정확도·교사 유용성으로 주장하지 않는다. 현재 P0 평가는 공식근거·기능검증 방식이며 자세한 범위는 `p0_evaluation_design.md`를 따른다.

| --- | --- | --- |
| GPT-5.6 Luna | low | 정적 화면, 필드 검사, 기록 양식, 반복 검수 기록, 촬영 안내·ZIP |

토큰을 절약하는 진행 제안:

- 새 task에서는 AGENTS의 세션 읽기 규칙을 지키되 기획 패키지 전체를 매번 다시 붙이지 않고 task의 관련 문서·변경 파일만 추가로 읽는다.
- 예시 데이터와 오류 재현 자료는 필요한 몇 건으로 제한하고 무관한 로그·대용량 CSV 전체를 대화에 붙이지 않는다.
- 작은 task가 완료되면 기록된 task·PLANS를 다음 작업의 인계 자료로 사용한다. 모델을 올릴 때도 전체 구현을 다시 요청하지 않고 unresolved 문제를 넘긴다.
- 정적 화면에서 실제 AI를 반복 호출하지 않는다. 표시 예시는 예시로 구분하고 실제 구동 검증에는 실제 호출을 사용한다.
- DEV에서만 비교·튜닝하고 최종 Test 반복 실행으로 품질을 조정하지 않는다.
- 모양만 반복 검사하는 자동 테스트는 늘리지 않는다. 후보 밖 ID, 검수 전 저장, 제외 관계 검색, 중복 저장 등 실패 비용이 큰 경계는 해당 task에서 검증한다.

## 개발 비용과 서비스 API 비용 구분

개발 모델은 코드를 만드는 도구다. CuriMap이 서비스 실행 중 호출하는 API 모델은 별도 설정·과금이다. 개발에 Sol을 써도 서비스 매핑을 항상 Sol로 호출해야 하는 것은 아니다. 서비스 매핑은 첫 연결에서 Terra를 시작 후보로 사용하고, Task 03-01에서 DEV의 Luna/Terra 품질·검수 시간·호출비를 비교해 최저비용 적격 모델을 선택한다. 서비스 품질 판단은 아직 검증되지 않았다.

검색은 저장된 검증 메타데이터·의미 인덱스를 재사용하고 매핑을 반복 호출하지 않는다. 검색 조건 해석은 규칙 우선, 규칙만으로 어려운 경우 저비용 모델을 DEV에서 검증해 사용한다. 임베딩은 별도 모델·별도 사용량이며 API 선택 시 공식 가격·접근 여부를 재확인한다.

## 데이터 근거와 사람 작업의 범위

현재 평가는 사회 27건·과학 51건의 사람 승인 공식 원문 데이터, 만점왕 8강좌·382강의 EBS 공식 인벤토리, Working Set의 공개 출처를 사용한다. CuriMap은 공식 ID 제한·근거 표시·검수 상태·실행 이력을, 검색은 알려진 항목·학년·교과 조건·원문 링크를 확인한다. 이 기능검증 자료는 개발·회귀 확인에 사용할 수 있지만 독립 성능 수치로 표현하지 않는다.

초기 CuriBase 100~150건은 사람 승인·수정 자산만 포함한다. 외부 교육과정 전문가 또는 교사 표본이 확보되면 실제 역할·표본·승인/수정/제외 기록을 별도 보조 증거로 추가할 수 있다. 확보하지 못하면 의미 정확도·교사 유용성·실제 EBS 업무 절감 효과를 주장하지 않는다.

초기 CuriBase 100~150건은 처리 건수가 아니라 사람 승인·수정되어 남은 콘텐츠 수다. 제외가 있으면 별도 적격 후보를 추가로 검수하고, 시간이 부족하면 실제 건수와 범위 조정을 보고한다. 반복 검수 task는 25건씩 처리하되 필요하면 같은 task에서 5~10건 회차로 나눌 수 있다.

사람이 직접 해야 할 주요 일은 사회·과학 공식 원문 QA, 초기 CuriBase 100~150건의 승인·수정·제외 검수, 기능 동작·원문 링크·운영 이력 확인과 실제 녹화다. 참여 교사/현업 전문가 확보 여부는 아직 미확정이며, 확보하지 못하면 교사·현업 검증을 했다고 표현하지 않는다.
