## 실제 산출물

- `public/review.html`, `public/review.js`, `public/review.css`: `검수 결정 저장`, 공식 성취기준 체크 목록, 수정 연계근거·수업 활용, 수정·제외 사유, 사람 검토 확인, `저장된 사람 검수 기록` 표시를 연결했다.
- `server/review-actions.js`: `HUMAN_APPROVED`·`HUMAN_EDITED`·`EXCLUDED` 결정과 서버 시각·고정 역할 `LOCAL_HUMAN_REVIEWER`를 기록한다. 다중 사용자 계정이나 신원 인증을 뜻하지 않는다.
- `server/server.js`: `GET /api/curimap/review-options?contentCuriId=...`와 `POST /api/curimap/review`를 추가했다. 기존 데이터 쓰기 잠금을 공유한다.
- `server/candidate-retrieval.js`: 기존 공식 기준 적격성 판별을 검수에도 재사용한다. 현재 활성·사람 QA 승인 사회 5~6학년군 공식 목록에서만 승인·수정할 수 있다.
- `server/data/curi-store.json`: 실제 사용자가 저장하면 해당 `mappingRuns[].reviewHistory`에 결정별 결과·사유·역할·시각·콘텐츠 버전을 누적하고, 해당 실행의 `contentCurriculumMaps`에 최신 검수 상태와 기록 ID를 연결한다. 이번 에이전트 검증은 모의 저장소에서만 수행해 실제 사람 검수 기록을 만들지 않았다.
- `server/curimap-mapping.js`: 최근 실행 조회에 검수 이력을 함께 반환한다. AI 원본 `mappingRuns[].result`와 기존 관계의 `draft`는 변경하지 않는다.
- 수정 시 선택에서 빠진 관계와 제외 결정은 `EXCLUDED`로 구분한다. 승인·수정 관계도 아직 `DRAFT` 영역이며 `verifiedAssets`·`searchProjection`에 추가하지 않는다. 다시 승인하면 AI 원본 기준으로 새 검수 기록을 남긴다.
- 서버는 검토 확인 누락, 수정·제외 사유 누락, 공식 목록 밖 기준, 다른 콘텐츠·실행, 비활성 콘텐츠, 실패·보류·실행 중 결과, 이전 검수 ID·콘텐츠 버전의 저장을 거절한다. 새 검수 결정은 화면에서 명시적으로 저장해야 한다.
- `server/review-actions-check.js`: 결정·원본 보존·기준 교체·제외·검수 이력 복원·충돌·저장 실패와 화면/API 경로를 모의 검증한다. `node server/review-actions-check.js`로 실행한다.

## 수동 작업

- 사람이 EBS 원문과 공식 성취기준을 비교해 적절한 승인·수정·제외 판단을 정한다. 수정할 때는 공식 목록에서 기준을 선택하고 원문에 근거한 연계근거·수업 활용·사유를 작성한다. 제외할 때는 사유를 작성한다.
- 별도 계정·설정·추가 API 키는 필요하지 않다. 검수 결정 저장 자체는 LLM API를 호출하지 않는다.

- [x] 실제로 확인한 판단과 결과를 응답한다. 문제가 있다면 콘텐츠 제목, 선택한 판단, 누른 버튼, 표시된 오류 문구를 함께 남긴다. 적합한 사례가 없어 실행하지 않은 판단은 미확인으로 남긴다.
