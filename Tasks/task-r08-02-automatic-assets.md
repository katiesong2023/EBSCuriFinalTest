# Task R08-02 - 자동 연계 자산 저장과 검색 재사용

## 설명

[R08-01](task-r08-01-automatic-evidence.md)의 후보·근거·검사 결과를 사람 승인 자산과 분리해 영구 보존하고, 현재 유효한 자동 검사 자산을 확인 수준과 함께 검색에 제공한다. 기존 승인 자산 4개와 승인 Gate를 보존한다. 2026-10-05 구현·검증 후 사용자 완료 처리·R08-03 진행 요청을 반영해 **완료**다.

별도 SQLite와 공개 근거 투영을 구현했다. 실제 테이블·상태·참조는 [ERD](../docs/ERD.md#6-자동-연계-자산-r08-02-automatic-assetssqlite)에 기록했다. 기존 승인 JSON·방송/시맨틱 SQLite는 수정하지 않았다.

## 구현 항목

### 데이터베이스와 이력 보존

- [x] 자동 연계의 실행·후보 관계·근거·검사 결과·현재 검색 가능 자산을 기존 사람 승인 데이터와 구분해 저장한다. 실패·보류·후보 0건도 실행 결과로 남겨 미처리 자료와 구분한다.
- [x] 다음 논리 관계를 추적하고, 관련 없는 원본이나 판본으로 연결되지 않도록 참조 유효성을 확인한다.

| 저장 대상 | 보존해야 할 내용과 관계 |
| --- | --- |
| 처리 대상·원문 버전 | 출처 시스템·원본 ID·판본·원문 필드·내용 지문·출처 위치, 검사에 사용한 원문 |
| 실행 | 대상 원문/교육과정/규칙 버전, 생성 방식, 시작·종료·성공·실패·보류·재시도 이력 |
| 후보 관계 | 원본 자료의 해당 버전과 공식 성취기준의 해당 버전, 연결·부분 충족·미확인 범위 |
| 근거와 검사 | 인용문·위치, 기준의 요구, 개별 검사 결과·이유·시점, 관계 및 실행 참조 |

| 검색 준비 | 자산 버전, 반영 대기·완료·실패, 마지막 반영 결과; 자동 결과와 사람 승인 구분 |
| 사람 판단과의 연결 | 후속 실제 검토가 참조한 자동 관계·근거 버전; 사람 결정 생성은 R08-04 책임 |

- [x] 전체 재생성되는 시맨틱 스냅샷과 관계없이 자동 자산·검사 이력이 유지되게 한다. 방송 원본·시맨틱 근거·승인 JSON의 기존 책임과 원본 ID를 보존한다.
- [x] 같은 제목의 다른 회차·판본과 검색 대표 그룹을 구분한다. 검색 대표 ID나 제목만으로 관계·승인을 전파하지 않는다.
- [x] 반복 실행·중복 저장·중단 후 재개가 중복 자산이나 이력 유실을 만들지 않게 하고, 새 실행 결과를 이전 버전과 비교할 수 있게 한다. 일부 자료의 실패가 성공 자료의 결과를 지우지 않아야 한다.
- [x] 기존 승인 자산·검수 이력의 이전 전후 식별자·내용·유효성을 대조하고 복구 가능한 변경 절차를 준비한다. 자동 실행을 추가한 것만으로 기존 최신 사람 검토가 교체되거나 승인 자산이 무효화되지 않아야 한다.

### 변경과 제공 유효성

- [x] 원문·출처 식별·판본·공식 기준·규칙이 변경되거나 자료가 비활성화되면 영향받은 자동 관계를 현재 제공에서 제외하고 재검사 대상으로 남긴다. 이력은 보존하며, 관계 하나의 기준 변경으로 무관한 관계까지 없애지 않는다.
- [x] 오래된 검사 결과·동시 수정·검사 중 버전 변경을 감지해 현재 자산으로 저장하지 않는다. 원문 변경 후 검색 캐시·수업 폴더 재조회·내보내기에서도 오래된 통과 표시가 남지 않도록 한다.
- [x] 사람 제외·수정 결정이 있는 관계를 자동 재실행이 덮어쓰거나 다시 노출하지 못하도록 우선순위를 보존한다. 새 버전에서 판단이 필요하면 변경 예외로 남긴다. 실제 관계별 사람 결정 기능은 R08-04에서 연결한다.

### 검색·교사 화면 연결

- [x] 공식 방송 자료가 검수 저장소에 수동으로 가져와지지 않았어도 후보 생성 → 자동 검사 → 별도 자산 저장 → 검색 준비가 이어지게 한다. AI 초안과 사람 승인 기록을 필수 입력으로 요구하지 않는다.
- [x] 검색 제공은 R08-01의 공개 조건을 통과한 현재 유효 관계로 제한한다. 부분 연계는 충족·미확인 부분을 표시하고, 실패·보류 관계는 교육과정 연계 결과에서 제외한다. 같은 자료의 주제 탐색 가능 여부는 독립적으로 유지한다.
- [x] 교사 자료 찾기·자료 재조회·내 수업 폴더·내보내기에서 주제 자료, 자동 연계 후보, 사람 승인 관계를 구분한다. 한 자료의 사람 승인 관계가 다른 자동 관계까지 승인한 것처럼 표시되지 않아야 한다.
- [x] 기존 승인 필터와 `/index.html`의 승인 자산 검색은 실제 유효한 사람 승인만 반환한다. 자동 자산을 기존 `verifiedAssets`·사람 승인 검색 투영에 섞어 넣지 않는다.
- [x] 자산 저장 후 검색 준비를 자동으로 이어가되 저장 성공과 검색 반영 실패를 구분한다. 검색 재시도는 후보 생성·사람 결정·자산 중복 생성을 요구하지 않는다.
- [x] 기존 관리자 세션·쓰기 권한을 유지하고 공개 검색에는 필요한 근거·확인 수준만 제공한다. 자동 생성·검사·재검사·저장은 관리 권한을 요구한다.

## 실제 구현

- `server/data/automatic-assets.sqlite` 스키마 v1: 원문 사본 `sources`, 실행 `runs`, 후보/인용/검사 `relations`, 자산 `assets`, 공개 투영 `search_projection`, 이력 `events`. 시맨틱 재빌드와 분리했다.
- 실행 서비스는 서버 원본으로 생성·검사하고 저장 직전에 입력 지문을 다시 대조한다. 후보·근거·자산은 트랜잭션으로 저장하고, 검색 준비는 별도 단계로 이어진다. 반복 입력은 재사용하며 중단 작업은 5분 임대 만료 후 다음 실행에서 재개한다. 실행 중에는 같은 입력에 409를 반환한다.
- 실제 사람 승인·수정·제외 관계는 자동 노출보다 우선한다. 기존 `reviewId`만 연결하며 자동 실행은 사람 검토 기록·`HUMAN_VERIFIED`를 만들지 않는다. 관계별 신규 사람 결정과 관리자 화면은 R08-03·04에서 이어간다.
- 교사 검색의 **자동 근거 검사 통과** 필터와 카드/모음/폴더/Markdown에 별도 부분 연계·인용·연결/미확인 부분을 추가했다. 기존 **교육과정 연계 확인** 필터와 `/index.html`은 사람 승인 전용이다. 검색 대표가 다른 회차여도 자산의 정확한 원본 ID로 제공하며 같은 제목의 다른 판본에 전파하지 않는다.
- 저장한 폴더를 열거나 화면으로 복귀할 때 현재 상태를 재조회한다. 재조회 전·실패 시 과거 통과 표시는 숨긴다. 내보내기도 다시 조회하며 조회 실패 시 다운로드하지 않는다. 사용자 메모·폴더 선택은 보존한다.

### API와 로컬 명령

| 경로 | 동작 |
| --- | --- |
| `GET/HEAD /api/admin/automatic-assets` | 최신 100개 실행·관계·자산·사건. `?runId=AUTO-RUN-…`으로 특정 실행 조회. 현재 자산 변경도 재대조 |
| `POST /api/admin/automatic-assets` | `{resourceId, subject, gradeBand?}` 또는 `{contentCuriId, subject?, gradeBand?}`. 원문/검사 결과 입력은 받지 않음 |
| `POST /api/admin/automatic-assets/search` | `{runId}`의 검색 준비만 재시도. 생성·사람 결정·자산 중복 저장 없음 |

HTTP는 관리자 세션·동일 Origin·기존 쓰기 잠금을 요구한다. 로컬 CLI는 저장소에 접근할 수 있는 운영자의 명시적 실행 도구다.

```sh
npm run data:automatic -- process --resource BCAST-4280dd3cf2aaac6c3584 --subject 과학
npm run data:automatic -- status
npm run data:automatic -- search --run AUTO-RUN-74a3fe37-3945-4593-b6af-8d6a85b67e83
npm run data:automatic:check
```

`saveStatus=CHECKED`는 검사 수행 상태이며 승인·검색 자산 보유를 뜻하지 않는다. `runs[].report.summary.publishable`, `assets`, `searchPreparation.ready/failed/invalidated`를 함께 확인한다. 저장 성공 뒤 검색 준비가 실패하면 실행 ID로 `search`만 다시 실행한다. 원문/기준/규칙 변경과 사람 결정 차단은 검색 재시도로 되돌리지 않으며 현재 사유를 확인하고 필요한 재검사를 수행한다.

### 백업·복원

1. `npm run data:automatic -- backup --destination /private/tmp/curi-automatic-backup.sqlite`로 **아직 없는 파일**에 일관된 SQLite 사본을 만든다. 같은 경로가 이미 있으면 다른 새 이름을 사용한다.
2. 복원할 때는 서버와 자동 처리 CLI를 종료한다. 현재 자동 DB도 별도 이름으로 백업해 둔 뒤 선택한 백업을 `server/data/automatic-assets.sqlite`에 복사한다. `CURI_AUTOMATIC_DB`를 설정했다면 그 경로가 대상이다.
3. 서버를 다시 시작하고 `status` 또는 교사 검색을 조회한다. 복원된 과거 통과도 현재 원본/기준/규칙/사람 결정과 다시 대조한다. 방송·시맨틱 DB·`curi-store.json`은 교체하지 않는다.

스키마 v1 최초 생성은 새 파일만 대상으로 한다. 버전 없는 기존 테이블·지원하지 않는 버전은 덮어쓰지 않는다. 기존 승인 4개·검수 이력은 이관 대상이 아니므로 재승인할 필요가 없다.

### 실행 확인

- [저장·무효화 계약](../docs/r08-02-assets-check.json) 26개: FK, 반복·동시 실행, 실패 롤백, 중단 후 재개, 검색 재시도, 원문/출처/판본/기준/규칙/비활성 무효화, 관계별 영향, 실제 사람 결정 우선, 시맨틱 재빌드·백업/복원, 기존 승인 보존.
- [HTTP·브라우저 검사](../docs/r08-02-http-browser-check.json): 임시 복제 서버 HTTP 4개와 Playwright 4개. 관리 권한·자동/사람 필터·같은 제목 회차 분리·카드·폴더·내보내기·원문 변경·조회 실패, 1440px/390px에서 확인했다. 통과 사례는 합성 개발 텍스트이며 실제 방송 정확도 평가가 아니다.
- R08-01 41개, 기존 후보/검수/초안 실패/승인 저장/검색 준비/승인 검색/교사 추천9·기존 수업 폴더 브라우저12 회귀를 통과했다. 기존 승인 4개와 세 원본 파일 SHA-256 불변을 확인했다. 유료 API 호출은 0이다.
- [실제 원본 2건](../docs/r08-02-real-runs.json)을 신규 DB에 저장했다. ‘지구의 자전 속도가 느려지는 이유’는 후보 1건의 관계 보류, ‘이상한 선거’는 후보 0건 보류다. **공개 가능한 자동 자산은 0건**이며 억지로 통과 사례를 만들지 않았다. 자동 검사는 현재 두 성취기준의 제한된 서술만 지원한다.

## 수동 작업

필수 키·계정·외부 서비스 설정은 없다. 유료 API를 사용하지 않는다.

- 서버를 재시작하고 `/`에서 **자동 근거 검사 통과** 필터를 선택한다. 현재 실제 실행 2건은 모두 공개 조건 미충족이므로 자동 후보가 0건이며, 필터를 해제하면 주제 자료는 계속 검색되는지 확인한다.
- 위 `data:automatic -- status` 명령으로 원본 ID·실행 상태·보류 이유·후보 수가 보존되고 같은 자료를 다시 `process`하면 `reused: true`인지 확인한다. `CHECKED`를 사람 승인으로 해석하지 않는다.
- **교육과정 연계 확인** 필터와 `/index.html`에서 기존 사람 승인 자료가 유지되고 자동 후보가 사람 승인으로 표시되지 않는지 확인한다.
- 내 자료를 수업 폴더에 담아 다시 열고 목록을 내려받는다. 현재 확인 수준을 표시하고 원문 재조회 실패 시 과거 통과로 표시하지 않는지 확인한다.
- `npm run data:automatic:check`와 두 검사 보고서에서 보존·무효화 결과를 확인한다. 실제 사람의 교육과정 의미 정확도·교사 효용 평가는 수행되지 않았음을 확인한다.
