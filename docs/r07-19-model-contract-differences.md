# 제품 계약과 모델 연결 준비

제품의 요청 해석은 `curi-request-v1`을 유지한다. 실험의 v2를 버전명만 바꾸거나 `value`를 삭제해 변환하지 않는다. 이번 변경은 A·B 요청 생성, 전달 응답의 검증·검색 연결과 기본 표시이며 실제 모델 실행은 없다.

| 항목 | 제품 v1 | 실험 v2 | 이번 적용 |
| --- | --- | --- | --- |
| 실행 의미 | label·원문 구절·필수/제외·논리 | 같은 구조에 typed value 추가 | v1 단일 런타임. v2 거절 |
| 시간·날짜 | 명시 label을 기존 연산자로 검사 | 값·단위·연산자를 분리 | 기존 지원 연산자 유지, 미지원은 UNKNOWN |
| 검색 | LOCAL_E5와 원문·단어 경계 | 별도 문자열 프로토타입 | 제품 경로 유지 |
| B 비교 | 요청별 원문 대조 응답 추가 | 개발 회차 수작업 검토 재사용 | 전달 응답을 원문과 대조. 사전 답을 모델 실행으로 보고하지 않음 |
| 품질 평가 | 현재 제품 기준선 필요 | 30후보 에이전트 검토 | 서로 합산하지 않음. 기존12질문은 개발 회귀로 사용 |

## A와 B의 비호출 연결

`request-model-preparation.js`는 Responses 형식 요청을 준비하고 완료/거절/미완료 응답을 구분한다. 생성용 Schema는 제품 Schema에서 만들며, 생성 형식의 제약과 런타임 의미·구절 검사를 분리한다. 이는 [OpenAI Structured Outputs 안내](https://developers.openai.com/api/docs/guides/structured-outputs)의 형식이며 실제 공급자의 모델별 호환성은 미호출 상태다.

`POST /api/curi/discover/model-preparation`은 외부 실행 옵션을 받지 않는 읽기 전용 경로다.

1. `{input}`을 보내면 기존 로컬 결과와 `requestExecution.preparationA`를 반환한다.
2. `{input,aResponse}`를 보내면 v1 해석 검증과 기존 조건의 검색을 수행하고 `preparationB`를 반환한다. 준비된 B 후보는 선택 프로그램·유형·기간·정렬과 판본 묶음을 적용하며, 공식 기준이 선택되면 그 기준의 후보 범위에 제한한다. 후보가 없으면 B 요청을 준비하지 않는다.
3. `{input,aResponse,bResponse}`를 보내면 B 응답을 검증해 후보 비교를 적용한다. 날짜 정렬·기존 필터·공식 기준 교집합은 기존 최종 경로에서 유지한다. B 순위는 관련순에 반영하며 부적합 후보를 제외한 뒤 기존 집계/페이지 경로를 사용한다.

A와 B 응답은 직접 JSON 또는 완료된 Responses 원형 응답을 받을 수 있다. 전달된 응답의 채택은 이 서버가 모델을 호출했다는 뜻이 아니다. 일반 화면은 모델을 자동 호출하지 않으며 A·B 전후 품질은 아직 미측정이다.

## B 인용과 조건 검증

`candidate-review.js`는 최대10후보의 제목과 소개문 앞600자를 준비한다. 원문을 잘랐는지 표시한다. 전체 회차 ID·판본·제목·소개문·출처 지문과 원래 질문/요구/선택 조건 지문을 대조한다. 다른 후보, 변경 원문, 다른 질문의 응답, 전달되지 않은600자 밖 인용, UTF-16 위치/인용 불일치, 요구 누락/중복, 근거 없는 충족 판정을 거절한다. 일부 응답이 잘못되면 해당 B 묶음 전체를 채택하지 않고 기존 후보를 보존한다.

B는 지역·프로그램·형태·날짜·길이·공식 기준·장면·자막 및 제외 조건의 시스템 판정을 덮어쓰지 못한다. 원문 인용으로 주제·관계의 대조 상태를 보완할 수 있다. 모든 요구가 확인되지 않으면 SUITABLE 판정을 채택하지 않으며 부분 관련·원문 부족·미확인을 구분한다. 인용이 실제 원문과 같다는 검사가 인용의 의미 해석까지 보증하지는 않는다.

관련 소재 목록의 용암·분화구·현무암은 화산 후보를 발견하는 데 쓸 수 있지만 명시된 좁은 요청을 화산 전체로 대체하지 않는다. 좁은 원문 단서 없는 후보의 노출과 A의 상위 개념 대체를 차단한다. 일반 동의어와 모든 좁은 개념에 대한 범용 분류를 완성한 것은 아니다.

## 실행 차단과 남은 작업

`request-model-client.js`는 기본 `allowExternal=false`다. 이 준비 경로는 클라이언트를 호출하지 않는다. 외부 실행에는 시스템의 별도 활성화, `CURI_ALLOW_PAID_API=true`, 모델·호출 수·출력/시간 제한·승인 예산 설정이 모두 필요하며, 기본 차단은 키 조회와 네트워크 이전에 작동한다. 예산 설정은 승인 범위 기록이고 금액 실측·공급자 지출 상한 기능은 아니다. 실제 비용 계측과 승인 범위 확정 전에는 제품에서 활성화하지 않는다. 키 값을 문서·검사·응답에 넣지 않았다.

실제 A 자동 생성→검색→B 실행의 운영 오케스트레이션, 새 질문의 의미 정확도/후보 관련성/비용·지연, 공급자 호환성·실패 복구 실측은 후속이다. 원문 부족은 모델 연결만으로 해소되지 않는다. 원문·지역 정보 보강 효과는 모델 효과와 별도로 평가한다.

## 교사 표시와 확인

기본 카드에 자료 선택 이유, 검증된 자기 회차 인용 최대2개, 남은 확인, 원문 열기를 우선 표시한다. 전달된 B 비교는 실제 모델 실행이나 영상·학년 적합성 확인으로 표시하지 않는다. 기존 상세 원문·교육과정 근거·영상 링크·개인 저장은 유지한다.

`request-model-check.js`는 비호출 fixture, `request-model-http-check.js`는 복제 서버의 HTTP를 검사한다. 보호4저장소는 검사 전후 동일하며 실제 서버를 재시작하지 않았다. 화면은 VM 기반 마크업·escape 검사이며 실제 브라우저/모바일 시각 검증은 미완료다. 수신12질문이나 기존 최종40질문으로 모델 성공률을 산출하지 않았다.
