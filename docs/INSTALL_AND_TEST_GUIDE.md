# Curi 소스 ZIP 설치 및 테스트 안내서

작성일: 2026-10-16 · 대상: Windows/macOS의 로컬 PC · 권장 브라우저: 데스크톱 Chrome

이 안내서는 Curi 실행용 소스 ZIP을 받은 사람이 설치하고 주요 기능을 확인하는 절차다. 2026-10-16 macOS에서 저장소 밖 새 폴더에 ZIP을 해제해 npm ci·npm start·교사 검색·교육과정 선택·폴더/메모 저장·새로고침·테스트용 구간 리스트·실제 확장 브리지를 확인했다. Windows 설치·네이티브 사이드 패널 UI·EBS 로그인/본편/구간 재생은 미검증이다. 첫 검색 준비 시간 초과를 수정해 최신 ZIP에 반영했다. 상세 기록은 패키지의 FINAL_TEST_REPORT.json을 참고한다.

기본 테스트는 외부 유료 AI 호출을 사용하지 않는 로컬 모드다. 영상에서 모델 보충 검색을 사용했다면 결과·순위가 다를 수 있으므로 배포자가 해당 차이를 명시해야 한다. 관리자 검토·교육과정 적합성·교사 효용의 확인과 설치 성공은 별개다.

## 1. 준비물

| 준비물 | 조건 |
| --- | --- |
| PC | Windows 또는 macOS, 압축 해제 폴더에 파일을 쓸 수 있어야 함 |
| Node.js | **24.18.0 이상**. npm 포함 |
| 브라우저 | 데스크톱 Chrome. 확장 최소 요구 버전은 116이며 최신 환경 권장 |
| 인터넷 | npm 패키지 설치, 필요한 모델의 최초 다운로드, EBS 페이지·영상 이용 |
| EBS 계정 | 선택한 영상의 로그인·시청 권한이 필요한 경우 사용 |
| 소스 ZIP | 서버·웹·확장·필요 DB/JSON과 package-lock.json이 들어 있는 실행용 패키지 |

영상 원본은 ZIP에 포함하지 않는다. Curi 폴더에서 HTML 파일을 더블클릭하는 방식이 아니라 Node.js 서버를 실행하여 이용한다.

## 2. 압축 해제와 파일 확인

1. ZIP을 PC의 일반 작업 폴더에 완전히 압축 해제한다. ZIP 미리보기 안에서 실행하지 않는다.
2. 압축을 푼 폴더에서 `package.json`이 있는 위치를 찾는다. 이하 이 위치를 **프로젝트 폴더**라고 부른다.
3. 다음 파일·폴더가 있는지 확인한다.

```text
프로젝트 폴더/
├── package.json
├── package-lock.json
├── public/
├── server/
│   └── data/
│       ├── curi-store.json
│       ├── broadcast-catalog.sqlite
│       └── ... 기타 실행용 DB·교육과정·설정 JSON
└── extensions/
    └── curi-segments/
        └── manifest.json
```

위 목록은 폴더 식별용이며 전체 의존 파일 목록은 아니다. 배포된 `server/data`를 일부만 골라 옮기지 않는다. 데이터가 빠졌을 때는 배포자에게 완전한 패키지를 요청한다. 초기 데이터 생성·수집 명령으로 누락을 임의 복구하지 않는다.

모델 파일은 숨김 폴더 `server/data/.model-cache`에 포함될 수 있다. 포함하지 않은 패키지는 해당 모델을 처음 사용하는 시점에 인터넷에서 내려받을 수 있다.

## 3. Node.js 확인과 패키지 설치

### Windows

1. 프로젝트 폴더를 탐색기에서 연다.
2. 폴더 주소 표시줄에 `powershell`을 입력하고 Enter를 누른다.
3. 아래 명령을 한 줄씩 실행한다.

```powershell
node --version
npm --version
npm ci
```

PowerShell에서 `npm.ps1을 실행할 수 없다`는 메시지가 나오면 같은 명령을 `npm.cmd --version`, `npm.cmd ci`로 실행한다. 이후 `npm start`와 `npm run ...`도 각각 `npm.cmd start`, `npm.cmd run ...`으로 바꿔 실행할 수 있다.

### macOS

1. 터미널을 연다.
2. `cd `를 입력하고 압축 해제한 프로젝트 폴더를 터미널에 끌어놓은 뒤 Enter를 누른다.
3. 아래 명령을 한 줄씩 실행한다.

```sh
node --version
npm --version
npm ci
```

두 환경 모두 `node --version`이 24.18.0 이상인지 확인한다. 명령을 찾지 못하면 Node.js 설치 후 터미널을 닫았다가 다시 연다. `npm ci`가 오류 없이 끝나야 다음 단계로 진행한다. `node_modules`는 이 단계에서 생성되며 다른 PC에서 복사한 폴더를 재사용하지 않는다.

## 4. API 키 없이 로컬 테스트 설정

서버를 시작하기 전에 프로젝트 폴더에 `.env` 파일을 일반 텍스트로 만들고 아래 내용을 저장한다. Windows에서는 실제 파일명이 `.env.txt`가 되지 않게 파일 확장명을 확인한다. 기존 개인 `.env`를 덮어쓰지 말고 압축 해제한 별도 테스트 사본에서 작업한다.

```dotenv
PORT=3000
CURI_ALLOW_PAID_API=false
```

별도로 `server/data/teacher-search-model-policy.json`을 일반 텍스트 편집기로 열어 **`"enabled": false`**인지 확인한다. `true`라면 설치한 테스트 사본에서 그 값만 `false`로 변경하고 저장한다. 나머지 항목·쉼표·중괄호는 유지한다. 이 설정 파일이 없으면 현재 코드에서는 해당 모델 경로를 비활성으로 처리한다.

현재 교사 모델 검색에는 별도 정책 경로가 있어 `CURI_ALLOW_PAID_API=false`만으로 모든 모델 호출이 비활성이라고 판단하면 안 된다. 이 안내서는 두 설정을 함께 확인한다. API 키를 입력하지 않으며 개발용 비용 원장·유료 실험 스크립트는 실행하지 않는다. 이미 API 키가 설정된 개인 개발 환경보다 별도 테스트 환경을 사용한다.

로컬 모델 다운로드와 EBS 페이지 요청에는 인터넷을 사용할 수 있다. 이는 유료 LLM API 호출과 다르다.

## 5. Curi 서버 시작

프로젝트 폴더의 터미널에서 실행한다.

```sh
npm start
```

서버 실행 메시지가 나오면 Chrome에서 다음 주소를 연다.

```text
http://localhost:3000
```

터미널을 열어둔 상태로 테스트한다. 서버는 현재 PC의 루프백 주소에 바인딩되므로 다른 PC·휴대전화에서 접속하는 공개 서비스가 아니다. 종료는 서버 터미널에서 `Ctrl+C`, 재시작은 다시 `npm start`다.

**주소는 처음부터 끝까지 `http://localhost:3000`으로 통일한다.** `127.0.0.1`이나 다른 포트로 바꾸면 개인 자료가 별도 공간으로 보인다. 서버 안내에 127.0.0.1이 표시되어도 브라우저와 확장 설정은 위 주소로 맞춘다.

## 6. 기본 웹 기능 테스트

개인 자료 테스트에는 기존 자료와 구분되는 **`설치 테스트`** 폴더를 사용한다. 새 설치에서는 개발자 PC의 개인 폴더·메모·구간이 자동으로 나타나지 않는 것이 정상이다.

| 순서 | 조작 | 기대 결과 |
| --- | --- | --- |
| 1 | 첫 화면 열기 | 검색창과 기본 화면이 표시됨. 검색 전 자동 결과가 없어도 정상 |
| 2 | `기후 변화` 등 주제 입력 후 `자료 찾기` | 결과 또는 빈 결과 안내가 표시되고 로딩이 종료됨 |
| 3 | 결과가 없으면 `지구의 자전` 또는 패키지에 안내된 회차명으로 검색 | 후보가 있으면 다음 테스트 진행. 정확한 검색어·후보 유무 기록 |
| 4 | 자료의 상세 설명·원문·출처 펼치기 | 해당 자료의 설명과 제공 가능한 출처 확인. 정보 부족 표시는 그대로 기록 |
| 5 | `가져가기`에서 전체 기준 조회·필터·기준 선택 | 기준을 선택·해제할 수 있음. 관련 후보 부재를 설치 실패로 보지 않음 |
| 6 | `선택 완료` 후 새 폴더 `설치 테스트`를 지정하고 `가져가기` | 저장 성공 안내와 내 수업 이동 제공. 기준 미선택은 `선택 안 함` 이용 가능 |
| 7 | `내 수업으로 이동` 후 해당 폴더 열기 | 저장 자료와 선택한 교육과정 표시 |
| 8 | 자료 메모를 입력하고 저장 상태 확인 후 새로고침 | 같은 주소·Chrome 프로필에서 메모와 자료 유지 |

첫 검색은 전체 자료의 색인을 준비하므로 수십 초가 걸릴 수 있다. 첫 검색 대기는 최대120초이며 이후 검색 제한은12초다.

검색 결과가 없다는 사실과 서버 오류는 구분한다. 모든 시험 검색어가 빈 결과이거나 원천 데이터가 없다는 오류가 나오면 패키지 데이터·설정을 확인하고 배포자에게 보고한다. 기본 테스트는 교육과정 연결의 의미 정확도·수업 적합성 평가가 아니다.

## 7. Chrome 확장 설치·연결

1. Chrome 주소창에서 `chrome://extensions`를 연다.
2. 개발자 모드를 켠다.
3. **압축해제된 확장 프로그램을 로드합니다**를 누른다.
4. 프로젝트 폴더의 **`extensions/curi-segments`**를 선택한다. `manifest.json`이 바로 들어 있는 폴더여야 한다. 프로젝트 전체나 ZIP 파일을 선택하지 않는다.
5. EBS CURI 확장이 설치되면 Chrome 도구 모음의 확장 메뉴에서 아이콘을 고정한다.
6. `http://localhost:3000/lesson.html`을 열고 해당 탭을 유지한다.
7. EBS CURI 아이콘을 눌러 사이드 패널을 연다.
8. 패널 상단의 **EBS CURI 연결**에서 주소 `http://localhost:3000`을 입력하고 **연결·폴더 불러오기**를 누른다.
9. 웹에서 만든 `설치 테스트` 폴더가 패널에 표시되는지 확인한다.

확장 파일을 교체한 경우 `chrome://extensions`의 Curi 카드에서 새로고침하고 **Curi·EBS 페이지도 각각 새로고침**한다. 설치 폴더를 삭제하거나 옮기면 확장이 동작하지 않을 수 있으므로 테스트 중 그대로 둔다.

## 8. 실제 영상과 구간 테스트

지식채널e·다큐프라임의 접근 가능한 개별 회차를 우선 사용한다. 과거 기술 확인 사례는 지식채널e 「지구의 자전 속도가 느려지는 이유」와 「다윈의 예언」이다. 현재 공개·시청 가능 여부와 패키지의 검색 결과는 다시 확인해야 한다.

1. Curi 자료의 `방송 보기`로 EBS 원본 회차를 연다.
2. 필요한 경우 EBS에 로그인한다. 확장에서 본편 확인 안내가 나오면 `EBS 로그인` 후 `영상으로 돌아가기`를 사용한다.
3. 로그인 상태 반영이 필요하면 영상을 새로고침하고 광고가 끝난 **본편을 직접 재생**한다.
4. 확장에서 현재 영상 제목과 저장할 폴더 `설치 테스트`를 확인한다. 다른 탭이 선택되어 있으면 영상 목록을 새로고침하고 정확한 회차를 선택한다.
5. `구간 지정` 탭을 선택하고 이름 `설치 확인 구간`을 입력한다.
6. 본편에서 `시작 지정`, 조금 재생한 뒤 `끝 지정`을 누른다. 직접 입력 시 예를 들어 시작 `0:10`, 끝 `0:20`처럼 영상 길이 안의 시간을 사용한다. 시작보다 끝이 커야 한다.
7. 현재 폴더와 구간을 확인하고 패널의 가져가기/저장 버튼을 누른다. 저장 성공 안내를 확인한다.
8. 같은 주소의 내 수업 자료로 돌아가 저장한 구간 카드와 이름·시간을 확인한다.
9. `저장 구간 보기`를 눌러 원본 회차의 시작 이동을 확인한다. 자동 재생이 제한되면 EBS 재생 버튼을 직접 누른다.
10. 끝 정지 여부를 관찰한다. 원본 전체 재생으로 돌아갈 때는 패널의 구간 제어 해제를 사용한다.

구간은 원본 링크와 시간 기록이며 영상 파일이 생성되는 기능이 아니다. 지원하지 않는 플레이어·외부 iframe·로그인/권한·버퍼링 상태에서는 시간 읽기나 제어가 보류될 수 있다. 실패한 회차·단계·메시지를 기록하고 모든 EBS 영상 지원으로 판단하지 않는다.

## 9. 수업 영상 리스트와 재사용 테스트

- [ ] 수업 폴더에서 저장 구간 카드를 수업 영상 리스트로 드래그하면 리스트에 표시된다.
- [ ] 구간이 두 개 이상이면 드래그로 순서를 바꿀 수 있다.
- [ ] 구간 합계 시간이 표시된다. 겹치는 구간도 각각의 길이로 합산한다.
- [ ] 폴더 전환·새로고침 후 자료·구간·리스트 순서가 유지된다.
- [ ] 리스트에서 항목을 빼도 원본 구간 카드가 유지된다.

브라우저 데이터 삭제·시크릿 창 종료·다른 프로필/접속 주소 사용은 저장 결과에 영향을 준다. 단순 새로고침 후 보존과 기기 간 동기화를 혼동하지 않는다.

## 10. 관리자 화면 확인 — 선택 사항

현재 제출 설명의 관리자 검증 한계를 고려하여 기본 교사 기능 테스트와 분리한다. 화면 접근·조회 성공이 교육과정 연결의 타당성 검증을 뜻하지 않는다.

1. 서버 터미널의 **이번 실행의 관리자 코드**로 로그인할 수 있다. 코드를 외부 공유 화면에 노출하지 않는다.
2. 고정 비밀번호가 필요하면 서버를 `Ctrl+C`로 종료한 후 아래 명령으로 직접 설정한다. 로컬 비밀번호는 8자 이상이며 숨김 입력한다.

```sh
npm run admin:password
npm start
```

3. `http://localhost:3000/admin.html`에 접속하여 로그인한다.
4. 자료·품질 목록, 교육과정별 확보 현황과 조회 가능한 원문·검토 상태를 확인한다.
5. 실제 사람 승인·취소·공용 자료 변경은 기본 테스트에 포함하지 않는다.

설정 명령은 테스트 사본의 `.env`를 변경한다. 기존 환경변수가 따로 설정되어 있으면 로그인 설정에 영향을 줄 수 있다. 관리자 코드를 모르거나 개발자 측 검증이 필요한 경우 교사 테스트와 분리하여 미확인으로 기록한다. 현재 사람 승인 자산은 0건이므로 승인 목록이 비어 있다고 설치 실패로 판단하지 않는다.

## 11. 문제 해결

| 증상 | 확인·조치 |
| --- | --- |
| node/npm 명령을 찾지 못함 | Node.js 버전·설치 확인 후 새 터미널 열기 |
| npm.ps1 실행 차단 | PowerShell에서 `npm.cmd` 사용 |
| npm ci 실패 | 프로젝트 폴더·package-lock.json·인터넷·오류 로그 확인. 임의로 잠금 파일 삭제하지 않기 |
| SQLite·모듈 관련 오류 | Node.js 24.18.0 이상인지 확인하고 해당 환경에서 `npm ci` 재실행 |
| 서버 접속 불가 | 터미널의 실행 오류 확인, 서버가 계속 실행 중인지 확인 |
| EADDRINUSE / 포트 사용 중 | 기존 본인 Curi 서버를 종료하거나 테스트 사본의 `.env`에서 다른 포트 선택. 주소·확장 설정도 함께 변경 |
| 검색이 모두 비거나 DB 누락 오류 | 배포 데이터·폴더 구조 확인. 임의 재수집·초기화보다 배포자에게 보고 |
| 최초 모델 준비 실패 | 인터넷·Hugging Face 접근·디스크 여유/쓰기 권한 확인. 포함된 모델이 있으면 숨김 폴더 누락 확인 |
| 모델 보충 사용 불가 안내 | 기본 로컬 모드 설정과 별도 정책의 enabled 값 확인. 키 입력·예산 증액으로 임의 복구하지 않기 |
| 확장 로드 실패 | manifest.json 바로 위 폴더 선택 여부·Chrome 버전·누락 파일 확인 |
| 폴더 없음·연결 실패 | 서버·내 수업 탭·같은 프로필·정확한 주소 확인, 확장/Curi/EBS 갱신 |
| 영상 시간 읽기 실패 | 회차 선택·로그인·본편 재생·지원 플레이어 확인 |
| 저장 자료가 사라진 것처럼 보임 | localhost/127.0.0.1·포트·프로필·시크릿 모드 차이 확인 |
| 관리자 로그인 실패 | 현재 실행 코드 또는 설정 비밀번호 확인, 설정 후 서버 재시작 |

## 12. 테스트 결과 기록 양식

아래를 복사하여 설치 결과를 남긴다. API 키·관리자 코드·비밀번호는 기록하지 않는다.

```text
테스트일:
ZIP 파일명/제출 버전:
운영체제 / Node.js / Chrome 버전:
확장 버전:
접속 주소:
유료 호출 비활성 설정 확인: 예 / 아니오
패키지 설치 / 서버 시작: 성공 / 실패
검색어 / 결과 여부:
원문·출처 표시: 확인 / 미확인
교육과정 조회·개인 연결: 확인 / 미확인
폴더·메모 저장·새로고침 유지: 확인 / 미확인
확장 연결·구간 저장: 확인 / 미확인
테스트 회차 / 시작·끝:
구간 시작 이동 / 끝 정지: 확인 / 미확인
리스트·순서·재열기: 확인 / 미확인
관리자 조회(선택): 확인 / 미확인 / 미실시
오류가 난 단계 / 정확한 메시지:
```

테스트가 끝나면 서버를 `Ctrl+C`로 종료한다. 테스트 폴더를 지우려면 본인이 만든 `설치 테스트`만 확인하여 삭제한다. 브라우저 전체 저장소를 초기화하거나 공용 DB를 삭제하지 않는다.
