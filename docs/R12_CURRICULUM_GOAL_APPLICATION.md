# 교육과정 수업 목표 기능 적용 결과

2026-10-14 사용자 적용 요청으로 제품에 반영했다. 실제 교사 연구가 아닌 기능/계약/화면 검증이다. 유료 API·영상 재생·실제 운영 제안 제출·사람 승인 실행은 없다.

## 적용한 동선

1. 상세 필터의 **교육과정에 맞춰 찾기**에서 주제/탐색어·다룰 내용으로 기준을 찾는다. 서비스 탐색어와 코드/공식 원문을 구분한다. 공식214기준/학년군·중1 편성 참고는 보존한다.
2. 기준을 선택하고 **이번 수업에서 필요한 내용**, 자유 수업 목표, 원하는 영상 활용 목적을 정해 **이 목표로 자료 찾기**를 누른다. 영상 활용 목적은 교사의 의도이며 장면 판정이 아니다. 기준이 바뀌면 요구·목표 입력을 새로 시작한다.
3. 새 선택의 기본은 **관련 후보 우선**이다. **선택 기준 관련 후보** 다음에 **주제 확장 자료 — 기준 연계 미확인**을 구분한다. 후보만 보기/확인 기록 있는 후보만 보기에서는 확장 자료를 제공하지 않는다. 명시적 관계 상태/확인 필터도 확장 자료를 제한한다. 기존 주소는 후보 한정으로 복원한다. 원래 검색어·국내/제외·프로그램/주제 등 선택 조건을 유지하며 각 범위 내부에서 정렬하고 페이지를 나눈다.
4. 카드에 목표·원하는 역할, **이 수업에 쓸 이유**, 자기 회차 인용·남은 요구·교사가 준비할 활동·영상 미확인을 표시한다. 교사 활동 제안과 영상에서 확인한 설명을 분리한다.
5. 빠른 담기와 기존 수업 폴더 담기를 유지한다. 선택 기준/교육과정 판본·요구·목표·목적을 개인 선택 기록에 이어받는다. 폴더에는 공통 목표와 영상별 개인 역할/원문 근거/추가할 활동 표가 있으며 수정·재열기가 가능하다. 학생 수행 완료 점수는 만들지 않는다.
6. **연계 근거 제안하기**를 직접 누르면 현재 원문/기준·정확한 인용·출처를 확인하는 미리보기를 연다. 연결되는 요구와 이유만 제출한다. 개인 목표/구간/메모는 제출하지 않는다. 원문·기준·인용이 바뀌거나 허용하지 않은 필드/송신원이면 거절한다. 제출은 PENDING 검토 후보이고 승인/자동 공개를 바꾸지 않는다.
7. 관리자 화면의 **교사의 연계 근거 제안**에서 접수 내용을 보고 검토중/반려로 표시한 뒤 기존 원문/관계 검토를 연다. 기존 해당 영상×기준 검토가 있으면 검토ID·결정·현재 유효성도 보여준다. 검토중 전환 때 현재 원문/기준을 재확인한다. 보조 원문이 기존 검토 계약의 지원 범위를 벗어나면 보류하며 새 승인 체계를 만들지 않는다.

## 빈 결과와 명시적 확장

기준은 자동 해제하지 않는다. **기준 전체 내용으로 찾기**는 선택 요구를 전체로 바꾼다. **주제 자료까지 넓혀 보기**는 우선 모드로 돌아가고 명시적 관계/확인 기록 제한을 해제한다. 원래 검색어가 없으면 기준의 주제 탐색어를 사용한다. 자유 목표를 입력한 첫 검색에서 원래 검색어가 없으면 그 목표를 검색어로 사용한다. 기존 검색어가 있으면 임의로 덮어쓰지 않는다.

확장 자료의 선택 기준 관계는 미확인이다. 기준을 개인 활용 기준으로 기록할 수 있지만 해당 기준 확인 기록을 복사하거나 승인으로 사용하지 않는다. 학교 학년/영상 난이도·실제 모형/실험 장면·학생 수행은 별도 확인이다.

## 실제 코드

- `server/lesson-goal.js`: 모드·목표 길이/목적·현재 기준의 요구ID 검증, 수업 의도 문맥.
- `teacher-combined-search.js`: 기존 한정 경로 재사용, 관련/확장 범위·확인 기록 모드·선택 요구 비교/우선순위.
- `curriculum-discovery.js`: 공식 요구·교육과정 판본·서비스 탐색어를 기준 선택 응답에 제공.
- `search-state.js`, `curriculum-picker.js`, `discover.html`, `teacher-cards.js`, `teacher-source.js`: 목표·모드·기준 선택·카드의 구분/인용·빈 결과 복구·제안 진입.
- `lesson-context.js`, `lesson-folders.js`, `lesson.js`: 기존 선택 기록·폴더 저장 재사용, 목표/목적/요구의 개인 기록과 폴더 공통 목표·자료별 역할·저장 당시 인용 표.
- `server/link-proposals.js`, `public/link-proposal.js`, `public/admin-link-proposals.js`: 별도 명시적 제안 접수/원문 대조·관리자 검토 연결. 원문/승인 정본을 수정하지 않는다.

## 검증 결과

[통합8검사](r12-curriculum-goal-check.json)와 [기존 결합20검사](r12-curriculum-goal-legacy-check.json)가 통과했다. 과거 한정1→새 우선3(관련1/확장2) 합성 사례, 확인 기록0, 임의 요구/인용·다른 송신원·개인 필드 거절, 중복 제안 방지·관리자 인증/검토/승인 상태 분리, 목표 입력의 실제 모드 전환, 개인 목표/역할 저장, 명시적 제안 미리보기/제출, 폴더 목표 수정/재열기·390px을 확인했다. 실제4저장소 SHA 동일·페이지 오류0·유료 호출0이다. 관리자 신규 제안은 임시 복제 서버에만 제출했고 운영 DB에 테스트 제안을 남기지 않았다.

[실제3000 확인](r12-curriculum-goal-running-check.json)에서는 자석+자전 기준이 한정0→우선2(둘 다 연계 미확인 확장), 자전+자전 기준은 관련3을 제공했다. 범위를 구분하는 동작 확인이며 관련성/효용 향상 수치가 아니다. [목표 입력 모바일](r12-curriculum-goal-search-mobile.png)과 [폴더 모바일](r12-curriculum-goal-folder-mobile.png)에 목표/역할/근거/추가 활동을 기록했다.

CG-01~08의 기능을 적용했다. CG-09의 실제 교사 선택/반복 사용·새 독립 평가와 교실 활용은 미완료다. 데이터 공백/검색 의미 품질·보조자료 전량 사람 확인을 이번 기능 검사로 완료 처리하지 않는다. R12-03의 전체 공통 검색 과제와 R12-06의 실제 사용자 검증은 유지한다.

## 저장 구조

기존 개인 브라우저 저장 키를 유지한다. 선택 기록에 curriculumVersion/goalRequirements/usePurpose와 기존 lessonGoal/usePart를 보존하고 폴더에 lessonGoal을 추가한다. 과거 기록의 없는 값은 빈 값으로 복원한다.

`server/data/link-proposals.sqlite`는 요청자가 명시 제출할 때 사용하는 별도 접수 DB로 Git에서 제외한다. proposals의 id(PK)는 동일 영상/기준/원문 지문/요구/인용/이유의 해시, status는 PENDING/IN_REVIEW/REJECTED, created_at·record(JSON)에는 공식 출처/판본/정확한 인용·확인 시점·미확인 범위를 기록한다. 이것은 승인 정본이 아니다. 기존 관리자 관계 결정/자산/이력 경로를 재사용하고 접수만으로 공용 검색·승인을 변경하지 않는다.

- [ ] 관리자 제안 목록→기존 관계 검토 동선을 확인한다. 실제 승인에는 별도의 원문/기준 확인이 필요하다.
