# Curi 두 번째 스타일가이드 — B / 발견의 장면

버전 B 0.1 · 2026-10-15 · **비교용 제안 / 운영 미적용**

[그리드·인터랙션 비교 시안](../grid-interaction.html)

[전체 시안](index.html) · [토큰 CSS](tokens.css) · [토큰 JSON](tokens.json) · [관찰 기록](reference-observations.json) · [A안 가이드](../CURI_STYLEGUIDE.md) · [A안 시안](../curi-styleguide.html)

Curi를 **자료에서 수업의 장면을 발견하는 도구**로 표현한다. 어두운 무대 위의 큰 문장과 원형 신호로 탐색을 시작하고, 아이보리 면에서 소개문·근거·시간을 읽는다. A안의 녹색을 어두운 색으로 바꾸는 수준을 넘어 타이포 위계, 화면 대비, 박스 구성, 로고의 인상을 함께 바꾸는 별도 안이다.

기존 A안 원본, 현재 웹·확장0.5.0, 로고·개인 기록은 수정하지 않는다. 이 폴더의 HTML은 가상 자료로 동작하는 독립 시안이다. 서버 API·localStorage·chrome.storage·영상 플레이어를 사용하지 않는다. 시안의 저장은 메모리에만 반영되며 새로고침하면 사라진다.

## 1. 참고 관찰과 적용 해석

참고: [Illuminating Radioactivity — Page 5](https://illuminating-radioactivity.com/5/?ref=httpster.net). 2026-10-15 Chrome에서 지정 페이지의 처음 화면·스크롤·오른쪽 원형 메뉴 열기/닫기·390×844 화면을 직접 관찰했다. 웹 텍스트 도구는 페이지를 읽지 못해 브라우저로 확인했다. 메뉴를 통해 다른 장 전체를 탐색하거나 터치 실기기·음성·영상 조작을 검증하지는 않았다.

| 실제 관찰 | B안으로 해석 | 채택 범위 |
| --- | --- | --- |
| 검정 바탕과 흰 큰 문장, 밝은 다음 구간 | 어두운 탐색 헤더 + 밝은 읽기/입력 패널 | 화면 대비와 정보 위계 |
| 포스터 3열과 둥근 이미지 모서리 | 자료를 구분하는 편집형 프레임 | 실제 확인된 이미지가 있을 때만 표시 |
| 흰 원 안의 메뉴 아이콘, 색 원 안의 장 번호 | 원형 섹션 번호·짧은 상태 신호 | 주요 메뉴 이름은 글자로 계속 표시 |
| 녹색·주황·분홍·파란 장 구분 | 살구·라일락·연두의 절제된 포인트 | 주요 행동·교과/상태 역할을 고정 |
| 큰 산세리프 본문, 좁은 고정폭 캡션 | 한국어 산세리프 + 시간·번호용 mono | 장문의 고정폭 한국어 사용 금지 |
| 스크롤에 따라 흑백 구간과 자료가 이어짐 | 큰 구역 간 리듬·짧은 전환 | 강제 스크롤·스크롤 가로채기 없음 |
| 관찰한390px 화면의 콘텐츠 일부 가로 잘림 | 모바일은 별도로 세로 재배치 | 원본의 가로 넘침을 복제하지 않음 |

관찰한 계산 스타일에 `custom_19789`, `custom_20744`, `Share Tech Mono`, `Roboto`가 나타났다. 앞의 두 이름만으로 공식 글꼴명을 추정하지 않는다. 큰 본문의 DOM 글자값 일부는22/28/42/100px였으나 변형·배치 영향을 포함한 시각 크기와 같다고 단정하지 않는다. B안의 아래 글자 크기는 새 설계값이다.

원본 메뉴·로고·원자 도상·포스터·글꼴 파일·문구를 Curi 자산으로 가져오지 않는다. 브라우저에서 관찰한 색도 그대로 브랜드 토큰으로 사용하지 않는다. 원자력·위험을 암시하는 기호를 Curi 로고로 사용하지 않는다. B 시안의 자료 이미지는 CSS·문자로 그린 추상 예시이며 실제 EBS 썸네일이 아니다.

## 2. A/B 선택 기준

| 항목 | A / 조용한 수업 작업공간 | B / 발견의 장면 |
| --- | --- | --- |
| 첫인상 | 밝고 담백한 업무 공간 | 선명하고 편집적인 콘텐츠 공간 |
| 주요 바탕 | 따뜻한 흰색 | 차콜, 읽기 영역은 아이보리 |
| 브랜드 색 | 짙은 녹색 | 살구색 행동 + 라일락 보조 |
| 제목 |36px 중심의 차분한 위계 | 브랜드 제목72px, 작업 제목32–36px |
| 카드 | 선·여백 중심, 색 차이 최소 | 상단 시각 프레임 + 밝은 근거 면 |
| 버튼 | 짙은 녹색 주 행동 | 어두운 면은 살구, 밝은 카드 안은 검정 |
| 로고 | 소문자 워드마크·열린 c와 연결점 | 대문자 CURI·열린 사각 프레임과 중심점 |
| 확장 | 밝은 배경을 유지 | 어두운 브랜드 헤더 + 밝은 조작부 |
| 더 어울리는 우선순위 | 익숙함·반복 업무·시각적 절제 | 자료 발견·콘텐츠 존재감·기억되는 인상 |
| 적용 시 주의 | 중요 상태가 지나치게 약하지 않도록 | 어두운 면의 장문·색상 과잉·대형 제목의 공간 점유 |

둘 다 사회·과학 동등 범위, 자연어 검색, 소개문·근거 확인, 교육과정→폴더의 두 단계 가져가기와 위치별 기록 계약은 같다. 시안의 작은 A/B 카드도 같은 자료를 사용한다. A안 상세 시안과 B안 전체 웹·확장 화면을 함께 보고 결정한다. B안이 검색 품질·교사 효용을 높였다는 실측은 없다.

선택 시에는 ‘어느 쪽에서 제목과 근거가 먼저 읽히는가’, ‘가져갈 위치를 바로 찾을 수 있는가’, ‘확장에서 시작·끝·저장 결과를 구분할 수 있는가’를 같은 과제로 확인한다. 아직 사용자 선택은 확정되지 않았다. 혼합안을 원하면 로고·타이포·색·컴포넌트의 역할을 다시 정리하고 적용한다.

포인트 색은 화면의 주인공 전체를 칠하는 배경이 아니라 행동·분류 신호다. 같은 화면의 강조색은 최대3개 범주로 제한한다. 자료마다 무작위 색을 붙이지 않는다. 교과와 확인 수준은 분리한다. 사회 살구색이 가져가기 가능성·사람 확인을 뜻하지 않으며, 과학 라일락이 과학적 정확성의 인증이 아니다. 성공의 연두색도 저장 완료만 뜻한다. 반드시 상태 문구를 함께 쓴다.

일반 글자4.5:1·큰 글자3:1, 입력 경계와 포커스3:1을 점검한다. 실제 계산은 [contrast-checks.json](contrast-checks.json)으로 제공한다.17개 조합이 목표를 통과했다. 구분선은 장식이며 대비 통과를 입력 식별의 근거로 쓰지 않는다. 이 계산은 완전한 WCAG 감사를 대신하지 않는다.

한국어는 시스템 산세리프(`Apple SD Gothic Neo`, `Malgun Gothic` 등), 숫자·영문 라벨은 시스템 `ui-monospace`를 사용한다. 시안은 외부 폰트 접속이나 설치 없이 열린다. 추후 별도 글꼴을 택하면 공식 배포·라이선스·자체 호스팅 여부를 함께 확정한다. 원본의 익명 custom font를 추출하지 않는다.

한국어 대형 제목 자간은 약−1px, 본문은 기본값을 권장한다. 제목이 길면 줄바꿈하고 필수 의미를 잘라내지 않는다. 영문 장 이름을 한국어 메뉴 대신 쓰지 않는다. 영문 라벨을 줄여도 기능 이름은 유지한다.

웹 바깥 컨테이너 최대1360px(border-box), 바깥 여백48px→24px→16px. 12/8/4열과 카드3/2/1열을 제안하며 정확한 계산과 구간 점유는 11절을 따른다. B 전체 시안에도 자료 3/2/1열과 소개 8+4열을 반영했으며 공간/장 전환은 별도 비교 시안에서 확인한다. 본문 문단 폭은 약60자 이내를 권장한다. 확장은 여백을 포함해360px, 내부16px다.

간격은4/8/12/16/24/32/48/64/96px. 웹 큰 구간64px, 모바일40px, 카드 내부20–24px, 카드 간16px, 입력 라벨8px, 확장 구간24px. 어두운 여백이 읽기 내용을 과도하게 밀어내지 않도록 검색 후 브랜드 제목은 접거나 줄이고 현재 입력·결과·조건을 남긴다.

## 5. 박스·버튼·입력·상태

| 요소 | 기본 형태 | 상호작용 |
| --- | --- | --- |
| 웹 읽기 카드 | 아이보리, 반경20px, 그림자 없음 | 제목/프로그램→소개/근거→원문/가져가기 |
| 이미지·시각 프레임 | 반경20px 바깥 카드에 맞춤 | 실제 이미지 없으면 중립 프레임, 콘텐츠를 만들어내지 않음 |
| 확장·작은 패널 | 반경12–16px | 스크롤 가능한 읽기 영역 |
| 대화상자 | 아이보리, 반경20px, 최대480px | 출처·선택·실패 메시지는 불투명 면에 표시 |
| 입력·일반 버튼 | 반경8px,1px 식별 경계 | 최소44×44px, 입력48px 권장 |
| 주요 버튼 | 어두운 면 살구+검정 글자 | hover 밝은 살구, pressed 최대1px 이동 |
| 카드의 가져가기 | 검정 면+아이보리 글자 | 카드의 밝은 면에서 가장 강한 행동 |
| 보조 버튼 | 투명/읽기 면+식별 경계 | hover 중립색, 주요 버튼과 구분 |
| 선택 폴더·범위 | 대비 반전 + aria-pressed/current | 색 외에도 이름·현재 상태 제공 |
| 장 번호·짧은 분류 | 원형 또는 pill | 장식·안내이며 버튼으로 오인시키지 않음 |

일반 카드에 강한 그림자·글로우·노이즈·블러를 넣지 않는다. 그림자는 모달에만 제한한다. 참고 사이트의 질감이나 빛 표현은 큰 브랜드 시각 영역에서만 고려하고 본문/입력 뒤에는 사용하지 않는다. 로고와 상태점은 움직이지 않는다.

버튼은 기본/hover/focus/pressed/disabled/loading/selected/success/error를 구분한다. 저장 중에는 동일 버튼이 ‘가져오는 중’으로 바뀌고 중복 실행을 막는다. disabled는 인접 설명으로 사유를 제공한다. 오류는 색뿐 아니라 실패 사유와 재시도를 표시하고 입력을 보존한다. 예시 disabled 버튼은 상태 비교용이며 실제 요청을 실행하지 않는다.

## 6. 웹 화면과 동선

**탐색.** 워드마크와 자료 찾기/내 수업 자료를 고정된 주요 경로로 둔다. 원본의 원형 메뉴를 그대로 숨김 메뉴로 옮기지 않는다. 모바일에서도 기능 이름을 보여준다. 대형 브랜드 문장은 처음 탐색에 쓰고 검색 이후에는 작업 공간을 우선한다.

**자연어 검색.** 넓은 질문 입력과 한 개의 주요 검색 버튼. 현재 질의·제외 조건·정렬·전체 결과 수를 읽을 수 있어야 한다. 교육과정 선택을 검색 필수 단계로 만들지 않는다. 로딩 중 기존 결과·입력 유지, 늦은 이전 응답 무시, 빈 결과 원인·직접 조건 수정·재시도를 유지한다. B시안은 가상3자료의 단순 제목/설명 검색이며 제품의 의미 검색 품질 시연이 아니다.

**자료 카드.** 실제 자료의 제목→프로그램·날짜·소개문 상태→원문 인용/요청의 연결 이유→남은 확인→원문/가져가기. 원문 인용과 요청 해석을 각각 표시한다. 가상 시안은 인용도 가상임을 명시한다. 실제 EBS 썸네일이 없으면 무관한 사진이나 추정 장면을 생성하지 않는다. 출처 부족·시간 미확인·학년 적합성 미확인을 밝은 면에 분명히 표시한다. 반투명 덮개로 근거를 숨기지 않는다.

**가져가기.** 현재 계약대로1/2교육과정 선택 또는 선택 안 함→2/2폴더 선택·새 폴더 이름→마지막 가져가기. 원 두 개와 글자 단계를 함께 쓴다. 이전으로 돌아가도 선택과 입력 유지. 자료 제목·대상 폴더·선택 기준 수를 마지막 화면에 재표시한다. 선택만으로 저장하지 않는다. 빈/중복 폴더 이름·조회 실패·저장 실패는 해당 입력 근처에 표시한다. 실제 저장 확인 뒤 위치를 포함한 완료 문구. 시안은 빈 이름 검증·중복 자료의 동일 폴더 재추가 방지만 구현하며 폴더명 중복 정책·실제 저장 실패는 운영 계약을 따른다.

**내 수업.** 전체/수업 폴더/폴더 미지정의 위계를 유지한다. 폴더 탐색은 어두운 면, 자료·개인 메모는 밝은 면을 권장한다. 위치별 교육과정·목표·메모·선택 이유·구간을 합치지 않는다. 전체 보기의 자료가 어느 위치에 있는지 명확히 표시하고 복사/이동/삭제의 적용 위치를 안내한다. 시안은 현재 세션의 가상 가져오기 결과만 보여주며 기존 기록·이동·삭제·내보내기를 구현한 것이 아니다.

## 7. Chrome 확장 프로그램

어두운 헤더에 심볼·CURI, 밝은 몸통에 현재 영상·저장 위치·전체/구간·시간 입력·저장 결과를 둔다. 메타13px, 본문14px, 회차 제목20px. 원형점은 연결 상태의 보조이며 연결됨/연결 필요 문구가 정본이다.

순서는 **현재 영상 → 대상 폴더 → 영상 전체 또는 영상과 구간 → 가져가기 → 확인된 결과**다. 영상 전체에서 구간 이름·시간을 강제하지 않는다. 프로그램/회차·지원 플레이어 계약은 기능에 따르며 디자인만으로 지원 범위를 확대하지 않는다.

## 9. 인터랙션·접근성·반응형

- 짧은 상태120ms, 모달220ms와 최대10px 이동. 로딩을 장식 애니메이션으로 숨기지 않는다.
- `prefers-reduced-motion`에서 이동·반복·부드러운 스크롤을 끈다. 내용은 항상 표시한다.
- 실제 button·input·label을 사용하고 최소44px 조작 높이를 지킨다. 원형 번호는 버튼이 아니다.
- 모달은 제목·현재 단계·초기 포커스·Tab 범위·Escape·닫은 뒤 호출 버튼 복귀를 제공한다. 모바일 높이를 넘으면 모달 내부 스크롤로 조작한다.
- 가상 저장·연결 결과는 `role=status`로 알린다. 실제 서비스에서는 저장 확인 결과만 성공으로 읽는다.
- 필드 오류는 라벨 근처의 문장과 연결하고 색 외에도 문구로 표시한다. 네이티브 선택과 키보드를 지원한다.
- 웹1440/1280/390/360, 확장360px과200%확대에서 읽기·저장을 확인하는 것이 적용 기준이다. 제공 검사 기록에 실제 확인한 크기·상태와 미확인 범위를 구분한다.

## 10. 산출물·확인·다음 선택

`index.html`, `preview.css`, `preview.js`는 비교용 화면이다. `tokens.json`/CSS는 B전용 토큰, SVG5개는 B전용 로고다. `reference-observations.json`, `contrast-checks.json`, `preview-checks.json`에 관찰·계산·기술 확인을 남긴다. 로컬 파일로 열거나 이 폴더를 정적 서버로 제공하면 된다. 웹4크기 가로 넘침0·시안 상태12검사(모션은 정적 규칙 확인)를 기록했으며 브라우저 자체200%확대·실제 확장 저장·스크린리더·교사 효용은 미확인이다. 외부 CDN·실제 계정·키가 필요 없다.

검토 순서: **01 A/B비교 → 02 컬러/타이포/컴포넌트 → 03 웹 검색과 가져가기 → 04 확장 전체/구간/실패 → 05 로고 크기**. 데스크톱과 모바일을 각각 보고 판단한다. 좋은 인상과 실제 업무 효율은 구분하며 실제 교사 검증을 완료로 표시하지 않는다.

이번 결과는 두 번째 선택지 제공이다. 사용자가 A/B 또는 조합 방향을 결정하면 선택한 체계를 별도 구현 task로 적용한다. 현재 운영 화면·설치 확장·A안 원본을 자동으로 바꾸지 않는다.

### 원본의 그리드 해석

Illuminating Radioactivity5페이지의1440×960 화면에서 포스터는 약 `(x44,y394,w316,h603)`, `(x449,y394,w316,h602)`, `(x851,y394,w316,h602)`에 있었다. 위쪽 모서리 y394를 맞추고, 이미지 사이 약89/86px의 넓은 간격과 오른쪽 메뉴 여백을 남긴 **편집형3열 구성**이다. 전체 폭을 같은 카드로 가득 채우는 대시보드와 다르다.

실제 DOM에서는 이미지 위젯이 `position:absolute`,1440px의 상대 컨테이너 안에 배치되어 있었다. 이는 고정 좌표를 가진 편집 캔버스 관찰이지 원본이 네이티브12열 CSS Grid를 쓴다는 증거가 아니다. 상단 큰 문장·포스터·작은 연도 캡션이 각자의 수평 기준선을 공유하며, 모든 요소의 폭이 같지는 않다.

오른쪽 원형 메뉴를 열면 약x948부터 검은 덮개가 나타나고 장 이름은x1029 부근에서 시작한다. 메뉴가 열린 채 스크롤하면 밝은 장과 큰 인물 이미지·겹친 컬러 설명 카드가 뒤로 지나갔다. 작은 카드가 겹쳐 보였다는 관찰만으로 드래그/스와이프 동작을 확정하지 않는다. 메뉴의장 2 링크는 실제로 `/5/`에서`/12/`로 이동했다. 따라서 원본 장 탐색은 단순한 같은 페이지의 펼침이라고 설명하지 않는다.

앞선390×844 관찰에서는 문서폭769px과 가로 잘림이 나타났다. Curi B는 원본의 고정 좌표·겹침·장식 비례를 모바일에 복제하지 않고 **큰 문장→이미지/자료→캡션의 순서와 구간의 리듬**을 유지하면서 재배치한다.

| 확장 |360px 독립1열, 어두운 헤더/밝은 조작부 | 큰8/4구도를 축소하지 않음; 시간2열, 필요 시1열 |

큰 제목은 항상8열에 고정된 채 글자가 잘리는 방식으로 구현하지 않는다. 텍스트 실제 길이와 읽기 순서를 우선한다. 본문을 아이보리 면으로 바꿔도 열 기준선과 캡션 위치는 유지한다. 프레임/읽기/번호의 서로 다른 크기가B의 리듬이며 무작위 masonry나 무한 가로 캐러셀은 제안하지 않는다.

원본 메뉴가 열린 상태의 Escape로는 닫힘을 관찰하지 못했고, 배경도 스크롤되었다. Curi의 ‘단계 메뉴’는 배경 조작 차단·Escape·포커스 복귀를 추가하여 읽기 문맥을 보존한다. 원본 결함이나 불확실한 동작을 그대로 브랜드 요소로 채택하지 않는다.

원본의 전환 시간·easing·스크롤 애니메이션 발동 구간은 프레임 단위로 측정하지 않았다. 이 절의 120/180–220ms, 10px은 Curi 설계값이다. `prefers-reduced-motion`은 이동/전환을 0ms로 하고 구간 내용을 즉시 보여준다. 시안의 장 전환은 선택 시점의 전환이며 원본의 전체 스크롤 서사를 재현했다고 표시하지 않는다.

### A와의 비교 관점

A는 **같은 작업공간에서 목록과 근거에 자리를 나누어 주는 전환**,B는 **자료→근거→정리의 구역과 크기 대비로 리듬을 만드는 전환**이다. 둘 다 입력과 자료를 지키는 기능 계약은 같다. [비교 시안](../grid-interaction.html)에서 같은 가상 자료로 열 표시·근거 패널·단계 메뉴·모바일 재배치를 비교할 수 있다. 이 차이를 현재 제품 적용이나 업무 효율 개선 실측으로 해석하지 않는다.


## Chrome 사이드 패널 적용 기준 — R12-14

확장0.6.0은 아이콘 아래 임시 팝업 대신 Chrome 사이드 패널을 사용한다. 기본 문서는 기존 `popup.html`이며 `side_panel.default_path`로 열린다. 웹페이지 옆의 세로 작업 공간으로 화면 전체 높이를 사용하고 내부를 독립 스크롤한다. 본문 클릭 시에도 패널을 유지한다. 오른쪽 배치와 폭은 Chrome 사용자 설정/조작을 따른다. 360px은 비교 시안의 기준 폭이며 실제 폭을 고정하거나 좌우 비율을 강제하지 않는다. 좁은 폭에서는 시간 입력/현재 시간 버튼을 한 열로 바꾼다.

선택한 EBS 페이지가 저장 대상이며 다른 탭을 눌렀다고 대상을 자동 변경하지 않는다. 페이지 이동/닫힘 시 이전 영상의 저장과 시간 읽기를 잠그고 ‘열린 영상 목록 새로고침’으로 재확인한다. 영상별 초안·폴더 선택·기존 저장 결과는 보존한다. 이 기준은 확장 표시 방식의 공통 변경이며 디자인안 선택을 뜻하지 않는다. 3/4안의 확장 시안은 왼쪽 가상 영상 영역/오른쪽 세로 패널 배치를 보여 준다. 작은 화면에서는 비교를 위해 위아래로 쌓이며 실제 데스크톱 Chrome 배치와 구분한다.
