## 검색과 시맨틱 레이어

- 기존 3개 장소 관계를 유지하면서 사회·과학 편집 개념을 60개로 확장했다. 원문 태그는 1,668개(과학 995·사회 444·공통 229), 원문 태그가 있는 대표 자료는 1,496개다. 상위 개념 추론 후보 179개는 별도로 저장하고 기본 검색의 직접 근거로 사용하지 않는다. 전체 22,118개 자료를 모두 상세 태깅한 상태가 아니다.
- 원문 태그마다 필드·구절·오프셋·출처·확인일·내용 지문·규칙 버전을 보존한다. 프로그램명·휴리스틱 seed만으로 원문 근거를 만들지 않는다. 초기 42개념·1,491언급·125추론은 [이전 빌드](semantic-before-language.json), 최신 `.2`는 [현재 빌드](semantic-build.json)로 구분한다.
- “설악산 또는 김제”는 일반어에도 OR, “해안 지형 제외하고 우주”는 복합 제외 전체, “김제 5분 이내”는 김제 검색과 재생시간 미확인으로 처리한다. AND는 각 OR 분기 안에서 유지하며 제외한 표현을 긍정 개념·지리 조건에 다시 넣지 않는다.
- “고조선이나 삼국시대 유물 발굴”처럼 알려진 표현 사이의 붙여 쓴 선택은 `(고조선 OR 삼국시대) AND 유물 AND 발굴`로 처리한다. “명의 같은”은 선호, “명의에서”는 필수 프로그램이다. 임의의 한국어 문법·중첩 괄호 전체를 해석하는 파서는 아니다.
- 수업 도입·요청 어미를 내용어에서 분리하고 시간·학년·자막·폭력/수술 장면·자연 촬영 조건은 미확인으로 표시한다. 원문에 요청한 관계 표현이 있어도 `RELATION_NOT_VERIFIED`를 유지한다. 심장 비유·화석 인명·4·19 숫자 오탐은 관측한 범위의 제한된 규칙으로 보강했다.
- 화면은 자료 목록을 먼저 표시하고 소개·추천 이유·원문 근거를 접힌 설명에서 보여준다. 자료 모음·재접속·메모 다운로드와 현재 링크 갱신을 보존했다.
- `GET /api/curi/discover/context`는 최대 6자료·직렬화 24,000자에 근거·추론 후보·미확인 조건을 담는다. 글자 수는 모델 토큰 수와 다르다. 유료 모델 호출·관계 추론 검증은 R10 후속 범위다.

디스크 시맨틱 SQLite는 감사·재현용 스냅샷이다. 런타임은 같은 규칙의 메모리 태그와 카탈로그별 최대 8개 질의 결과를 캐시한다. 원본 파일 변경 시 새 카탈로그를 만들며 디스크 스냅샷은 다시 빌드해야 한다. 그래프 DB·새 임베딩·범용 모델을 연결했다고 표현하지 않는다.

## 문서와 분담

기존 52개 task는 [대응표](TASK_REDESIGN_MAP.md)에서 빠짐없이 보존·통합·이월했다. 사회·과학 수집/검색을 소량 사람 검수와 유료 모델 선정 뒤로 미루던 의존 관계를 정리했다. R04 검색 결함과 R05 긴 요청 해석을 분리했고 R09는 진행중으로 유지한다. 사람 확인 체크는 채우지 않았다. 계획안 섹션과 통합 PLAN, 실제 구조 ERD, AGENTS/ARCHITECTURE를 맞췄다.

주 에이전트는 수집·질문 해석·검색·시맨틱·화면·통합 검증과 공용 문서를 담당했다. Luna 테스트 담당은 회귀/교사 검사와 전후 JSON, Luna 문서 담당은 R04/R05 task·SEARCH_QUERY_FIXES만 담당했다. 별도 R09 세션의 quality 검사·원문감사 산출물은 보존하고 공용 파일 수정 중단 통신 이후 주 에이전트가 통합했다.

## 재현

Node.js 24.18 이상, 저장소 루트에서 실행한다. 아래 오프라인 검사는 서비스 유료 API를 호출하지 않는다. `.env` 키를 읽을 필요가 없다.

```sh
node server/semantic-build.js
node server/semantic-check.js
node server/query-regression-check.js --phase=after
node server/teacher-query-check.js --phase=after
node server/quality-gates-check.js
node server/subject-scenarios-check.js
node server/classroom-scenarios-check.js
node server/broadcast-check.js
node server/source-links-check.js
node server/discovery-check.js
```

`quality-gates-check.js`는 고정 카탈로그와 현재 디스크 빌드를 대조한다. 이후 수집·원문·규칙이 달라지면 불일치가 예상되므로 같은 스냅샷을 명시적으로 빌드하거나 새로운 평가 스냅샷을 별도 준비한다. 기존 before 보고서는 덮어쓰지 않는다.

로컬 서버는 `CURI_ALLOW_PAID_API=false PORT=3317 node server/server.js`, 주소는 http://127.0.0.1:3317/ 이다. Playwright를 사용할 수 있는 환경에서 `node server/discovery-browser-check.mjs`, `node server/semantic-browser-check.mjs`를 실행한다. 설치 위치가 별도이면 `CURI_PLAYWRIGHT_MODULE`, 사용할 Chromium 실행 파일은 `CURI_BROWSER_EXECUTABLE`로 지정할 수 있다. 이번 검증은 설치된 Chromium headless shell 1228을 사용했다. 처음 기본 실행에서 요구한 1234 바이너리가 없어 시작하지 못했으며, 기존 바이너리를 지정한 실제 재실행 14+10개가 통과했다.

`node server/quality-source-samples.mjs --annotate-only`는 저장된 GET 결과로 판단 부분만 재생성한다. 네트워크 없는 재생성을 새로운 원문 도착 확인으로 세지 않는다. 방송 재수집은 별도 명시적 작업이며 위 검사 명령에 섞지 않는다.
