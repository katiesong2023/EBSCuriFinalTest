# Curi 개발 정리

- 작성 기준일: 2026년 10월 16일
- 프로젝트: EBS_Curi / 서비스 브랜드: EBS CURI
- 참가 대회: 2026 EBS AI Innovation Challenge
- 신청 부문: 트랙1 — 바로 쓰는 에이전트(Now Agent), 사용자 확인
- 문서 목적: 지금까지의 개발 과정, 현재 구현, 검증 결과와 한계를 정리하여 제출 보고서·시연 준비의 기초 자료로 사용한다.

이 문서는 저장소의 구현·검증 기록을 종합한 개발 현황 문서다. 최종 제출 보고서나 전체 기능의 사용자 승인 완료 기록은 아니다. 현재 상태의 정본은 [PLANS](PLANS.md)이며, 본 문서 작성 중 제품 실행·데이터 재집계·신규 성능 평가는 수행하지 않았다. 아래 수치는 명시한 작업 시점의 기록이다.

## 1. 서비스 개요와 개발 목적

Curi는 EBS 콘텐츠의 교육 메타데이터를 구축하고, 이를 교사의 수업 자료 탐색과 재사용에 연결하는 웹서비스 MVP다. 공개된 프로그램·회차의 텍스트 메타데이터와 공식 교육과정을 활용하여 관련 자료와 교육과정 연결 후보를 찾고, 원문 근거를 확인하며 수업 폴더·노트·영상 구간으로 정리하는 흐름을 구현했다.

해결하고자 하는 문제는 다음과 같다.

- EBS 방송 아카이브를 수업 주제와 교육과정에 맞춰 활용하려면 프로그램·회차를 찾아보고 교육과정을 별도로 대조해야 한다.
- 제목·소개문 등 공개 메타데이터의 정보량이 달라, 제목 검색만으로는 자료 내용과 활용 가능성을 판단하기 어렵다.
- 찾은 영상의 활용 장면과 선택 이유를 매번 다시 확인하지 않도록 개인 수업 자료로 축적할 필요가 있다.
- 자동으로 생성한 교육과정 연결 후보와 실제 사람이 확인한 관계를 구분하고, 원문 변경 시 근거를 다시 점검해야 한다.

이 문제 정의는 개발 배경이다. EBS 내부 업무의 실제 소요시간이나 교사의 시간 절감률을 현장 조사로 확정한 결과는 아니다.

## 2. 서비스 구성

| 구성 | 역할 | 현재 구현의 성격 |
| --- | --- | --- |
| Curi | 교사의 자료 탐색·원문 확인·수업 자료 저장·구간 활용 | 로컬 웹 화면과 Chrome 확장프로그램 |
| CuriMap | 콘텐츠와 공식 교육과정의 연결 후보·근거 생성 및 검토 | 로컬 규칙·원문 대조·자동 검사와 선택적 사람 검토 |
| CuriBase | 콘텐츠 원천 정보와 재사용 가능한 메타데이터 관리 | 방송·시맨틱·자동 자산·기존 승인 저장 경로를 구분한 저장 구조 |

CuriBase의 모든 자료가 사람 검수를 마친 자산이라는 뜻은 아니다. 원천 등록, 자동 후보, 자동 검사 통과, 실제 사람 승인은 서로 다른 상태다. 교사의 개인 폴더·메모·구간 역시 공용 승인 자산과 분리한다.

## 4. 현재 구현된 주요 기능

### 4.1 공식 원천 수집과 설명 보강

- 공식 EBS 공개 목록·상세 페이지 등에서 프로그램·회차 식별자, 제목, 소개문, 링크, 방송일 등 텍스트 메타데이터를 수집한다.
- 수집 체크포인트, 출처, 확인 시점, 원문 지문과 변경 이력을 관리한다.
- 공식 보도자료 등 보조 설명은 해당 회차의 제목·식별·시기 등을 대조하여 연결한다.
- 원문 부족, 제목 반복, 다른 회차 도착 등 품질 문제를 구분한다. 제목·프로그램 기반 안내는 공식 내용 설명과 구분하여 표시한다.
- 소개문과 검색 인용의 위치·판본을 대조하고, 원문 변경에 따른 오래된 근거를 점검한다.

2026-10-15 전체 점검 기록은 콘텐츠·판본 23,403개를 대상으로 한다. 빈 소개 13,085개와 오류 의심 533개, 합계 13,618개 중 11,627개에 실제 내용 설명을 보충했다. 남은 1,991개는 내용 미확보로 기록했다. 이 분모에는 목록 자료 등이 포함되므로 방송 고유 회차 수로 표현하지 않는다. 앞선 설명 보충 작업과도 대상이 겹치므로 합산하지 않는다.

NEWS 클립 76건은 수집 이력이 있으나 2026-10-15 사용자 요청으로 공용 원천·검색에서 삭제했다. 현재 제공 실적에 포함하지 않는다.

근거: [원천 보충 task](../Tasks/task-r12-02-source-coverage.md), [소개문 재점검 결과](R12_DESCRIPTION_RECHECK.md).

### 4.2 주제·자연어 자료 탐색

- 교사가 주제·질문을 입력하여 EBS 자료를 탐색한다.
- 주제, 자료 유형, 프로그램, 기간 등 조건과 관련도·방송일 정렬을 제공한다.
- 요청의 내용어와 이용 대상·활용 목적·조건을 구분하고, AND/OR·제외·프로그램 조건 등을 로컬 규칙으로 처리한다.
- 소개문·내용 키워드·원문 근거를 제공하고, 다른 회차나 단순 배경 언급이 검색 근거로 섞이는 문제를 개선해 왔다.
- 관련 목록 자료는 개별 영상과 구분하여 별도로 펼쳐볼 수 있게 했다.
- 미확인 장면·시간·학년 적합성 등을 확인된 사실처럼 표시하지 않는다.

현재 일반 탐색은 원문과 편집 어휘·로컬 규칙 중심이다. 기존 승인 자산 검색에는 별도 임베딩 경로가 있으며, 이를 전체 방송 탐색에 적용된 범용 의미 검색의 완성으로 설명하지 않는다. 검색 누락과 무관·부분 관련 후보는 남아 있다.

### 4.3 공식 교육과정과 자료 연결

| 이용 범위 | 사회 | 과학 | 합계 |
| --- | ---: | ---: | ---: |
| 초등3~4 | 22 | 51 | 73 |
| 초등5~6 | 27 | 51 | 78 |
| 중1 참고 | 37 | 26 | 63 |
| 합계 | 86 | 128 | 214 |

공식 성취기준 214개와 73단원을 바탕으로 교육과정 조회·관련 후보·주제 필터를 제공한다. 중학교 공식 학년군은 1~3학년이며, 제품의 중1 참고 구성은 EBS 뉴런 편성을 참고했다. 학교별 실제 배치는 미확인이다.

현재 교사 화면에서는 주제·질문으로 자료를 먼저 찾고, **가져가기 또는 수업 폴더에서 교육과정을 선택적으로 연결**한다. 관련 후보와 전체 기준 보기를 전환하고 여러 기준을 고른 뒤 선택 완료·폴더 지정·저장으로 이어진다. 기준을 고르지 않아도 자료를 저장할 수 있다.

관련 기준 추천, 교사의 개인 연결, 기준 충족 검토, 영상의 수업 적합성은 각각 구분한다. 학년은 이용자 문맥이며 전체 수집을 제한하거나 자동으로 적합성을 보증하는 조건이 아니다.

### 4.4 내 수업 자료와 폴더

- 기존 내 자료와 수업 폴더를 `/lesson.html`의 내 수업 자료 화면으로 통합했다.
- 전체 자료, 폴더별 자료, 폴더 미지정 자료를 조회한다.
- 수업 목표, 폴더·자료별 교육과정, 개인 메모, 선택 이유와 구간을 관리한다.
- 저장한 자료를 제목·프로그램·폴더·교육과정·개인 기록으로 찾고 목록을 내보낸다.
- 같은 자료를 여러 수업에 활용하더라도 위치별 기록은 독립적으로 보존한다.
- 저장 실패 시 입력 유지·재시도, 다른 창의 변경과 미저장 편집의 충돌 방지를 제공한다.

개인 자료는 현재 브라우저 프로필과 접속 주소별 저장 공간에 보관한다. 사용자 계정별 서버 저장·기기 간 동기화는 아직 구현하지 않았다.

근거: [내 수업 자료 통합](R12_05_UNIFIED_LIBRARY.md).

### 4.5 Chrome 확장프로그램과 수업용 구간

작성 시 확인한 확장 버전은 **1.2.25**, Manifest V3 기반이다. 웹 프로젝트의 `package.json` 버전 `0.2.0`과 확장 버전은 별도 관리 값이다.

- Chrome 사이드 패널에서 지원 EBS 페이지의 원천 정보와 플레이어 시간을 읽는다.
- 기존/새 수업 폴더를 선택하여 영상·구간 정보를 Curi에 저장한다.
- 구간 이름, 시작·끝 시간, 메모를 저장하고 내 수업 화면에서 편집·재열기한다.
- 지원 플레이어에서 구간 시작으로 이동하고 끝 정지를 제어한다.
- 폴더별 수업 영상 리스트에 구간을 담고 드래그·버튼으로 순서를 바꾸며 합계 시간을 확인한다.
- EBS 로그인 안내, 원래 영상으로 복귀, 초안 보존, 본편 재확인과 확장 업데이트 안내를 보완했다.

구간은 원본 영상의 시간 북마크다. 영상 파일 추출·합치기·자동 연속 재생은 구현 범위가 아니다. EBS 로그인·시청 권한·플레이어 상태, 같은 Chrome 프로필의 Curi 탭 연결이 필요하며 실제 지원 확인은 지식채널e·다큐프라임 중심의 제한된 범위다.

근거: [구간 개발·실제 재생 기록](R12_07_SEGMENT_BOOKMARKS.md), [수업 영상 리스트 task](../Tasks/task-r12-15-lesson-video-playlist.md), [확장 manifest](../extensions/curi-segments/manifest.json).

### 4.6 관리자와 검토·승인

- 교사 화면과 관리자 화면·API의 접근을 구분하고 관리자 코드 인증을 제공한다.
- 자료·품질 관리, 교육과정별 확보 현황, 원문·근거 비교와 오류·변경 예외 처리를 제공한다.
- 자동 실행·검사·자산 저장·검색 준비 상태를 보존하고 재시도 경로를 구분한다.
- 선택적 관계별 사람 확인, 부분 수정, 결정·승인 자산 통합 저장 경로를 구현했다.
- 공용 연계 제안은 명시적 제출과 미리보기를 거쳐 별도 검토 접수로 기록한다. 개인 담기·메모 저장만으로 승인하지 않는다.
- 관리자 여섯 화면에 공통 색상·입력·표·메뉴·로고 스타일을 적용했다.

**현재 사람 승인 자산과 승인 검색 투영은 각각 0건이며 별도 자동 공개 1건을 유지한다.** 과거 사람 승인 4건은 2026-10-10 취소했고 원본과 결정·취소 이력은 보존했다. 자동 공개는 부분 근거의 자동 후보이며 사람 검수 완료를 뜻하지 않는다.

| 웹 화면 | HTML·CSS·JavaScript, 교사 자료 탐색·내 수업·관리자 화면 |

| 방송 원천 | `broadcast-catalog.sqlite`, 수집·원문·회차·링크 점검 이력 |
| 시맨틱 계층 | `semantic-layer.sqlite` 등, 개념·표현·원문 인용·판본·검색용 정보 |
| 자동 자산·검토 | 별도 SQLite 경로로 실행·관계·검사·자산·접수 상태 관리 |
| 기존 승인 경로 | JSON 기반 검수·결정·승인 자산·검색 투영 보존 |
| 개인 수업 자료 | 브라우저 저장소의 폴더·메모·기준·구간·리스트 |
| 확장프로그램 | Chrome Manifest V3, 서비스워커·콘텐츠 스크립트·사이드 패널 |
| 임베딩·모델 | 로컬 임베딩 경로와 제한된 유료 모델 비교 실험을 운영 검색과 구분 |

근거 관리의 핵심은 원문·인용 위치·출처·확인 시점·내용 지문·규칙/교육과정 판본을 함께 보존하는 것이다. 원문 표현의 존재, 교육과정 요구 충족, 실제 사람 확인, 링크 도착, 실제 영상 재생은 각각 별도 상태로 다룬다.

일반 탐색 런타임은 메모리 카탈로그·캐시를 사용하며 SQLite의 FTS와 시맨틱 스냅샷이 모든 요청을 직접 처리하는 구조로 단순화해 설명하지 않는다. 상세 저장 구조는 [ERD](ERD.md), 파일 책임은 [ARCHITECTURE](ARCHITECTURE.md)를 따른다.
