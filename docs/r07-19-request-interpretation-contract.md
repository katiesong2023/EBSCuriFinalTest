# 교사 요청 해석 계약

교사의 자유로운 질문을 검색 가능한 의미와 조건으로 바꾸는 계약이다. LLM은 요청을 해석하고, 검색 시스템은 원래 조건을 보존하면서 자료와 근거를 대조한다. 질문별 예외 규칙을 늘리는 대신 모든 질문에 같은 출력 구조와 검증 절차를 적용한다.

계약 버전은 `curi-request-v1`이다. 이번 범위는 요청 해석 구조, 책임 분담과 비호출 로컬 검증이며, 제품의 검색 API나 화면에 연결하는 단계는 포함하지 않는다. 계약 예시는 수작성 개발 자료다. 실제 LLM의 이해 정확도는 API 연결 후 별도로 측정한다.

## 입력과 출력

검색 시스템은 원래 질문과 현재 화면에서 선택한 조건을 입력 봉투로 전달한다. 질문 원문은 정규화하거나 덮어쓰지 않고 보존한다. 현재 검색 API의 200자 제한은 연결 단계에서 같은 기준으로 검사하며, 초과 입력을 몰래 자르지 않는다. 과거 대화는 현재 질문의 대상을 설명하는 데 필요한 범위만 별도 제공하고, 현재 발화와 구분해 출처를 붙인다. v1의 로컬 예시는 단일 발화만 대상으로 한다. 이전 발화를 참조해야 하는 요청은 해석 보류로 남긴다.

입력 봉투의 구조는 `input-envelope.schema.json`, 단일 발화 예시는 `example-input.json`에 있다. 이 입력 스키마의 기존 필터 값 검증은 연결 단계에서 현재 제품 검증기에 위임한다.

`lockedConditions`는 시스템이 소유한다. 예를 들어 선택 성취기준, 프로그램 필터, 날짜 범위를 LLM이 반환한 해석으로 삭제하거나 변경하지 않는다. 질문과 선택 조건이 충돌하면 충돌을 표시하고 사용자에게 해제를 요청한다. 현재 제품의 필터 이름과 값은 기존 입력 검증기를 통해 적용한다.

LLM 출력은 다음 항목으로 제한한다. 후보 ID, 원문 내용, 사람 승인, 교육과정 적합성은 요청 해석 출력에 넣지 않는다.

| 필드 | 의미 |
| --- | --- |
| `originalQuery` | 입력과 완전히 같은 원문 |
| `clauses` | 주제, 고유명, 관계, 지리 범위, 프로그램, 형태, 시간, 자막, 장면, 날짜, 대상, 교육과정, 목적 또는 기타 요구 |
| `mode` | `required` 필수, `excluded` 제외, `preferred` 선호, `context` 사용 문맥 |
| `sourceSpans` | 해당 의미가 나온 원문 구절과 위치. JavaScript와 동일한 UTF 16 시작 위치 포함, 끝 위치 제외 |
| `expression` | 필수와 제외 요구의 AND/OR 결합. 인접 복수 요구는 기본 AND, OR에는 원문 근거 필요 |
| `expansions` | 후보 발견을 돕는 다른 표현 또는 가설. 필수 조건을 대체하거나 새로운 필터를 만들지 않음 |
| `unresolved` | 모호하거나 해석하지 못한 구절, 이유, 확인 질문 |
| `grammarSpans` | 의미 조건으로 사용하지 않는 요청 문법과 표현의 원문 구절 |
| `status` | `READY`, `NEEDS_CLARIFICATION`, `UNRESOLVED` |

모든 비공백 문자는 의미 항목, 연결 표현, 해석 보류 또는 문법 구절에 포함한다. 문자열 위치 검사와 이 전체 기록으로 누락을 추적한다. 겹치는 인용은 허용한다. 동일 구절이 관계와 국내 범위에 함께 기여할 수 있기 때문이다.

형식이 올바르다고 의미도 올바른 것은 아니다. 예를 들어 ‘우리나라’를 문법 구절에 숨기면 전체 문자열 기록은 통과할 수 있다. 조건 누락·추가·강도 변경과 AND/OR 변경은 원문 대비 의미 검토가 별도로 필요하다. 로컬 검증에는 이와 같은 잘못된 해석을 포함했다.

## 책임 분담

| 일 | LLM | 검색 시스템 |
| --- | --- | --- |
| 질문 이해 | 주제·관계·조건·선호·문맥을 원문 구절과 연결 | 입력과 출력 원문 일치, 필드·참조·인용·누락 검사 |
| 고유명과 낯선 표현 | 모르는 이름을 보존하고 임의 분해·교정하지 않음 | 이름을 별도 검색 단서로 보존하고 미지원 요구를 기록 |
| 국내 조건 | ‘우리나라’를 필수 지리 범위로 해석 | 지역·국가 저장 근거로 대조. 국내라는 단어가 원문에 없어도 검증된 장소 연결을 활용 |
| 관계 요청 | ‘용암이 만든 지형’, ‘밤낮 활동 비교’를 의미로 표현 | 관계 요구를 검색 계획과 후속 후보 평가에 전달 |
| 다른 표현 | 검색용 표현 확장 제안 | 원래 질문·원래 주제와 함께 후보 발견에 사용. 확장은 충족 근거가 아님 |
| 필수·제외·선호 | 원래 강도와 부정 대상을 구분 | 조건의 강도와 논리를 실행·유지. 선호는 후보 탈락 조건으로 쓰지 않음 |
| 메타데이터 적용 | 데이터 지원 여부나 자료 충족 여부를 단정하지 않음 | 공식 기준·프로그램·형태·기간 등 현재 저장소와 지원 기능에 연결 |
| 불확실성 | 모호한 구절과 확인 질문을 반환 | 해석 보류·조건 미확인·빈 결과를 구분하고 조용히 조건을 완화하지 않음 |
| 자료 적합성 | 1단계에서는 판단하지 않음 | 후보 원문과 인용을 후속 평가로 전달. 실제 영상·학년 적합성·사람 승인은 별도 |

학년은 수업 문맥으로 처리한다. 질문이 학년을 명시해도 영상 적합성이 확인된 것으로 표시하거나 수집 대상을 제한하지 않는다. 공식 학년군, 중1 참고 편성, 학교별 실제 진도는 구분한다. 공식 성취기준이 요청되면 기준 범위를 해석하고, 실제 코드는 시스템이 공식 저장소에서 대조한다.

## 화산 지형 요청의 해석

사용자 질문은 ‘화산지형에 해당하는 우리나라 지역 수업자료’다.

| 원문 | 해석 | 강도 |
| --- | --- | --- |
| 화산지형 | 화산 지형이라는 내용 주제 | 필수 |
| 우리나라 | 국내 지리 범위 | 필수 |
| 해당하는 우리나라 지역 | 해당 지형의 지역 사례 | 필수 |
| 수업자료 | 수업 활용 목적 | 문맥 |

기대 논리는 ‘화산 지형 AND 국내 AND 지역 사례’다. ‘해당하는’과 ‘수업자료’를 회차 소개문에 반드시 등장해야 하는 단어로 요구하지 않는다. ‘우리나라’를 제거하거나 국내·해외 전체로 넓히지 않는다.

‘용암 지형’은 후보 발견을 위한 가설적 확장으로 제안할 수 있다. ‘한라산’, ‘제주도’를 사용자가 지정한 필수 지역으로 추가하지 않는다. 해당 지역과 화산 지형의 관계는 검색 시스템이 확보한 자료와 검증된 지역 정보에서 찾아야 한다. 화산 형성 과정 설명이 명시되지 않은 요청에 그것을 새 필수 조건으로 추가하지 않는다.

정확한 구조와 위치를 포함한 응답은 `example-output.json`에 있다.

## 검색 계획으로 넘기는 규칙

1. 형식·원문·위치·논리 참조를 검사한다. 실패한 응답은 검색 계획으로 채택하지 않는다.
2. 원문 대비 의미 보존을 검토한다. 실행 전 의미 검사는 일부 기계 규칙만으로 보장할 수 없으므로, 명시 조건 비교와 검토 표본을 함께 사용한다. 별도 모델 재검사만으로 정확성을 확정하지 않는다.
3. 시스템의 기존 선택 조건과 결합한다. 응답이 화면 조건을 변경할 권한은 없다.
4. 필수와 제외 요구를 지원 범위에 연결한다. 자료가 `MATCH`, `MISMATCH`, `UNKNOWN` 중 어느 상태인지 요구별로 기록한다. 제외 대상의 실제 부재가 확인되지 않으면 제외 충족도 `UNKNOWN`이다.
5. 검증 가능한 조건은 실행한다. 자료의 국내 범위가 불명확하면 국내 조건을 충족한 결과로 표시하지 않는다. 관계 의미·자막·장면 같은 미확인 조건은 원래 강도를 유지한 채 별도 기록하고 후속 평가로 넘긴다.
6. 확인 전 탐색 후보를 제공하는 경우 ‘모든 필수 조건을 충족한 결과’와 분리한다. 후보 발견과 최종 요구 충족을 같은 상태로 취급하지 않는다.

모호한 지명, 상충하는 필수 조건, 이전 발화 없이는 이해할 수 없는 지시어는 보류한다. 확인 질문이 필요 없는 미지원 조건은 ‘조건 미확인’으로 유지한다. 자료 없음, 검색 실패, 원문 부족을 빈 결과만으로 단정하지 않는다.

API 오류·타임아웃·검증 실패 시에는 원래 질문과 시스템 선택 조건으로 로컬 탐색을 수행할 수 있다. 이때 해석이 적용되지 않았음을 기록하고, 원래 질문의 필수·제외 조건을 충족했다고 보장하지 않는다. 현재 임시 API 차단은 유지하고, 활성화 후 같은 계약으로 소규모 비교를 진행한다.

## 로컬 검증과 다음 단계

정상 예시 10개와 오류 응답 13개를 검사했다. 국내 조건 누락·선호로의 강등, OR를 AND로 변경, 미등록 이름 훼손, 임의 지역 추가, 틀린 인용·유니코드 위치, 존재하지 않는 참조, 선호의 필수화, 해석 보류의 은폐를 포함한다.

`validation-results.json`의 23개 검사는 모두 통과했다. 이 수는 계약 예시와 검증기의 동작 확인이며 LLM 정확도나 의미 검색 품질 점수가 아니다. `validate.cjs`는 이번 스키마에서 사용한 키워드만 검사하는 로컬 검증기다. 제품 연결 시에는 정식 JSON Schema 검증기 또는 동등한 타입 검증과 런타임 의미 검증을 적용한다.

재현 명령은 다음과 같다.

```sh
node check.cjs
```

다음 단계에서는 API 요청 해석을 이 구조로 반환하도록 연결하고, 처음 보는 질문에서 원문 조건 보존을 평가한다. 질문별 예시를 그대로 맞히는 검사와 새로운 표현의 일반화 검사를 구분한다. 이후 검색 계획 연결과 후보 원문 평가를 검증한다. 이 단계에서 화면 변경·새 지역 사실 적재·후보 재정렬·API 실행을 완료한 것으로 처리하지 않는다.
