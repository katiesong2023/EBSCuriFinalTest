# R12-03 검색 결과 완성도·API 내용 분석 준비 — 2026-10-15

현재 후보의 관련순·원문 인용과 기존 API 검토 입력을 보완했다. 이전 개발170을 같은 입력·동일 데이터로 비교했다. 빈 결과 감소나 범용 의미 검색 완성은 달성하지 않았다. 사용자 결과 확인 전 R12-03은 진행중이다.

## 변경

- `request-relevance.js`에서 요청 주제와 같은 문장의 역할·변화·원인·조건 설명 표현을 관련순에 반영한다. 설명을 요청했는데 대응 단서가 없으면 새 가점을 주지 않는다. 필수/제외·OR·프로그램/형태/기간 필터를 완화하지 않는다.
- `source-explanation.js`에서 요청 설명 단서가 있는 문장을 우선 인용하고 남은 확인을 카드에 연결한다. 원문 UTF-16 위치를 유지한다. 표현 단서와 의미 충족·실제 영상 적합성은 구분한다.
- `source-text-quality.js`에서 더빙·수어·자막 표기 뒤의 제목 반복을 내용 설명으로 취급하지 않는다. 원본을 수정하지 않는다.
- `candidate-review.js`에서 기존 B후보 검토 입력의 소개문 전달량을 후보당600→6,000 UTF-16 코드 단위로 늘렸다. 최대10후보·잘림 표시·원문 지문·실제 전달 범위의 인용 검사·이모지 경계를 유지한다. 전송량 상한은 증가했으며 실제 모델 비용/효과는 아직 측정하지 않았다.

## 기능 검증·현재 서버

검색 근거/전송8·API 준비/응답23·질의27·내용 관계8·요청 조항19·결합20·원문 품질17·미리보기4·필터16검사를 수행했다. 기존 API 표시 테스트의 사라진 ‘원문 열기’ 문구 기대를 현재 카드의 연결 이유/인용/escape 검사로 갱신했다. 필터 검사는 원래 화석 판본에 지질 문맥이 없어 검색에서 탈락하는 기존 실패를 가점0에서도 재현한 뒤, 날짜 정렬을 확인할 수 있도록 합성 원문에 지층 단서를 보완했다. 제품의 화석 문맥 필터를 완화하지 않았다.

최종 코드를3000서버에 재시작 적용하고 역할·동네 변화·먹이 관계·다문화의4검색을 HTTP200/새 근거 필드와 함께 확인했다. 브라우저 화면을 새로 촬영하지 않았으며 기존 카드의 표시 함수를 그대로 사용한다. 사용자 저장자료/폴더를 수정하지 않았다.

## 향후 API가 맡을 부분

기존 A해석은 원래 요청의 필수/제외/선호·관계·고유명과 시스템 선택 조건을 보존해야 한다. 후보 발견을 개선해야157빈을 다룰 수 있으며 B재정렬만으로 빈 후보를 복구하지 못한다. B는 이미 발견한 후보의 자기회차 제목/소개문으로 주제 중심성·일화/비유·관계 설명을 비교하고 정확한 인용과 요구별 MATCH/MISMATCH/UNKNOWN을 반환해야 한다. 이번 전송 확장은 그 원문 공백을 줄이는 준비이며 실제 API 연결/호출 성능의 증거는 아니다. 공식 보조 원문은 현재 로컬 근거로 사용하지만 B의 기존 title/summary 인용 계약에 자동 포함시키지 않았다.

157빈·무관4·설명 부족·장면/제외의 실제 부재는 잔여 과제다. 추가 원천 확보와 A후보 발견/B내용 비교의 효과를 따로 측정하고 사람 선택/교사 효용은 R12-06에서 확인한다.
