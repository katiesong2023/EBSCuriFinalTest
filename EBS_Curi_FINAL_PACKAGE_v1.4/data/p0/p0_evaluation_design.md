# P0 공식근거·기능검증 평가 설계

## 1. 전환 배경과 목적

기준일은 2026-09-17이다. 제작자는 교육과정 전문가가 아니므로, 독립 사람이 성취기준 정답을 작성한 것처럼 CuriMap의 의미 연계 정확도를 주장하지 않는다. 이전의 Gold·사람 관련도 채점·수작업 성취기준 라벨 설계는 적용하지 않으며, 그 초안과 빈 파일은 이력 보관만 한다.

대신 이 설계는 다음을 재현 가능하게 검증한다.

1. 공식 교육과정 데이터와 EBS 공개 메타데이터가 원문·ID·출처와 함께 정확히 저장되는가
2. CuriMap이 존재하는 공식 성취기준만 후보·결과로 제시하고, 사람 검수·수정·제외 흐름을 지원하는가
3. EBS가 이미 제공한 교과·학년 정보가 있는 강좌를 조건 검색했을 때, 알려진 항목을 반환하는가
4. 실행·실패·재시도·출처 표시의 운영 기록을 남기는가

이는 의미 연계의 교육과정 정확도, 교사의 수업 유용성, 실제 EBS 업무시간 절감 효과를 증명하지 않는다. 그런 주장은 교육과정 전문가 또는 교사 표본의 별도 검토가 확보된 뒤에만 한다.

## 3. 평가 축

### 3.1 공식근거·데이터 무결성

사회 27건과 과학 51건을 대상으로 다음을 정적으로 점검한다.

- 성취기준 ID의 고유성·형식, 본문·교과·학년군·교육과정 버전·PDF 쪽수의 빈값 여부
- `HUMAN_APPROVED` 및 `USABLE_HUMAN_APPROVED` 상태만 서비스 후보에 사용되는지
- CuriMap·CuriBase가 반환·저장한 성취기준 ID가 이 공식 목록에 존재하는지
- 콘텐츠·연계·검수 기록에 원본 ID·원문 링크·확인 시각·상태가 남는지

보고 지표는 `공식 ID 유효율`, `필수 출처 필드 완결률`, `사용 불가 기준 차단 건수`다. 이것은 데이터·제약의 정확성이지 콘텐츠-성취기준 의미 정확도가 아니다.

### 3.2 CuriMap 근거성과 검수 흐름

공개 텍스트가 있는 5~10건의 실행 시나리오에서 화면과 저장 흐름을 확인한다. 각 실행은 다음을 만족해야 한다.

- 후보·결과의 모든 성취기준 ID가 공식 목록에 존재하고, 코드·본문·원문 근거를 표시한다.
- 입력 텍스트 부족·후보 없음·호출 오류에서 임의의 코드를 만들지 않고 보류 또는 오류 상태를 표시한다.
- 검수자가 승인·수정·제외할 수 있고, 검수 전 초안은 검증 자산 검색에 노출되지 않는다.
- 실행 ID·모델 및 설정·입력 콘텐츠 ID·지연·성공/실패·재시도가 기록된다.

보고 지표는 `공식 ID 유효율`, `근거 표시 완결률`, `검수 동작 성공률`, `실행 기록 완결률`, 오류·재시도 건수다. 결과가 교육과정상 맞다는 점은 이 지표로 주장하지 않는다.

### 3.3 알려진 항목·조건 검색

`CURRICULUM_NATIVE`의 EBS 공식 인벤토리에서 확인된 8개 기본 강좌를 기준으로 8~12개의 알려진 항목 검색 시나리오를 만든다. 각 시나리오는 공개된 강좌명 또는 고유한 학년·교과·학기 조건, 기대 강좌/강의 식별자, 기대 필터 조건을 가진다.

- 모든 기대 식별자는 EBS 공식 인벤토리의 행으로 먼저 확인한다.
- 검색은 기대 식별자가 결과 집합에 있는지, 교과·학년 조건을 위반한 결과가 없는지, 결과의 EBS 원문 링크가 표시되는지를 확인한다.
- 검색 결과의 수업 유용성·의미 관련도·순위 품질은 사람 전문가 채점 없이 계산하거나 일반화하지 않는다.

보고 지표는 `알려진 항목 반환율`, `조건 위반 반환 건수`, `원문 링크 표시율`, `무결과·오류 건수`다. 이 시나리오는 개발·회귀 확인에 사용할 수 있는 기능검증 자료이므로 봉인 Test나 독립 성능 수치로 표현하지 않는다.

### 3.4 운영과 재현성

각 기능검증 실행에 코드 버전 또는 작업트리 상태, 데이터 버전, 실행 시각, 입력 ID, 결과 상태, 지연 시간, 호출 수·가능하면 비용을 남긴다. 오류를 수정한 뒤 다시 실행하면 실행 ID를 분리한다.

응답 시간·재시도·완료된 화면 동작은 기술적 운영 수치다. 사용자·교사의 실제 업무시간 절감 또는 교육 효과로 일반화하지 않는다.

### 3.5 선택적 외부 검토

교사 또는 교육과정 전문가가 확보되면 5~10개 CuriMap 결과를 `승인`·`수정`·`제외`로 표본 검토할 수 있다. 이는 전문가의 실제 검토 기록과 역할·표본·한계를 함께 제시하는 보조 증거이며, 전문가가 없으면 수행하지 않았다고 명시한다.

## 4. 이전 Gold 자산의 처리

`p0_gold_a_labels.csv`와 `p0_gold_a_labeling_guide.md`는 빈 입력지·작성 안내의 이력으로 보관한다. `GOLD-A-01`~`GOLD-A-10`의 분할 등록은 `REPLACED` 상태이며, 정답·튜닝 입력·성능 수치에 사용하지 않는다. 삭제하지 않는 이유는 설계 전환 이력과 데이터 누수 방지 결정을 추적하기 위해서다.

## 5. 사전 성공 기준

| 영역 | 통과 기준 |
| --- | --- |
| 공식근거 데이터 | 서비스 사용 성취기준의 ID·본문·교과·학년군·원문 쪽수 필수값 100%, 사용 불가 기준 0건 반환 |
| CuriMap 제약 | 확인 시나리오에서 공식 목록 밖 ID 0건, 결과·보류·오류 모두 상태와 근거 표시 |
| 검수 흐름 | 승인·수정·제외·검수 전 검색 제외·실패 후 재시도 시나리오가 각각 동작 |
| 알려진 항목 검색 | 사전 등록한 모든 시나리오에서 기대 식별자 반환, 명시한 학년·교과 필터 위반 0건 |
| 운영 기록 | 실행별 입력 ID·데이터/코드 버전·결과 상태·지연·오류/재시도 기록 100% |

이 표는 사전 기능 기준이다. 실제 수치와 실패는 그대로 기록하며, 미측정 의미 정확도·교사 유용성·업무 절감 효과로 확장 해석하지 않는다.

## 6. 후속 적용 순서

1. Task 00-09에서 EBS 공식 인벤토리 기반의 알려진 항목·조건 검색 시나리오 8~12개를 만든다.
2. Task 00-10에서 CuriMap·검수·검색 실행에 공통으로 남길 운영 기록 필드를 확정한다.
3. 구현 task에서 공식 ID 제한, 원문 근거 표시, 검수 상태 분리, 실행 이력을 구현한다.
4. Task 03-03에서 CuriMap의 공식근거·검수 흐름을, Task 03-04에서 알려진 항목·조건 검색을, Task 03-05에서 실행 이력·지연·오류 기록을 확인한다.
5. 외부 전문가 검토는 확보된 경우에만 별도 표본·역할·한계와 함께 추가한다.
